# GitHub 交付、合并与清理

仅在创建/更新 PR、执行已授权合并或合并后清理时读取。本页的删除检查适用于每一次删除动作。

## PR 与版本记录

1. 核对实际仓库远端和本组分支，查找该 head 已有 PR，复用匹配项；PR 的 base 必须为 `dev`，head 必须为登记的修复分支，不能为 `dev` 或 `main`。
2. 使用仓库 PR 模板，关联完整组内 issue。正文用结构化参数或 UTF-8 临时文件 `--body-file`，保留真实换行。
3. 保存 head SHA、目标分支名、merge base、实际完整差异、实际目标 `dev` SHA、CI 运行及审查范围。审查和人工批准均绑定该范围，不能仅凭 head 未变沿用更换目标分支前的结论。PR API 的 base 快照可能落后于分支当前值；需要确认集成内容时检查当前远端 ref 和合并预览父提交，不直接对两分支尖端做差异而混入其他 PR。
4. 逐项等待所需检查成功。合并结果可能与单独 head 不同；目标分支推进时核对当前合并预览和所需集成检查。存在冲突时，由总控确认原会话停止写入后在对应修复分支解决，同步文档并重新验证、全新审查及取得新范围人工确认，不能绕过保护规则。

## 人工批准后的合并

- 执行前重新读取 PR：状态为 OPEN、base 为 dev、head 和完整审查范围与人工验收及最终审查记录一致、CI 满足要求且可以合并。
- 按仓库允许的策略合并，使用 expected head 等版本约束，避免合入授权后新推送的代码。CLI 可采用 `gh pr merge <编号> --repo <仓库> --merge --match-head-commit <已批准SHA>`；策略以实际仓库配置为准，不加 admin 绕过。
- 合并操作与删除分支分开执行；先查证 PR 为 MERGED、目标为 dev，并记录 `mergeCommit`，再清理。不要让 `--delete-branch` 在未经过下节检查时顺带删除分支。
- 请求超时或结果不明时先查询真实状态；已经合并就继续清理，不重发合并。未能合并则保留分支和 issue，不声称完成。

## 修复分支删除检查

每个目标同时满足以下条件才允许删除：

1. 来源是本组已核实 PR 的 **headRefName**，属于任务登记的修复分支；绝不从 baseRefName、当前所在分支或用户自由文本直接生成删除目标。
2. 将目标落实为精确 ref 后，确认既不是 `dev`、`main`，也不是仓库默认分支。即使调用者声称已授权，也拒绝在本清理流程删除这些长期分支。
3. PR 已合入 dev，且该分支当前 tip 仍等于已验收的 PR head。分支出现合并后的新提交时保留它，报告新提交，不把未合入工作当成旧修复清掉。
4. 逐个精确删除，使用预期 tip 约束保护远端操作；不用通配符、批量“已合并分支”清扫或无条件强制推送。

远端已不存在时记录该项已清理；无需因此中止其他合法清理。GitHub head 分支名仍保留在 PR 元数据中，不代表远端 ref 仍存在，须实际查询。

本地删除前检查 ref 和所有关联 worktree。仅当 tip 与验收版本一致、关联工作区无未保存或无关改动时，安全切到 detached HEAD 等保留源码和证据的状态，再删除该精确本地修复 ref。Git 的祖先判断受 squash/rebase 合并影响，须结合真实合并策略和 PR 事实判断，不能仅凭“已合并分支列表”清理；不能强制移除脏 worktree 或递归删除目录来使命令成功。无法安全完成本地清理时保留并报告。

删除后分别查询远端和本地 ref，确认实际消失；保留 worktree、日志、覆盖率与截图。

## 关闭 issue 与同步总入口

- 从本组 issue 清单和 PR 正文核对关联，区分 **PR 编号** 与 **issue 编号**；不能把 PR 编号当成修复对象关单。
- 查证合并且对应 issue 的完整范围已经交付后，按 `completed` 关闭每个关联 issue，并重新读取状态。等待验收的其他 PR、未完成的组内 issue 和总入口剩余子任务保持开放。
- 关单不以分支删除成功为必要前提：修复已合并且范围完成时可关闭 issue，同时如实记录仍受阻的分支清理。也不能以关单成功冒充分支已删除。
- 在总入口和各 issue 顶部追加或同步完成记录：验收 head、CI/审查证据、PR、实际合并 SHA、分支及关闭状态。保留原始要求和历史记录；只有总入口自身的全部范围完成才关闭总入口，不能仅凭本次选定的子任务已完成就关闭它。
- 后续收到“已合并，关闭 issue”时，查证 PR 合并事实，继续未完成的清理步骤；已成功步骤查证后跳过，避免重复创建 PR、合并或关闭错误对象。
