# 多会话编排

分组完成、准备派发，以及恢复或回传分支任务时读取。这里的会话是 Codex 中独立可见、可继续对话的 chat/thread；总控中的开发子 Agent 只用于会话内部工作。

## 工具与启动条件

- 本仓库使用 `tools/Invoke-CodexThread.ps1` 连接官方 Codex App Server，命令和前置条件见[会话控制接口](../../../../docs/project/codex-thread-control.md)。先执行 `Doctor`；`Create` 绑定已存在的 worktree/分支并返回真实 thread ID，`Send` 向同一 thread 开启下一 turn，`Read` 与有界 `Wait` 查询真实结果。脚本通过本地 socket 调用会话协议，不是 `codex exec` 或开发子 Agent。
- 在 `orchestration.json` 中记录独立的 `controller.json` 路径及服务器 socket，主会话通过命令工具调用脚本即可。创建或发送响应未确认时使用 `Reconcile` 按实际工作区或原 thread 对账，查证后恢复原 thread/turn 登记，不重发请求。API/schema 以本机实际 Codex 版本为准；失败不把命令进程退出或已发送请求当作会话完成。
- 创建时显式记录不超过本任务已授权权限的 `Sandbox`，不得因执行失败自动提升。分支会话需要验证资源或用户决定时，回报“待验证资源/待输入”、具体请求并结束当前 turn；总控从 `Read`/`Wait` 取得请求，协调后向同一 thread `Send` 授予或回复。turn 已结束不代表该组已交付，不要求分支会话另行控制总控 thread。
- 创建采用两阶段派发：创建请求的初始提示只调用工程统筹受派模式，提供分组与路径，明确“仅只读核对 worktree/分支/基准并回报，等待总控启动开发，不得修改、提交或运行验证”。待真实会话 ID 和 API 工作区绑定确认、会话回报的 Git 状态也一致后，总控才向同一会话发送下方完整实施任务。queued 或仅创建成功不授权开工。
- 用户选择本多会话流程并要求实施时，已授权按分组创建独立会话，无须逐个再询问。只要求修改 skill、规划或模拟演练时，不创建真实开发会话；明确要求实测时仅创建登记的测试会话，并按要求永久删除。接口不可连接或缺失所需能力时报告无法自动编排；不得用 `spawn_agent`、`codex exec` 或后台 shell session 替代。
- 同一分支只允许一个会话拥有写入权。已有 worktree 时要求会话使用该 worktree，不能让工具另建不对应的工作区。若工具只能自己创建 worktree，使用其实际产物核对分支和基准后登记，避免额外建立第二个同分支 worktree。
- 主工作区尚未提交的规则/skill 不会自动出现在其他 worktree。派发时提供实际可读的 skill 绝对路径和受派模式约定；子会话读取真实材料，不能假设继承主会话历史。无法读取必需材料时先报告阻碍，不启动错误的默认 dev 开发流程。

## 会话登记与等待

总控在自己的 worktree 下建立 `build/issue-delivery/<本轮唯一编号>/orchestration.json`，每次派发或状态变化及时保存组 → issues → 分支 → worktree → host/真实 thread ID → 最近游标 → 交付 head → 状态 → 写入负责人及资源持有者。首次在总控回复和已有计划记录中注明该文件的绝对路径；没有总入口时仍使用此工件，不为登记另建 issue。该工件不提交 Git，也不随分支清理删除。

使用工具返回的实际 ID，queued 请求的 client ID 与正式 thread ID 分开记录。创建尚未确认时先查询结果，不盲目重发。恢复总控时先读取登记并核对真实会话与 Git 状态，再继续未完成步骤；尚未落盘或结果不明时先查询真实状态，不凭记忆重复派发。

状态按事实推进：准备 → 创建中 → 开发 → 待输入/待验证资源/失败，或已交付并停止写入 → 返修 → 重新交付 → 汇总 → 待人工验收 → 集成与清理。失败或等待不会自动变成完成。

- 优先使用有界的紧凑等待快照，传入各 host、thread ID 和最近游标；每次等待不超过 60 秒，工具更短上限优先。更新游标，仅在需要细节时读取完整会话。未变化快照不重复播报。
- 总控为全批开发子 Agent 分配最多三人的并发预算；默认每个活跃分支会话一名。会话申请增加预算时，只有其他名额已释放才可授予。只读审查员与开发者分开记录。
- 构建、Godot、覆盖率及导出运行权也由总控登记：工作区、进程、用途、持有会话、开始与实际结束。分支会话先申请、得到明确授予后才启动，释放后再授予下一会话。超时或失联时查询实际进程，不能仅凭等待结束就将资源再次授予。
- “全部结束”指所有计划组都交付本轮结果且确认已停止写入；保留可回传的原会话。工具显示 idle/completed 只是候选状态，还须核对交付提交、干净工作区、证据及已无开发/验证写入进程。

## 分支会话派发内容

使用真实值填写以下信息，正文明确调用 `$farm-exchange-engineering-lead`：

```text
使用 $farm-exchange-engineering-lead 的分支受派模式。
总控会话：<host 与 thread ID>；组：<组名>；范围：<issues 与组内顺序>。
仓库/worktree：<绝对路径>；唯一分支：<codex/...>；基准：<dev SHA>。
必须读取：<真实工程统筹 SKILL.md 绝对路径>、<总控 SKILL.md 绝对路径>、适用仓库规则与原始 issue。
仅本组允许的文件/接口：<清单>；公共说明由总控处理；其他会话：<组与所有权>。
并发开发预算：<人数>；验证资源：<向总控申请的方式>。
在指定分支按顺序实施、维护专题文档、完成全新提交前审查与获准的适用验收，只提交本组成果。
不切换 dev，不创建 dev→main PR，不自行推送/建 PR/合并/关单/清理分支，不递归启动分支会话。
交付 issues、worktree/分支、基准/head、变更文件、审查及验证证据、公共文档需求、遗留项；确认所有写入和验证进程结束。
本轮交付后停止写入并结束回复，保留会话等待总控返修；阻碍如实报告，不能标成已完成。
```

回传返修时，先核对原会话和分支登记，发送具体问题、当前 head、文件所有权、验证要求与更新后的开发预算。会话在 idle 时使用能启动下一 turn 的发送方式；消息仅排队或 steering 尚未完成时继续等待，不将发送成功当成修复完成。总控整合期间不再派发同分支写入；恢复返修前显式结束整合写入并交回当前 head。

## 总控接管集成

全部交付后，总控取得各分支的独占写入权，核对最新 head 与无未保存改动，再补公共说明及组织审查。接管写入结束前，分支会话保持等待。业务返修由原会话负责；与 dev 的文本冲突及集成回归由总控负责。不能通过强推、丢弃工作区或提前删除分支化解冲突。

会话不可达或已无法继续时，报告受影响组，保留其分支和证据；先与用户确认新的会话安排，再转派。不得静默另开会话冒充原会话返修。只有交付与清理结束且无需返修时，才按用户授权处理会话归档；本 skill 不删除会话。
