# 维护

用于文档、测试、构建、CI、配置与协作工具。按实际变化使用标题前缀 `docs`、`test`、`build`、`ci` 或 `chore`；示例：`chore：新增分类模板驱动的 issue 提交 skill`。

正文聚焦受影响的工件与真实验证。文档问题写位置和不准确/不清楚之处；测试任务写缺少验证的业务行为；构建与工具任务写命令、输入和输出约定。独立维护任务不自动加入无关的游戏验收。

## 正文骨架

```markdown
## 问题与现状
{{现有工件/流程的具体问题、位置和影响}}

## 改进范围
{{修改哪些工件、规则或流程；需要保持的约定}}

## 验收标准
- [ ] {{目标工件或命令产生所需结果}}
- [ ] {{与任务相关的格式、链接、场景或构建验证通过}}
- [ ] {{对应中文操作说明/导航一致}}
```

## 按任务补充

| 任务 | 需要时补充的证据与验收 |
| --- | --- |
| 文档 | 页面/文件位置、规则依据、可执行示例及链接 |
| 测试 | 尚未覆盖的公开行为、触发条件、必要失败与成功对照 |
| 构建/CI | runner 或系统、实际命令、输入版本、产物与失败状态 |
| 配置/skill/工具 | 生效位置、调用方式、适用范围、格式与真实流程验证 |
