# 重构

用于集中共同业务规则、调整模块职责或降低调用方负担，同时保持现有行为。标题示例：`refactor：集中作物适季时间的共同计算`。

以真实重复、调用约束和修改成本说明问题。证据写文件、成员及实际消费者；提供行号时确认其有效性。改进方向可以限定共同知识与状态归属，不必提前指定新类或接口。尚需探索的方向写清探索结果，不作为已定实现。

## 正文骨架

```markdown
## 问题与目标
{{具体结构摩擦、共同规则或维护成本}}

## 现状与证据
{{涉及文件/成员、调用关系及真实重复}}

## 改进范围
{{集中哪些知识或职责；保留哪些业务差异和状态拥有者}}

## 保持的行为
{{重构可能影响的现有规则、错误结果、调用顺序或资源不变量}}

## 验收标准
- [ ] {{目标重复消除，或调用方无需再维护该约束}}
- [ ] {{已有业务结果与列明的不变量保持；相关行为回归检查}}
- [ ] {{中文接口/实现说明与最终结构一致}}
```
