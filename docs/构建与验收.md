# Windows 构建与验收

## 构建来源

- 引擎：`E:\Godot\Godot_v4.7.2-stable_mono_win64` 中的 Godot 4.7.2 Mono。
- 官方 .NET 导出模板：同一目录中的 `Godot_v4.7.2-stable_mono_export_templates.tpz`；Windows x86_64 模板与中文所需 ICU 数据解压在 `export_templates/4.7.2.stable.mono/`，可供后续项目复用。
- `project.godot` 启用中文断行所需的文本服务数据；导出包应包含该数据。
- 项目导出配置：`export_presets.cfg`；C# 构建配置：`FarmExchange.sln`、`FarmExchange.csproj`、`NuGet.Config`。Godot 的 .NET 导出要求项目根目录有与程序集同名的 `.sln`，Windows 发布首次运行还需从 nuget.org 获取 .NET 运行时包。

## 生成可运行版本

在项目根目录执行：

```text
dotnet build FarmExchange.csproj -c Release
E:\Godot\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe --headless --path . --export-release Windows build/windows/FarmExchange.exe --quit
```

`build/windows/` 是可覆盖且不纳入 Git 的 Windows x86_64 中间导出目录。导出后可在 PowerShell 中按以下方式验收启动：

```powershell
$executable = (Resolve-Path -LiteralPath build/windows/FarmExchange.exe).Path
$process = Start-Process -FilePath $executable -ArgumentList @('--headless', '--quit-after', '5') -WindowStyle Hidden -Wait -PassThru
if ($process.ExitCode -ne 0) {
    throw "导出程序启动失败，退出码：$($process.ExitCode)"
}
```

Windows GUI 程序经 PowerShell 的 `&` 直接调用后，`$LASTEXITCODE` 可能保持空值，不能据此判断启动是否成功；上面命令等待进程结束，并读取实际的 `ExitCode`。打包或移动时保持 `build/windows/` 中的全部文件完整。

## 自动化测试与行覆盖率

测试分为三层：`TestFarmGame` 检查六种作物、对应加工、切换移除、交易与市场规则，`TestWorldMap` 检查地图坐标和镜头边界，`TestMainScene` 检查主场景选种、建造和出售。`tests/test_suite.tscn` 在同一个 Godot 进程中依次运行这三层测试，任一检查失败都会返回非零退出码。

在项目根目录执行完整测试：

```powershell
./tools/Run-Tests.ps1 -GodotConsole 'E:\Godot\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe'
```

脚本使用仓库锁定的 `dotnet-coverage` 版本生成 `coverage/coverage.cobertura.xml`。覆盖率只统计 `scripts/` 中的业务脚本，排除 `tests/` 和 Godot 自动生成源码；总行覆盖率不得低于 80%，当前本地基线约为 90%。修改业务功能时必须在同一 issue 中同步修改或补充对应测试；不得通过排除业务文件降低统计范围。覆盖率报告与 `coverage/` 目录不纳入 Git。

## GitHub Actions 持续集成

`.github/workflows/ci.yml` 使用 Windows 托管运行器、.NET 8 和 Godot 4.7.2 Mono，并按以下规则触发：

| 触发分支 | 编译与场景测试 | 80% 行覆盖率门槛 | Windows Release 导出与启动 | 上传产物 |
| --- | --- | --- | --- | --- |
| 推送到 `dev` | 是 | 是 | 否 | Cobertura 报告，保留 14 天 |
| 推送到 `main`（包括人工合并 PR） | 是 | 是 | 是 | 覆盖率报告及完整 Windows x86_64 目录，保留 14 天 |

工作流中的 Godot、.NET、`dotnet-coverage` 和 GitHub 官方 Action 均固定到明确主版本或工具版本。升级这些依赖时应通过独立 issue 修改版本，并在 `dev` 验证成功后再合并。`main` 的导出程序启动步骤使用上面的进程退出码检查，成功后才上传 Windows 构建；产物名包含提交 SHA，下载后应保持目录结构完整。它是提交级验收产物，不替代带版本号的正式 Release 压缩包。

## 正式版本

正式版本只从已人工合并的 `main` 构建，采用 `v主版本.次版本.修订版本`。不兼容既有存档或核心玩法规则的变更递增主版本；兼容地新增玩法、系统或内容递增次版本；兼容地修复缺陷、优化性能或调整表现、文档和构建递增修订版本。首个稳定公开版本为 `v1.0.0`，此前使用 `v0.次版本.修订版本`。

Windows 正式包固定写入：

```text
build/releases/v主版本.次版本.修订版本/FarmExchange-v主版本.次版本.修订版本-windows-x86_64.zip
```

压缩包不纳入 Git，只上传到同版本 Git 标签对应的 GitHub Release。发布前须重新完成 Release 编译、全部自动化场景测试、Windows 导出和导出程序启动验收；标签、GitHub Release 与压缩包中的版本号一致才算发布完成。

## 当前玩法验收步骤

1. 运行游戏，确认出现等距地图和右侧经营按钮；左键短按选格，左键拖动、滚轮和 WASD 可浏览地图。移动到地图边缘时，确认可看到菱形边界，边界外没有地块，镜头中心不能移出地图范围。
2. 查看地图中心：应有 3 块未播种农田、2 处配套加工场地，可能是三块同种，也可能是两块同种加一块另一种；两处场地按农田作物匹配。面板初始金币为 50.00，免费选地次数仍为 2。
3. 等待工人轮流播种浇水，确认预置农田自动收获，原料进入对应场地并产出加工品。三块同种时两处场地加工同一种；两种作物时应分别产出两种加工品。商店不能出售原料。
4. 再任选两格未解锁土地免费解锁；一格建农田，另一格在下拉框选“磨坊”并建造。新农田默认小麦。工人浇水后 5 tick 收获，磨坊取走小麦再过 3 tick 产出面粉。两次免费机会用完后，新土地需要 10 金币。
5. 选中农田，从下拉框改种玉米；生长中的旧作物消失。移除磨坊，再在同一土地建玉米加工坊。玉米浇水后 6 tick 成熟，加工 4 tick 后产出玉米粉。其余作物及场地按 `生产与交易.md` 的表格检查。
6. 每经过 10 tick，面板天数增加 1，面粉售价按曲线更新并显示涨跌百分比和幅度分类；面粉价格始终位于 1.00～20.00 金币，其他加工品按当日面粉价倍率计价。
7. 在商店出售加工品，金币按各品种“数量 × 当天售价”的总和增加。售价和金币均显示两位小数，出售后加工品库存归零。
8. 移除正在加工的场地，已投入原料消失；移除生长中的农田，未收获作物消失。土地保持已解锁。

当前版本具有六种作物及配套加工循环；存档与离线收益的规则尚待确认，退出游戏后本次进度不会保留。
