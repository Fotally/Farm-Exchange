## 季节耕作表：#42

**已确认方向：**功能完成后开局即可使用，玩家配置各季适宜作物，让农田自动循环种植。执行必须复用现有季节、预计成熟、供水和越季失败规则；耕作表不包含自动买卖。

**启动前需确认：**

- 配置按单田还是地块组生效。
- 每季选择一个作物，还是配置作物序列。
- 修改计划与手动改种的优先级及生效时点。
- 剩余生长时间不足时的行为；是否允许玩家明确配置备用作物尚未确认。

**接入位置：**从选种与尝试播种的意图接入，复用 `PlantingRules` 和现有农田命令。配置形态明确后再确定需要保存的计划状态，不预建计划语言。

**后续验收方向：**配置后可连续多轮、跨季执行；界面可看清当前执行与下一轮目标；手动操作和修改计划按最终规则生效；禁生季节失败和播种拒绝继续遵守统一规则。

## 后续扩充人力：#43

**已确认方向：**农田扩张后可以增加人力，先服务播种与浇水。开局三名真实工人及多人调度已完成，不列为剩余任务；现行移动与两日目标的适用布局见[三人工人实施方案](../architecture/workers/worker-scheduler/implementation-movement-proposal.md)。

**启动前需确认：**

- 人力由玩家雇用还是随扩张提供，以及增加数量和触发条件。
- 是否存在一次性费用、工资，以及具体数值。
- 新工人的出生位置、可照料范围，以及扩员后的两日目标适用规模与布局。
- 是否展示建议人手、工作负荷或人力不足提醒。

**接入位置：**`WorkerScheduler` 的工人集合与任务认领；经营入口和表现继续使用一秒推进与只读工人快照。具体扩员命令与界面在规则确认后确定，不预设雇佣、工资或覆盖半径。

**后续验收方向：**新增工人实际参与经营；多名工人不重复播种或浇水，不执行过期任务；相同田块与供水条件下增加人力能缩短等待；以明确的工人数、布局与统计起止点验证目标，不暗改单人工速。

## 委托挂单、自动买卖与手续费：#36

**已记录方向：**玩家可通过委托或预设策略减少频繁查看市场；高级交易需要手续费，计算方式尚未确定。现行即时交易仍按已完成的同价零费规则执行。

**启动前需确认：**

- 挂单与自动交易各自支持的触发条件、数量、有效期及撤销方式。
- 买单是否占用金币、卖单是否锁定实物库存；收到报价公告后是否可修改委托。
- 手续费采用固定金额、比例还是按订单类别区分，扣费时点及未成交是否收费。
- 多单执行顺序、部分成交、资金或库存不足时的结果。
- 暂停、关闭与未来存档下的订单状态，以及界面提醒和交易记录。

**接入位置：**使用 `TradingService` 的受控交易命令完成结算，库存与金币仍由原模块唯一持有。冻结资金或库存的需求确认后再设计相应操作，不预建锁定机制，不猜手续费。

**后续验收方向：**按最终规则验证触发、成交、撤销、费用和执行顺序；资金与实物守恒、失败零修改，不重复成交、不产生负库存；时间和暂停行为与届时生效规则一致。

## 行情学习反馈：#44

**已确认方向：**前期帮助玩家适应消息、判断行情并买卖商品，熟悉后再扩展到产能规划；不因此推迟季节耕作表的可用时间。

**仍属建议：**报价后回看消息、实际涨跌与交易结果，以及引导目标、行情复盘、交易收益展示，均尚未获实施确认。

**启动前需确认：**

- 消息预测性与不确定性的表达，以及提示强度。
- 是否添加回看、复盘、收益展示或引导目标，采用什么记录与交互方式。
- 初期商品数量与引导方式是否调整，具体影响范围和验收标准。

**接入位置：**复用 `MarketQuotes` 的真实消息与报价数据；若需要交易结果记录，确认内容与保留周期后再设计。报价公式和事件规则由市场专题维护，反馈功能不新增提前播报，不事后编造因素解释。

**后续验收方向：**展示可追溯到真实消息、实际报价和玩家交易；提示强度与可见内容符合最终确认；不改变报价与公告时点，不让查询推进经营或抽取事件。

## 后续启动与交付

用户选定某项后，先讨论该项未确认规则并更新对应 issue，再制定文件范围和验收步骤。每次只完成选定 issue 的明确范围，开发与中文文档完成后按仓库约定新开独立只读审查，执行编译、场景、逐模块覆盖率、导出与实际程序启动验收，再提交 dev → main PR 等待人工合并。
