# 工人加工岗位与 process 动作设计提案

关联 [#113](https://github.com/Fotally/Farm-Exchange/issues/113)，归属 [#105](https://github.com/Fotally/Farm-Exchange/issues/105)。2026-10-07 核对现有加工、工人源码及清亮 v2 动作。本页仅供规则选择，尚未启用加工岗位；现有自动加工和 #108 建筑动效可继续独立交付。

## 事实和需要选择的作用

`ProcessingSystem.TryStart` 对空闲匹配场地从公共库存取一份可用且超过底线的原料，设置批次时间；`Advance` 到期产出。`FarmGame` 协调按稳定锚点顺序领取及结果入库，建造加工场地时也立即尝试全场领取。工人当前仅播种、浇水，真实工作格位于 3×3 中心。详见[加工规则](../gameplay/production/processing.md)。

| 选择 | 无人时的行为 | 经营影响与取舍 |
| --- | --- | --- |
| A：继续自动加工 | 现行自动领取、自动计时 | 保留既有吞吐量，不启用 process 人物动作；首批采用此既有事实 |
| B：工人启动批次，建议讨论 | 未启动等人；已投入批次继续自动完成 | 增加到场与启动劳动，可释放工人兼任农活；改动比持续驻场少 |
| C：持续有人才加工 | 无人不启动，已有批次暂停进度 | 最强人力约束；七设施与三工人的争用显著，需明确离岗和优先级 |

若用户希望工人确实参与加工，建议先讨论 B。B 的人物动作应该表达“投入/操作启动”，不能在工人离开后继续于该设施画木槌。B/C 均会降低或改变现有吞吐量，不能用材质动效遮掩规则变化，也不默认增加工人数或加快周期。

## 唯一状态归属与 Interface

`ProcessingSystem` 继续唯一拥有已投入原料所代表的批次、加工进度和完成状态；`WorkerScheduler` 唯一拥有任务/岗位认领、工人位置与劳动进度；`Inventory` 唯一拥有公共资源、冻结和底线。B 不需要永久岗位表；若选 C 并要求玩家固定指派，岗位指派也归 `WorkerScheduler`，UI 仅提交完整命令。

建议复用实际调度 Seam，新增加工任务需要和执行凭据，而不是建立平行工人系统。`FarmGame` 在同一经营步协调任务、批次和领取：

- 只读任务需要返回空闲可启动场地及实例凭据；缺料/底线阻挡时不占住工人。执行时再次检查，预选并不冻结原料。
- 完整 `TryStartProcessing(request)` 重验工人真实到达、任务凭据、设施空闲与原料可用性，再一次完成扣一份原料与启动批次。失败两端不变，调用方不用拼接扣货/计时。
- 成功结果只通知表现；原料投入后不能出售或冻结。批次到期仍经原正式入库路径产出一份，动画击打/结束不调用生产命令。
- C 若启用，`ProcessingSystem` 根据经营步骤传入的有效在岗结果决定是否推进；不保存第二份工人位置。岗位取消与改派命令先确定旧岗位释放和批次暂停，再提交新认领，失败不半更新。

以上为拟定行为 Interface，不承诺新增同名公开方法或 C# interface。暂停使人物劳动和批次计时均不推进；倍率改变实际时间驱动，已完成一半的业务进度保留。批量推进必须纳入工人到达、启动完成、离岗和批次完成事件，不能跨事件按旧驻场状态整段累加。

## 建议规则及失败/取消

B 建议按现有稳定锚点规则选择可启动加工场地，所有任务仍由三名工人兼任；农活与加工之间优先级、启动耗时尚待确认。多人竞争最后一份原料时，只允许执行重验成功者启动，其余失败不产生虚假 FX。原料在到场前被卖出、冻结或底线上调时同样重验失败、释放认领，不收启动费也不保存虚假投入。

| 事件 | B 的建议行为 | C 额外需要确认 |
| --- | --- | --- |
| 工人到场/离开 | 到达后完成启动劳动才领取；成功即释放工人，批次继续 | 到场如何恢复计时，离岗是否立刻暂停 |
| 缺料/受底线限制 | 空闲不分任务；已认领任务执行重验失败时释放 | 常驻工人等待还是转做农活 |
| 提高底线/冻结库存 | 已投入不退回，已有批次不受影响 | 同左，不能把已投入重复冻结 |
| 设施拆除 | 未启动任务失效；已投入沿现行规则损失，不退料 | 释放该岗位与认领，暂停批次不能残留 |
| 岗位/任务切换 | 未启动可取消、原料未扣；已启动按自动批次继续 | 批次保留投入和进度，何时可恢复须明确 |
| 暂停/高倍率 | 业务时钟统一；过期动作跳过，不补播、不多结算 | 同左，禁止视觉离场决定批次暂停 |

B 会取消“新建加工场地立即自动领取”和“每次空闲自动续批”这两个现行入口，必须显式作为玩法变更确认；只增加人物动画同时仍自动领取不构成工人启动规则。投入和完成在同一秒发生时应保留原批次先推进、后领取的相位约束，工人启动是否从下一经营秒计时要在正式时序中统一规定并测试，不能凭 UI 帧顺序决定。

## 七工位素材适配与层级

包根 `default/npcs/characters/<id>/` 下 process 合成帧为通用木槌动作；抽查 npc001 每方向 8 帧，参考周期 1.1 秒，击打帧 4，道具 mallet。参考动作循环与帧时长不等于业务周期。64×64、脚根 `(32,60)`，方向行 `down/left/up/right`，右向已经镜像。合成帧包含道具，不再叠第二个槌；四向必须逐帧检查手握点、击打高度和工具接触，人物方向不能用建筑 q 代替。

| 场地 | 对现有 process 的适配结论 | 共同实施需要的素材/站位 |
| --- | --- | --- |
| 小麦磨坊 | 木槌不能表达磨盘或风车启动 | 投料/操纵动作，门前可见工作点；磨坊 body→sails→hub 层级保持 |
| 玉米加工坊 | 未证明存在合适槌击工位，不能直接适配 | 先确认工艺表现，再给投料/研磨动作及接触点 |
| 碾米坊 | 木槌可让人联想到舂米，但不证明该建筑已有舂臼 | 工位/舂臼画面与纵向击打动作匹配后才可用 |
| 淀粉坊 | 木槌不等同清洗、磨碎或滤取 | 选择具体操作，配工具及台面接触层 |
| 榨油坊 | 通用敲击不能代表压榨 | 压杆/转柄/投料动作，检查设备前后遮挡 |
| 制糖坊 | 不应对锅炉随意挥槌 | 投料/搅拌动作，锅炉蒸汽属于建筑表现而非人物产出 |
| 腌制坊 | 木槌仅在确认敲盖/封装含义后可能使用 | 桶口/工作台高度、接触帧和前景遮挡层 |

以上是动作语义评估，**七项均未通过正式工位接触验收**，不是确认新增七种工艺。q0 建筑画布 256×240/pivot `(128,176)` 只有图片接地点，不等于人物可站位置；当前逻辑中心常处于建筑实体内部。真正加工岗位必须一同确定逻辑工作格/站位，不能让经营在中心而人物被任意挪到门口假装到场。若选改工作偏移，由 `BuildingFootprint` 或明确拥有工作点的实际 Module 定义一次，并同步工人行程、候选及快照，不将规则放在纹理清单。

表现上遵循地面低层、建筑/人物按实际接触点排序，再处理设施内部前景台面与工具。现有静态整图没有给所有工位拆分前后遮挡层；需要手伸入设备内部时应补对应图层，不能把整个人物全局置顶，亦不能平面旋转 PNG 伪造方向。若与[设施旋转](facility-orientation-proposal.md)同时启用，还需逐 q 确认实际工作点与人物方向，q0 动效不能直接覆盖 q1～q3。

## 依赖与共同验收

[#35](https://github.com/Fotally/Farm-Exchange/issues/35) 的加工时间、底线与投入规则继续作为数值基准，岗位变化必须显式修订吞吐量预期；[#43](https://github.com/Fotally/Farm-Exchange/issues/43) 决定未来人力，不默认以扩编解决任务不足；[采收搬运](worker-harvest-transport-proposal.md)若启用，需要联合确定竞争任务的优先级与携货工人能否接岗位。

规则确认后的验收包括：无人、有一人和多人竞争；最后一份原料被卖出/冻结；底线等待与调整；到达前拆除、已投入后拆除；切岗位与半批进度；每批单次产出；买入后的首次可启动时点；逐秒和批量同结果；三人同时照料农田及七工位时的等待和吞吐量变化。1920×1080 逐七工位、四人物方向检查真实站位、手/工具/设备接触、前后遮挡和暂停高倍率。岗位规则、人物素材、必要设施图层、中文文档与测试一并交付，再走项目审查和引擎导出流程。

待用户决策：继续 A 或启用 B/C；岗位指派方式与兼任优先级；启动/驻场耗时；缺料离岗规则；新建是否取消即时领取；工作点变更；七工位具体工艺与动作；是否接受吞吐量变化。未确认前，不把现有通用 process 动作用于主经营。
