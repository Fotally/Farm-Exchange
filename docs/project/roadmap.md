# 游戏系统规划

已确认玩法的细节按主题记录在[游戏规则](../README.md#游戏规则)；代码模块接口记录在[代码架构](../README.md#代码架构)。本页维护范围、待确认事项和阶段。

## 已确认背景

- 类型：放置挂机游戏。
- 地图：384×384 基础格，每格 64×32；农田与加工场地各占 3×3，道路占一个基础格。
- 视角：等距视角。
- 引擎：Godot 4.7.2 Mono，安装目录见项目根目录 `AGENTS.md`。
- 脚本语言：C#，使用 Godot Mono。
- 首条挂机循环：开局已有中心农田、加工场地与 3 名真实耕作工人，玩家仍可继续建造；工人按经营秒移动到田、播种和浇水，作物成熟后自动入库，可直接出售原料，或交给对应场地加工后出售加工品。
- 扩张循环：积累足够的钱后在空地建造更多生产建筑。
- 地图单张固定、菱形边缘清晰，镜头中心不能移出范围。中心免费预置 3 座农田和 2 处加工场地；任意基础格可作锚点，全部占地空闲且不越界才能建造，一座生产设施 10.00 金币、道路每小格 1.00，初始金币 50.00。点击任一子格选择、改种或拆除同一整座设施。左键短按选格、拖动平移；默认设计与主要验收基准 1920×1080、最远缩放 1.25。可见基础格、地图块候选格和生产实例是不同计数，不互相替代。
- 已确认可建造和移除农田。移除时未收获作物消失，不退费用。首版体验重点是放置生产建筑并自动产出。
- 现有七种作物和各自的加工场地。具体时长、收获量及产物见[作物与选种](../gameplay/production/crop-growth.md)。
- 开局三块农田每局等概率选择“三块同种”或“两块同种加一块另一种”；两处加工场地按所选作物匹配。同一种子得到相同开局配置，新游戏随机生成。
- 每秒推进一次经营；7 个游戏日等于 360 秒。十四商品按固定双周锚点独立报价，供需、季节、事件与成本关系参与价格，节日只移动本次，公告在实际报价前一日出现。初价、整数分限幅及完整公式见[独立报价与消息](../gameplay/trading/market-quotes.md)。
- 十四商品同价零费即时买卖，买入与自产进入同一公共库存；完整检查资金、货量和容量后提交，失败零修改，暂停可交易。七种原料保留按品种全部出售，加工品可全部出售；已投入加工的原料不可卖，手动出售不受保留底线限制。详见[即时交易](../gameplay/trading/sales.md)。
- 每种原料的公共库存保留底线默认为 0，在库存窗口按非负整数设置；设置本身不触发领取，下一经营步的领取阶段使用新底线。新建加工场地仍按稳定格序即时尝试全场领取；自动加工从未冻结且超过底线的原料中每批取最多9份，锁定本批数量并等量产出，中途不追加，少量批次同样使用完整周期。手动出售不受底线限制，提高底线不退回已投入原料。详见[加工](../gameplay/production/processing.md)。
- 农田可留存雨水；降雨与工人浇水使用同一供水状态，已获水作物生长中再次遇雨不重置，收获清除本轮水分。改种保水、拆除清水；具体顺序见[农田供水与降雨](../gameplay/production/water-and-rain.md)。主场景加载时生成10年循环地区天气预排，运行只执行生效与结束；整田供水和产量共用九格雨＞云＞晴判定，详见[地区天气](../gameplay/world/weather.md)。
- 七种作物各有适宜季节；手动和耕作表共用播种判断，当前适季即可播种，预计时间不足只提示风险。干田最低预留 1 秒供水，成熟恰在边界先结算；换季结算后其余禁生未成熟作物清理本轮作物和水分，保留农田与选种，不增加清理劳动或费用。具体表与口径见[作物与选种](../gameplay/production/crop-growth.md)。
- 工人横纵斜向每秒移动 3 基础格，即一个标准田跨度，沿真实陆地路线穿越建筑占用，到田中间格工作，道路连通不是通行前提；播种与浇水各占完整 1 秒。三人共享稳定锚点轮转与实例独占认领，完成或失效释放。两日目标从空田具备条件开始计经过时间；三人和 24 田在同一 8×8 标准田范围内验收，超范围仍照料但不承诺两日达标，详见[实现说明](../architecture/workers/worker-scheduler/implementation-movement-proposal.md)。
- 道路独占一格，土路、碎石、卵石、红砖、石板五材质均为每格 1.00 金币。选择材质后两次短按新建直线或按鼠标先行网格轴确定的 L 形整段；独立拆路工具两次短按选择投影直线，仅拆道路、不退款。四邻格跨材质自动连接，预览包含受影响旧路的操作后形状；失败整段零修改。道路参与选路偏好，不进入生产或改变工人速度；取消及输入细节见[道路铺设与移除](../gameplay/land/roads.md)。

## 水域与道路导航

水域 [#110](https://github.com/Fotally/Farm-Exchange/issues/110) 使用新局静态自然池塘，同一原始岸线决定水域、完整陆地建造和画面。工人通过 Godot 原生 A*／Funnel 绕水，使用 1/32 格保守简化、0.125 格脚底半径、1/256 格数值余量及额外离岸 1/8 格；不承诺任意略宽于脚底直径的通道必通。池塘不自动供水，不增加桥梁、挖填、第二套栅格导航或游戏磁盘缓存。完整数值与历史实验见[水域规划](water-terrain-proposal.md)，现行契约见[地形接口](../architecture/terrain/interface-terrain-map.md)。

全部道路材质原生区域成本为 1，普通陆地为 2，工速仍每经营秒 3 格。建拆后新领取或重新规划使用最新道路，已有行程保持；正常导航同步完成前暂停完整经营 tick，窗口保持响应。默认新局等待地形和导航准备完成后开始经营，显式全零池塘配置经相同创建入口保留 16,384 实例满地图基准。当前完整验收及 PR 状态以 #110 顶部记录为准。

默认三档池塘共 48 座，水面目标 8%（范围 6%～10%），中心保护区 24×24 格，近景 10×7 是生成参考椭圆轴长。配置纳入 Git，新局严格加载验证，本局保持不可变。两日照料预算由 [#154](https://github.com/Fotally/Farm-Exchange/issues/154) 独立观察，实际绕行按真实路线和既定工速推进。

## 大小地图导航与拆路预览

大小地图 [#153](https://github.com/Fotally/Farm-Exchange/issues/153) 以已认可的 1080P B 全屏原型为本阶段设计基线：左下角小地图固定全图与主镜头视野框，点击／拖动导航；M／展开按钮打开大地图，M／Esc 关闭；大地图无区域名称标签，左键短按定位、按住拖动浏览，滚轮独立缩放，同次游戏关闭重开保留倍率与查看位置，新开一局重置二者；打开大地图不暂停经营，开关地图不改变既有暂停状态。右键保留为辅助浏览。功能已接入真实主场景，具体验收和 PR 状态以关联议题为准。

完整范围及验收统一见[大小地图规划](map-navigation-proposal.md)，键位见[键鼠操作登记](input-bindings.md)。打开大地图取消建造与道路草稿，保留已有窗口；显示陆地、水域、农田、加工和道路，缩放为全图适配的 1～12 倍。输入优先级、手势收尾和边界按规划执行；原型浏览器检查不等同于正式游戏验收。同期接入 [#150 拆路初始单格预览](https://github.com/Fotally/Farm-Exchange/issues/150)，保持既有两次短按和投影拆路规则。

## 系统划分

系统按玩家行为和数据流拆分；已生效规则见[文档导航](../README.md)。

| 模块 | 职责 | 对外接口应保持的形状 |
| --- | --- | --- |
| 经营入口 `FarmGame` | 生成中心开局布局，协调占用、农田、加工、工人、库存、金币与日历；按固定顺序推进经营、换日并处理两类交易 | 聚合格子快照，查询库存价格，接收经营命令并推进一秒 |
| `LandOccupancy`、`BuildingFootprint`、`PlacementRules`、`PlantingRules`、`FarmingSystem`、`ProcessingSystem`、`WorkerScheduler` | 唯一空间实例与子格映射、固定占地/工作中心、完整放置与播种检查、每实例生产状态和三人任务/认领/游标 | 由 `FarmGame` 完整建造、拆除与推进；任意子格解析同实例，生产每实例一次；播种共用季节判断、供水共用操作，调度算法留内部 |
| `CropCatalog`、`Inventory`、`Wallet` | 分别唯一维护七作物定义、原料与加工品公共库存、金币余额 | `FarmGame` 查询定义并协调生产入库、出售和建造收支 |
| `CommodityCatalog`、`MarketQuotes` | 分别维护十四商品元数据、正式报价/排期/真实因素公告 | 读取目录，按日历推进并返回独立只读报价与消息 |
| `TradingService` | 一次性检查商品、数量、当前价、资金货物与容量，并完整结算 | 买入、卖出或全部出售命令返回真实结果/稳定失败原因 |
| `WeatherSystem` | 唯一维护地区天气预排、循环和当前活动矩形 | 提供位置／整田查询、当前快照与最近事件距离；开发／测试显式设置与自然预排在建局时分开 |
| 日历 `GameCalendar` 与比例 `GameTimeUnits` | 唯一维护累计模拟秒与暂停，换算年月日、季节和生产精确时长 | `FarmGame` 每步推进一秒；界面读取季、年、月、日 |
| 地图表现 `WorldMap` | 分块缓存地块与作物绘制结果，绘制边缘，转换等距坐标，显示所选地块 | 接收游戏状态并在经营变化后同步外观，按宿主决定更新选框，限制镜头中心在菱形内 |
| 镜头输入 `CameraController` | 区分左键点击与拖动，处理缩放和平移 | 通知 `Main` 已接受的短按，将镜头位置交给地图限制 |
| 场景协调 `Main` | 持有摆放和所选格，接收窗口意图、驱动计时器、统一刷新 | 唯一分派短按的普通选择、生产建造或道路意图，将经营命令转交游戏状态并显示结果 |
| UI 窗口与面板 | `DraggableWindow` 管拖动与边界，各窗口固定控件并只更新值；农田和加工详情使用经营语义快照，道路详情展示用途与移除 | 发出建筑选择、改种、移除和出售意图；位置只在本次运行保留 |
| 存档（后续） | 保存必要状态、恢复进度 | 读写完整游戏状态；离线收益规则待确认 |

`FarmGame` 仍把经营命令和相位顺序收在一个入口：调用方只知道格坐标、命令与经营步进，不需知道内部状态如何分配。各模块唯一持有自己的状态，`FarmGame.GetPlot` 聚合只读快照。报价算法留在 `MarketQuotes`，完整买卖收在 `TradingService`，库存没有第二份持仓存储。历史 `MarketPriceCurve` 保留为独立模块及测试，正式经营不调用。`WorldMap` 只根据快照绘制和选择，不复制经营规则。

## 分阶段交付

1. **地图基础（已实现）**：384×384 基础格、多格设施与整实例操作，等距地图、镜头与格定位。
2. **最小可玩循环（已实现）**：三名工人自动到田播种浇水，成熟自动收获、对应场地加工、按当前市场价出售，再用收入建造农田和加工场地。
3. **进度持续性**：按已确认规则加入存档、加载与离线收益。
4. **扩展内容（七种作物与配套加工已实现）**：按[作物](../gameplay/production/crop-growth.md)与[交易](../gameplay/trading/sales.md)规则提供独立农田选种、对应加工场地与全部加工品交易；其他建筑、目标与数值平衡待后续确认。

每阶段以引擎可运行、界面能验证当前行为、对应文档已更新为完成条件。存档、离线收益和扩展内容待后续确认。
