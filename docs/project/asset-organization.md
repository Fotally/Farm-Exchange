# assets 目录与素材管理约定

本页源于 2026-10-06 的素材分析与目录立规矩，目录约定继续适用。当前已选择[完整清亮 v2.0.0](../research/bright-complete-v2.md)作为素材基准，分期由 [#105](https://github.com/Fotally/Farm-Exchange/issues/105) 与子议题维护；素材选择不代表已接入，实际开发仍按各单范围完成项目交付流程。

## 按使用用途组织

正式资源按使用系统组织，原始交付按来源组织。游戏查找“使用什么”，来源资料回答“从哪里来”。不按下载包名称建立第二套正式运行目录。

下面是目录归属约定，尚不存在的目录在实际有文件时创建；本次不创建空目录。

```text
assets/
  AGENTS.md                       # 指向 .claude/rules/assets.md 的现有链接
  gameplay/                       # 世界中的正式资源
    terrain/                      # 地表图集、水纹及必要地形资源
    soil/                         # 农田干湿土层
    crops/                        # 播种层与七作物生长层
    buildings/                    # 加工设施纹理、活动部件
    decor/                        # 树、石、栅栏等环境装饰
    npc/                          # 人物图集、SpriteFrames、必要动作元数据
      npc001/                     # 多文件角色按来源 ID 归组
      shared/                     # 实际采用的共享工具纹理
    fx/                           # 世界共享短效果纹理
  ui/                             # 界面使用的资源
    icons/                        # 现有线条图标
    facilities/                   # 现有设施、作物缩略
  fonts/                          # 游戏实际采用的共用字体及许可证
  development/                    # 现有开发专用资源，保持正式包排除约定
  source/                         # 本地原始交付归档，不是游戏资源入口
    .gdignore                     # 建立此目录时隔离 Godot 扫描
    farm_exchange_art_agent_bundle/
      v1_0_2/
        farm_exchange_art_agent_bundle_v1_0_2.zip
    farm_exchange_bright_complete/
      v2_0_0/
        farm_exchange_bright_complete_v2_0_0.zip
```

`gameplay` 延续当前正式 NPC 的路径体系。地形属于地图地表，`soil` 属于农田覆层，两者分开；世界建筑图与 UI 缩略分别放在 `gameplay/buildings` 和 `ui/facilities`，可以同时存在。

角色目录是多文件资源的归组方式，不要求现有 20 张单图立刻搬入子目录。场景用的 `.tres`、`.res` 等 Godot 数据资源可以与纹理共存；完整场景和行为代码归属现有 `scenes/`、`scripts/`，制作工具归属 `tools/`，说明归属 `docs/`。

## 原包、参考和正式资源

| 类别 | 保存与引用规则 |
| --- | --- |
| 原始交付 | 原 ZIP 字节不变；记录实际内部版本和整个 ZIP 的 SHA-256。外层名称可改为项目格式，原交付名保留在来源记录中 |
| 解压预览、重建输入、参考工程 | 在项目外的工作目录展开，保持原包结构与各自 `res://` 根；ZIP 是其归档入口，不重复混进正式资源目录 |
| 默认候选资源 | 以包的默认索引和子 manifest 为准；“随包提供”不等于“项目已采用” |
| 已采用资源 | 按游戏用途复制必要文件，修复内部引用，维护来源映射和实际使用入口 |
| 参考配色、动效 | 保留原包中的参考身份；经用户确认采用后才提取，不能按同名文件覆盖默认资源 |

`source/` 为本地归档位置，目录约定本身不授予公开权限。来源包原先将NPC原图与派生动作列为私人评估、具体许可证未核实；2026-10-07维护者已明确允许公开所有已提供素材，见[授权记录](asset-sources.md)。本次仍只提交实际使用的运行资源与说明，原始ZIP和独立示例继续本地归档，不因授权扩大运行资源范围。

以后建立 `source/` 时，同时落实 `.gdignore`、Git 归档策略与各导出预设的明确排除，并验收实际导出内容。现有静态检查器会遍历整个 `assets/`，尚未允许 `.gdignore` 特殊文件；启用该目录时应同步调整该实际检查点。本次只记录约定，不修改忽略文件、检查器或导出配置。

## 命名保持语义

项目维护的路径使用小写 snake_case。文档库仍按 `docs/AGENTS.md` 使用小写连字符；原 ZIP 内供应方文件名不做批量改写。

| 文件示例 | 含义 |
| --- | --- |
| `buildings/wheat_workshop_q0.png` | 小麦加工设施，第 0 个世界朝向 |
| `soil/field_wet_q0.png` | 湿土层，第 0 个世界朝向 |
| `crops/wheat_growing_03_q0.png` | 小麦生长视觉档 03，第 0 个世界朝向 |
| `npc/npc001/npc001_sow.png` | 来源 ID 为 npc001 的四向播种图集 |
| `npc/npc001/npc001_sprite_frames.tres` | 同一角色的动作帧资源 |

只写实际存在且需要区分的状态、方向与变体。`growing_01/02/03` 是有顺序的视觉生长档，不能另造业务阶段；`q0`～`q3` 是世界朝向；`npc001` 是来源稳定编号，不重新按本地排序编号。地形纹理变体不得命名成对象朝向。

包版本记录在原始归档与来源说明里，不把包版本加到每张正式 PNG 名称中。来源升级通过记录版本和哈希区分，不以 `new`、`final`、`final2` 等名字制造多个不明确的运行入口。

## 来源说明和必要元数据

每组实际采用的新素材在同目录维护 `source_notes.md`，覆盖：

1. 来源包 ID、内部版本、原交付名、ZIP SHA-256、包内权威清单位置。
2. 包内路径到项目路径的明确映射；同组可用目录转换规则，但要列出例外。
3. 授权记录、许可证适用文件及当前使用范围；保留实际采用字体的许可证。
4. 实际改动，例如仅重命名、改写 `.tres` 引用、抽取活动层；保留原始输入，修改后不能继续声称与原包文件哈希相同。
5. 画布、pivot/脚根、方向、分层、动画时长与必要图集切片约定，链接其来源清单。
6. 状态为未接入、已接入或参考，以及真实场景/脚本入口；预留动作与实际启用动作分开记录。

原始清单留在 ZIP。运行目录只保存实际加载需要的元数据，迁移其路径字段时同步修复引用，不复制整个来源树去满足历史路径。暂不建立全项目素材注册器、动态扫描器或自定义资源加载框架。

来源总览维护在[素材来源记录](asset-sources.md)；当前包的数量、入口和已知限制见[完整清亮 v2 分析](../research/bright-complete-v2.md)，[v1 分析](../research/art-agent-bundle-v1.md)保留为历史。配色与素材版本不作为建立第二套运行目录的理由。

## 图像和资源使用规则

- 世界像素 PNG 保留 RGBA 与透明边，使用 nearest、关闭 mipmaps；不自动裁边、平滑缩放、补底色或整图旋转来伪造朝向。
- 图片画布大小不等于逻辑占地；pivot 对齐实例工作中心，NPC 脚根对齐经营位置。装饰的建议占地不自动成为建造或碰撞规则。
- 作物层与土层分开；已合成人物和身体/道具分层是两种显示方式，不能重叠使用造成重复道具。
- 动画保留逐帧时长、循环说明与视觉事件；动作不决定播种、浇水、收获或交易结算。
- UI SVG 和字体沿用 UI 的显示与倍率约定，不把世界 PNG 导入策略套到矢量和字体上。
- 素材接入的主要画面验收至少为 1920×1080，并另外检查 1× 与整数放大下的像素边缘；不据此改动已确认的镜头缩放范围。
