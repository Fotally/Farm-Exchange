# 水域地形与草土水素材设计提案

关联 [#110](https://github.com/Fotally/Farm-Exchange/issues/110)，归属 [#105](https://github.com/Fotally/Farm-Exchange/issues/105)。2026-10-07 完成源码与清亮 v2 包核对。本页是待确认的设计交付，不表示水域规则已获实施授权；首批 #106～#109 不依赖本功能。

## 事实与设计选择

现行地图为 384×384 基础格，农田、加工场地占 3×3，道路占 1×1；`LandOccupancy` 只保存设施占用，`PlacementRules` 检查范围、占用和余额。三名工人直线穿过占用，每秒移动 3 格。当前没有水域权威数据、寻路或桥梁，雨水由显式经营输入提供。具体基准见[规划](roadmap.md)、[地图规则](../gameplay/world/map-and-camera.md)和[供水规则](../gameplay/production/water-and-rain.md)。

| 选择 | 玩家含义 | 需要共同实施的内容 | 取舍 |
| --- | --- | --- | --- |
| A：纯视觉水面 | 看见水仍可建造、穿越，水不参与供水 | 地表、水纹及与设施接触的视觉处理 | 工程量较小，但水面没有地理约束，容易与玩家直觉冲突 |
| B：经营水域，建议继续讨论 | 水域和含水岸格不能建造；工人绕水行走 | 唯一地形数据、放置检查、真实陆地路径、到达性检查、岸线及水纹 | 含义一致；改变行程，必须重新确认原两日预算适用范围 |

建议 B 使用**新局按独立地形种子生成静态池塘、保持陆地连通**，暂不提供挖填或水面编辑。池塘覆盖比例、岸宽、中心保留区域的具体大小仍待确认；不把包内示例布局直接当正式地图生成器。纯视觉方案 A 是供用户比较的独立选择，不在 B 失败时自动切换。

## 建议的数据与 Module

建议增加实际需要的 `TerrainMap` Module：唯一保存 `(MapSize+1)²` 个共享顶点的草/土/水标签，以及创建时使用的地形种子和生成版本。它封装逻辑格判定和地形快照；`LandOccupancy` 继续只拥有建筑占用，不复制水域表。若用户选择 A，则仅在地图表现中维护视觉数据，不把虚假的经营限制加入 `PlacementRules`。

以下为 B 的拟定最小 Interface，成员名称只是设计表达，尚未新增 C# 类型：

| 调用方 | Interface 及约束 |
| --- | --- |
| `FarmGame` | 创建新局时一次构造地形，地形初始化完成后才生成中心设施和工人；创建失败须返回明确原因，不能悄悄改成无水图 |
| `WorldMap` | `GetCell(cell)` 返回四角标签和派生的格类别；只读，不反向写地形。纹理变体由固定种子和格坐标决定，不随镜头变化 |
| `PlacementRules` | 通过同一 `IsLand(cell)` 检查占地全部基础格；建议四角全部非水才算陆地。预检与正式建造执行同一判断，失败不扣费、不登记占用、不清装饰 |
| `WorkerScheduler` | 读取同一 `IsLand(cell)`，私有路径算法只经过陆地；返回不可到达状态后不认领该任务，不瞬移或穿水 |

静态地形查询为常数时间；陆地连通性在新局构造时检查，寻路只在分配任务、任务失效时发生，不在每个视觉帧全图搜索。若正式允许分离陆地或桥梁，应先补充可达性与通行设施规则；本提案不预建桥梁或可替换地形框架。

建议路径仍允许斜行，斜行的两侧正交格也必须可行，避免穿过两个水角；步速保持现行值。两日预算原本针对标准田布局的直线路程，绕水后不能声称自然保持，需要在确认地图限制后重新测量同一案例。暂停冻结任务与水纹；倍率通过唯一时间驱动推进经营，水纹只读视觉时间，不产生水分、降雨或经营事件。

## 81 组合、三变体的实际映射

来源均相对于 ZIP 包根 `FarmExchange-Bright-Complete-v2/`。完整基准见[清亮 v2 分析](../research/bright-complete-v2.md)。

- `default/static/terrain/manifest.json` 定义草=2、土=1、水=0，角序为 top、right、bottom、left，组合 `code = top + 3×right + 9×bottom + 27×left`，范围 0～80。
- `previews/world/scripts/scene_view.gd` 证明图集序号为 `index = code + 81×variant`，variant 为 0～2；三变体是纹理差异，不是 q0～q3 朝向。
- 9 列，stride=(68,36)，padding=2；切片左上角为 `((index%9)×68+2, floor(index/9)×36+2)`，取 64×32 区域。普通图用 `terrain_81.png`；采用菱形网格绘制时用 `terrain_81_mesh.png` 和其菱形 UV，不能把两种采样方式混写。
- 技术 mask 为 `masks/water_81.png`、`land_81.png`、`soil_81.png`、`grass_81.png`；水纹为 `ripples.png`。mask 可裁剪表现，但不能另推导一份可建造数据。

本项目 `MapCoordinates` 的格坐标表示**格中心**。建议顶点标签 `V[x,y]` 位于格空间 `(x-0.5,y-0.5)`；格 `(x,y)` 的上、右、下、左角分别取 `V[x,y]`、`V[x+1,y]`、`V[x+1,y+1]`、`V[x,y+1]`。共享边两端读取相同顶点，岸线才能连续。地图边缘使用已保存的最后一行/列顶点，绘制裁剪于地图菱形，不查询越界格。不要直接复制示例以格左上角为原点的坐标。

示例：全水 code=0，全土=40，全草=80；仅顶角为水、其余草为 code=78；顶右为水、底左为草为 code=72。按建议 B，后两个格均不可建造；地形的半水画面与经营禁建来自同一四角数据。

## 中心、存储和共同实施范围

建议保留中心三田、两加工场地及三工人起点的完整陆地区，并给已确认标准田预算验收区域保留连通土地；先计算这一保护区，再生成其外水域，不使用生成后搬动开局设施的补救。具体保护范围需用户确认后定值。

当前没有存档。本轮不增加存档系统；未来不可只保存一个种子而遗漏生成版本。若地图永不编辑，可保存种子、算法版本、地图尺寸并核验确定性；若允许编辑，则还须保存实际变更后的权威顶点数据。两者待存档任务决定。

规则确认后的实施必须同时包含地形权威、放置与通行检查、岸线映射、水纹裁剪、失败反馈、中文玩法与接口文档。水体不给农田供水是本提案建议，尚未得到用户确认；若选联动，需另定邻接距离、供水时点及水稻含义，不能由图片颜色推断。

## 可执行验收范围

1. 遍历 81×3 切片，检查序号、像素区域、mask 对齐；相邻格共享边无裂隙，地图四角和最外行列无越界。
2. 同种子/版本生成同地图；中心每座设施九格、三工人起点均陆地且连通。种子覆盖测试应检查连通性，不能只看一张截图。
3. 3×3 中任一子格含水时预检和执行同样拒绝；道路单格同规则。失败时金币、占用、作物和环境装饰零修改。
4. 三工人从水体两侧到田，测试直路、绕路、对角夹角、不可达田及途中目标拆除；重复认领、穿水、瞬移均失败。
5. 对照原 24 田两日预算记录实际变化；规则未确认前不改工人数、速度或动作耗时以使测试通过。
6. 1920×1080 下观察岸线、建筑边缘、人物过岸和水纹裁剪；暂停、0.5×/1×/2×及开发高倍率不改变经营因果。功能实现再按项目流程完成覆盖率、指定引擎测试和导出启动。
