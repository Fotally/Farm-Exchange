# 设施朝向与四向素材设计提案

关联 [#111](https://github.com/Fotally/Farm-Exchange/issues/111)，归属 [#105](https://github.com/Fotally/Farm-Exchange/issues/105)。2026-10-07 完成源码与素材清单核对；本页操作方案均待用户确认，不实施旋转玩法，固定 q0 的首批接入可独立交付。

## 既有事实与建议交互

现有 `BuildingSpaceSnapshot` 含锚点、类别、占地和工作格，没有朝向；农田与加工场地固定 3×3、工作偏移 `(1,1)`，道路 1×1。玩家从目录选类型，逐次建造后保持摆放，右键、Esc 或取消按钮退出，详见[放置预览方案](../gameplay/land/opening-and-building.md)。

建议只给农田和加工设施增加 q0～q3 外观朝向：摆放时用 R 或“旋转”按钮按 q0→q1→q2→q3→q0 切换；详情提供已建旋转按钮，暂停时也可操作。旋转不收费、不重启生产、不改占地或工作格。以上是建议，按键、建成后是否允许、费用均需确认。

| 方案 | 取舍 |
| --- | --- |
| 仅摆放前旋转 | 新增行为最少，但调整既有建筑必须拆除重建，触发现行作物/原料损失 |
| 摆放前及建成后旋转，建议 | 玩家可自由调整外观；需要明确命令有效性和生产不变约束 |

建议进入一种新的摆放类型时重置 q0，连续放置沿用当前朝向，取消后丢弃草稿朝向；拆除移除实例朝向，重建使用当次摆放请求。新局初始设施为 q0。未来存档保存每实例朝向，本任务不提前增加存档实现。

## 状态归属与最小 Interface

`LandOccupancy` 已唯一拥有锚点实例，建议在同一实例记录朝向并通过 `BuildingSpaceSnapshot` 只读提供，避免另建按锚点同步的朝向字典。`BuildingFootprint` 仍唯一定义占地与工作格；q 的变化不改变这两个几何事实。UI 仅拥有未建成候选朝向。

拟定 Interface：

- `FarmGame.CheckPlacement` / `TryPlace` 同时接收合法 q；正式执行重验类型、q、完整占地与资金，一次完成登记及扣款。非法 q 明确拒绝，不能静默截断或改成 q0。
- `FarmGame.TrySetOrientation(cell,q)` 将任意子格解析为同一实例，一次检查目标存在、类型支持和 q 有效性后提交；结果包括成功或稳定失败原因。设置相同 q 为成功且不产生其他变化；拆除后旧命令失败。
- `GetBuildingSpace` 返回新的只读快照。`WorldMap` 内部封装 q 到实际图的选择，UI 不直接改 Sprite，不分别更新朝向和纹理。

实现时名称可随既有接口统一，不新增只转发调用的 Module 或没有第二种 Adapter 的 C# interface。更改朝向只使该实例外观缓存失效；不扫描全图，不重分配工人任务，不重置成熟或批次进度。暂停只冻结时间，命令提交仍即时生效；公共倍率和开发倍率不改变命令含义。

## 实际 q 映射与图片层级

来源为[清亮 v2](../research/bright-complete-v2.md)包根下 `default/static/manifest.json`。七建筑、24 个农田图层项和 32 类装饰共 63 项，每项四张方向 PNG；252 个方向项实际有 210 种 RGBA。相同像素项只能按 `equivalent_directions` 复用，不能从对称外观自行猜测。

| q | 包内世界坐标变换 | 选图规则 |
| --- | --- | --- |
| q0 | `(x,y,z)` | `views` 中 q=0 |
| q1 | `(-y,x,z)` | `views` 中 q=1 |
| q2 | `(-x,-y,z)` | `views` 中 q=2 |
| q3 | `(y,-x,z)` | `views` 中 q=3 |

灯光固定屏幕左上；必须换对应 PNG，不能旋转屏幕二维整图。人物 `down/left/up/right` 是屏幕移动方向，与 q 没有序号等价关系。设施朝向不自动改变行走方向或在田中心工作的朝向。

建筑画布 256×240、pivot=(128,176)，农田画布 224×192、pivot=(112,128)。图像左上角为实际设施工作中心投影减 pivot；所有方向保持相同接触点。地面低层、实体按接触点深度排序、实例内部再遵循分层顺序。工人在前后穿行时，不能因为轮毂或作物的局部层号而被全局错误遮挡；选框和候选占地仍来自完整九格几何。

动效仅覆盖 q0 两建筑与三作物。建议明确 q0 使用已经验收的分层动效，q1～q3 使用各自已提供的静态图；这是待确认的朝向表现选择，不是资源缺失时的兜底。旋转离开 q0 时移除旧动效，不能留下悬空叶片、烟或旧作物层；回到 q0 时按当前真实快照建立表现，不补播历史产出。不得将 q0 叶片平面旋转伪造其他方向，亦不能让建筑身向 q1 而叶片仍向 q0。

农田旋转需地面和作物图层同取 q；未播种无植株，三档仍依实际生长进度选择。当前 q0 根点重组契约不能推定 q1～q3 已具有可用风动根点。装饰已在环境生成中按素材选择朝向，是否允许玩家旋转装饰另行确认，本建议不增装饰选择或操作入口。道路没有这套 q 图片，不借设施旋转增加道路方向语义。

## 共同实施与可执行验收

1. 对七加工设施、七作物三档和农田底图逐项遍历四向，检查清单路径、pivot、对称组；静态等价项复用后画面仍一致。
2. 候选按四次旋转回到原图，九格占地、冲突格、选框与鼠标锚点始终一致；失败建造不保留半登记朝向。
3. 从任意一个子格旋转已建实例，作物、水分、批次、年度表、工人任务、库存和金币完全不变；拆除、无目标、非法 q、道路均有明确结果。
4. q0↔q1 切换覆盖磨坊叶片/轮毂、糖坊蒸汽和三作物植株，确保旧图层消失且事件不重复。暂停中切换和恢复、高倍率后切换同样成立。
5. 1920×1080 截图覆盖相邻高建筑、人在前后、地面选框、四向预览；保持像素大小与相机倍率，检查屏幕左上光源和接触层级。
6. 规则确认后朝向命令、实例状态、UI、四向静态及 q0 动效转换一同实施，补充中文玩法与接口文档，再执行项目审查、逐模块覆盖率和指定引擎导出验收。

待用户决策：仅摆放前或允许建成后旋转；具体按键/按钮；是否采用免费且只改外观；摆放朝向保留规则；是否接受 q1～q3 静态表现；装饰是否维持纯环境。确认前不改现行建造请求。
