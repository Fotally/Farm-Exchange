# 配置库的严格输入、持久修订与删除

履行[流程配置编辑接口](interface-scenario-configuration-editor.md)，计划来源为[C分步设计](../ui/developer-tools-window/implementation-step-flow-editor.md)与[#104](https://github.com/Fotally/Farm-Exchange/issues/104)。

## 单一字段来源

`ScenarioEditableConfiguration`及其嵌套类型对应旧v1 JSON。字段中文元数据直接附于序列化属性；`ScenarioConfigurationSchema`扫描为只读描述，严格加载与通用表单共用该描述，避免逐窗口复制数量、日期或倍率约束。扫描只面对已登记类型；不扫描经营对象或`ScenarioConfiguration`运行包装。

枚举及字符串有限选项都使用字段的`Values/Labels`生成正式值与中文显示名。枚举值必须是已声明的精确成员名，中文标签与值一一对应；扫描时拒绝缺映射、未知成员、重复值或标签数量/内容无效。序列化继续使用正式成员名，显示标签不参与保存。元数据错误明确反馈，不自动使用枚举代码名补标签。

严格读取先拒绝对象的未知及重复键，再先读取非条件字段，最后判断条件字段。独立局要求seed，当前局发现seed即拒绝。写入按相同描述遍历，条件隐藏字段不序列化。int32/uint32直接解析和输出，不经浮点数保存。JSON加载继续拒绝字符串伪装数值、超容量、非有限数、未知原料、非法日期及非递增时间段。

`ScenarioConfiguration.Load`只读取一次文件字节，再交由同一描述构造DTO，将其转换为固定运行值；SHA-256仍计算原始字节，含BOM或原排版，不使用规范写入后的字节代替。后续编辑草稿、覆盖文件或删除配置不改变已加载运行对象。

## 草稿与数组

草稿保存私有编辑对象和加载时的规范字节。非法输入另外按字段路径保存，不把最后一次合法值冒充用户输入；UI读取时先取得非法原文，能继续修正。完整校验同时合并输入错误与时间顺序错误。

有序数组增删移动只改变草稿。删除及移动会重映射非法输入路径，错误跟随原行。添加使用已登记元素类型的默认值，不解释动态对象图；新增行日期与前一行不递增时仍明确报错，不能自动排序或静默改动时间安排。

## 发现与写入

只读示例来自既有三份权威JSON或其开发构建资源字节。用户目录递归发现JSON，`.hidden-flows.json`是目录状态而非参数文件；非法配置报告于`DiscoveryErrors`。隐藏流程记录是明确持久状态，不能通过内置示例仍存在来自动重新显示流程。

另存为使用输入的新caseId、修订1和新文件；文件名由库生成唯一标识，中文配置名称不作为路径。旧文件保持。覆盖重验条目原摘要、来源与修订，拒绝外部修改后的旧草稿；新修订由库计算，写成功后才返回新的条目和干净草稿。

写入使用同目录临时文件，完成全部字节后以同文件系统移动提交；失败保留原目标，不切换输出目录。临时文件只在本次操作中存在，异常后清理。保存不复制历史配置，不触碰报告目录，不自动提交Git；编辑器`tests/scenario-configs/user/`用于长期版本管理。

覆盖会使原历史报告摘要无法再由该位置的新内容核验。这是已确认的覆盖含义；报告继续保持当时原路径与摘要，不冒称旧输入可复现。另存为保留旧文件，仍可核验其旧报告。

## 外部修改后的显式重选

[#118](https://github.com/Fotally/Farm-Exchange/issues/118)将重新发现、按稳定文件身份定位和重验打开集中到 `ReloadSelection(entry)`。库不按可编辑的名称或列表下标恢复；合法外部修改即使未递增修订也会生成新摘要与独立草稿。正常 `Open`、覆盖、删除及启动仍重验旧摘要，旧脏草稿不会得到新凭据，也不会自动覆盖外部文件。

恢复结果同时携带本次合法目录、打开成功的新草稿或明确错误。文件已删除、改为非法JSON或在扫描后再次改变时，不返回可运行的旧草稿；对应失效条目从本轮列表移除。UI只呈现结果，不自行计算摘要或拼接扫描顺序。未保存输入在UI确认放弃后才重载，取消保持草稿；不引入监控、热加载或自动合并。

## 删除实际文件与持久目录项

垃圾桶确认由UI负责。库不使用任意调用方路径直接删除：条目须属于已登记流程及指定可写目录，原文件内容须仍匹配该条目，文件和目录不能通过可写树内的符号链接指向外部。内置条目永远只读。

单个配置删除只删除该文件。流程删除先扫描和重验全部所属可写配置；存在无法识别的用户JSON时拒绝，避免无法证明删除范围却报告成功。随后逐个删除，再写隐藏流程状态；全部完成才移除内存目录项。C#固定实现、三份只读示例及历史报告始终不属于删除对象。

多文件删除不是一个文件系统事务。操作中遇到文件占用或权限失败立即停止并反馈；已经完成的文件删除不回滚，也不声称回滚。目录项尚未持久隐藏时继续可见，UI重新扫描后呈现实际仍存在的配置。用户释放占用后可再次确认完成剩余文件与目录项删除。

## 验证入口

`TestScenarioConfigurationSchema`验证严格字段、整数容量、游戏日期、倍率、条件种子、非法原文保持、数组顺序/错误重映射，以及同一描述处理第二种布尔/枚举/嵌套对象数组形状。枚举检查中文标签、正式值无损读写和未知/非正式值拒绝；字典、递归、缺失元数据及非法枚举映射明确拒绝。

`TestScenarioConfigurationLibrary`在唯一临时目录验证三份旧JSON、只读保护、另存为/覆盖修订、重启发现及持久隐藏、原字节SHA-256与加载隔离、同名/外部修改/非法文件/外部路径拒绝、写入失败、修订上限、真实文件删除与历史报告保留。Windows另外用允许读取但禁止删除的文件句柄验证部分删除失败和覆盖失败后实际文件、修订及列表；POSIX允许删除已打开文件，因此不以该Windows句柄方式验收POSIX失败。

上述测试场景及完整编译、覆盖率、图形和导出验收由本issue整体验证统一运行，本实现说明不把尚未运行的检查记为已通过。
