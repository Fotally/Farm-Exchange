# 清亮 v2 环境装饰实现与验收约定

履行 [WorldMap Interface](interface-world-map.md)，关联 [#109](https://github.com/Fotally/Farm-Exchange/issues/109)。**状态：2026-10-07 已完成WorldMap整合、独立审查、完整测试与覆盖率、真实图形/性能及Windows导出启动验收。** 以下参数为当前实现值，证据见[验收记录](../../../archive/project/testing.md#2026-10-07-105-清亮-v2-首批素材动作动效与环境验收)。

## 已确认规则和状态归属

32 类装饰为纯环境，首批 q0；无占地、碰撞、费用、采集、掉落或手动摆放。正式建造成功后按真实完整占地清除装饰，预览和失败不清除；拆除后不自动重生。开局设施区域不生成装饰。来源与导入规则见[素材管理](../../../project/asset-organization.md)、[清亮 v2](../../../research/bright-complete-v2.md)。

由世界表现 Module 唯一持有装饰落点、已清除状态和绘制缓存，`LandOccupancy` 仍只持有真实建筑。`WorldMap` 初始化一次环境布局，接收完整建造成功结果或成功后的 `BuildingSpaceSnapshot`，内部遍历其 `Footprint.Offsets` 清除；`Main` 不逐棵查树或复制 3×3 数值。只移出镜头不能删除权威环境落点，也不能再次调用随机生成让已清除装饰复活。

可以在 `WorldMap` 内部实现实际需要的私有记录和按格查询，不因议题单列而增加只有转发作用的公开 Module。环境数量和状态不写入钱包、库存或工人；暂停不阻止玩家建造后的同步，倍率不改变装饰随机分布。

## 层级、跨格与清除

每装饰左上角为接触根点投影减各自 pivot。树冠、木料堆画布超过基础格很正常；排序依据接触根点，不按贴图上沿/底沿或类型统一层级。与人物、设施共用实体深度排序，土和基础地面在下层。q0 招牌和栅栏不是 CanvasLayer UI，不可全局置顶遮住工人。

装饰锚点位于成功建筑完整占地内就清除，冠幅伸入但根点在外的装饰保留；不扩大逻辑占地去迁就树冠。保留树冠可能遮住新建筑的一部分，必须按接触深度显示并实测，不以透明像素包围盒阻止建造。高树、木料堆和人物的层级需分别检查，不能把低草例外推成全部装饰固定在人物脚下。

建造跨 8×8 地图缓存块时，逐真实占地格清除对应锚点，并更新所有受影响的环境可见缓存。建造失败、鼠标预览、余额变化、选择地块不触发清除。道路只清除真实一格；相邻区域保持。重新同步、镜头离开再返回、拆除建筑都不恢复已清装饰；开始新局才重建该局环境。

## 当前分布与缓存参数

独立视觉种子固定为 `0x6e9375c1`，所有新局使用相同环境布局，不随开局作物随机种子变化，也不消耗其随机序列。无存档规则在本单引入。每格hash为无符号32位溢出混合：`v=col*374761393+row*668265263+seed`，再`v=(v^(v>>13))*1274126177`、最后`v^(v>>16)`。

自然27类排除hay_bale、timber_store、fence、farm_sign、bush_hedge；`hash%64<2`时生成，总密度约1/32，全图约4608点（实际数量由固定hash决定）。种类以`(hash>>8)%27`等权选择，包含高树、低草花、灌木、石头，不添加玩法含义。每格最多一个环境根点。

人工5类共10个明确点，以(192,192)为参考中心：草捆偏移(6,2)/(7,2)，木料堆(-6,4)，栅栏(-6,-4)/(-6,-3)/(-6,-2)，招牌(6,4)，绿篱(-2,4)/(-1,4)/(0,4)。人工点替换同根点自然项；三段栅栏和三段绿篱之间留有视觉开口。初始实际设施占地与任意已占用点随后统一清除，不为冲突点寻找替代位置。

内部`EnvironmentDecorations`仅由WorldMap持有；字典保存剩余根点、类型、画布Bounds，删除即永久清除，不维护第二份正式占地。世界同步时遍历真实`Footprint.Offsets`删除相应根点；重复同步为空操作。地图离屏不删除落点，镜头仅以完整原画布与视口相交判定可见：可见才创建Sprite2D，离屏释放绘制节点，下次入屏从仍存在的记录恢复。所有Sprite挂入同一共同YSort层，Position为根点、Offset=-pivot；纹理最多32种按实际可见类型加载并共用。初始化不立即创建全图数千节点。
## 可执行验收

1. 对32项核对存在、尺寸、pivot与q0路径；截图验收完整采用表，自然/人工项各出现在对应布置中。
2. 同种子两局环境落点一致且开局作物随机序列不受影响；初始3田2场全部占地无环境锚点。
3. 非三格对齐、跨四块的3×3建造：占地内环境全清、占地外保持；道路只清1格。预览、占用冲突、越界与余额不足均零环境修改。
4. 拆除、重复同步、镜头返回均不复活装饰；环境清除前后金币/库存/工人状态仅包含原建造的正常变化，不多扣清理费。
5. 1080P观察树后/树前人物、冠幅越格的新建筑、木料堆与高石、栅栏开口和选格：装饰不拦鼠标选地、不改变寻路、层级稳定。
6. 满地图图形性能平均≥60 FPS、P95帧间隔≤16.67ms并保存前后截图；每次镜头变化只更新可见环境，不重生成随机布局或全量重建地面。

## 已实现的真实场景检查

`tests/integration/test_environment_decorations.tscn`以1920×1080运行，从真实Godot树中观察绘制Sprite及对应根点，不暴露WorldMap私有字典。验证开局占地无环境、外围五种人工图实际存在；固定自然布局(159,7)跨块3×3内有灌木(159,8)、白桦(160,8)、金树(159,9)，通过真实建造恰好移除这三根点且区域外保持。测试还覆盖预览/越界失败零清除、道路单根点、拆除/镜头离开返回不复生、金币只收原建造费且工人与时间不变。

孤立橡树根点(89,94)用于真实NpcCharacter在树前/树后不透明像素交叠比较，并验证根点离屏而树冠仍可见的原图像素。截图保存`coverage/environment-center.png`、`environment-before-build.png`、`environment-after-build.png`、`environment-tree-behind.png`、`environment-tree-front.png`、`environment-tree-edge.png`。2026-10-07独立场景通过，记录位于本地`build/issue105-validation/environment-motion.log`；满地图FPS、综合覆盖率与导出验收另列最终交付记录。
