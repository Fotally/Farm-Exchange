# WorldMap 分块缓存与静态资源实现

对应[WorldMap 对外接口](interface-world-map.md)。空间权威仍属于 LandOccupancy/BuildingFootprint，生产状态仍由 FarmingSystem/ProcessingSystem 拥有；WorldMap 只保留从快照得到的绘制缓存，不推进经营。

## 地面与实例缓存

地面仍按8×8基础格组成48×48块，地表采用清亮v2三元mesh图集，从本局地形读取81组合编码；稳定格坐标选择变体0～2。每块缓存带UV的ArrayMesh与道路材质/mask/稳定变体及临时状态，五张原图集的AtlasTexture覆盖草地。道路变更只重绘受影响可见块，屏幕外脏块进入视野时重绘。镜头只改变可见性，农田或加工外观不重建草地。连接及操作完成后预览见[道路实现](implementation-road-appearance.md)。

`SyncFromGame`按稳定空间快照每生产实例读取一次`GetPlot`。实例外观键为建筑类别、作物类别、作物阶段、湿润、三档索引和实例朝向；不把每秒变化的精确进度加入键。`GrowthProgress`由经营入口以精确时间单位计算，三档是`[0,1/3)`、`[1/3,2/3)`、`[2/3,1)`。Seeded显示通用种子，None无作物，Growing选择对应七作物之一。改种或同种重启、自动收获、换季清理均按新快照撤掉旧层；拆除立即释放土层/表层节点，同锚点重建使用当前类别与作物。

地图仅缓存上次完成空间同步的只读快照引用。`LandOccupancy` 在建造、移除与清空后失效该快照；引用未变时，不重建道路快照投影、不构造设施删除 `HashSet`、不扫描环境完整占地。引用改变时按新旧道路差异刷新格和四邻涉及块，不以数量相等判断占地相等；首次初始化也执行完整空间同步。离屏脏地面块仍由镜头可见性更新时重绘。

空间同步将经营局的建筑布局投影为地图绘制缓存：新增实例创建土层／设施节点，删除实例释放旧节点，道路占用更新地面块，新增完整占地永久清除其中环境装饰根点。它不会推进农田、计算产量或更新土地权威状态。多数经营秒没有建拆，因此这些工作可以跳过，而农田水分、作物档位与加工外观仍在下述动态刷新中更新。

`ReferenceEquals` 判断依赖明确的[土地生产者约定](../../land/land-occupancy/interface-land-occupancy.md)：占地未变化复用同一不可变列表，成功建拆后发布新列表，已返回对象不被改写；`FarmGame.GetBuildingSpaces` 原样转发。不能每次查询复制列表，也不能原地修改列表后保留引用。前者导致重复空间同步及性能回退，后者导致漏掉建拆；同数量同锚点更换类别／朝向也必须发布新快照。`TestLandOccupancy` 保护生产者稳定性，`TestFarmGame` 保护经营转发，既有 `TestRoadMap` 保护消费者对同数量变更的响应。

所有生产实例的 `GetPlot`、外观比较、`Processing` 状态与 `Snapshot` 更新仍逐次执行；`UpdateFacilityVisibility` 和可见实例的 `Motion.Configure` 保留，真实成功结果仍按原凭据重验。土层的 `_visible` 与表层的 `_surfaceVisible` 是既有节点显隐缓存，避免不变时反复写Godot属性；表层由是否使用q0局部动效独立决定，不能随土层直接打开。该优化不改变主场景的推进／刷新时机、不延后生产外观，也不新增经营或占地权威状态。

加工动效直接复用该次 `GetPlot` 中的 `Building == Processor && RemainingSeconds > 0`。经营详情的加工中状态也由同一加工快照的正剩余时间判定；地图仅需要启停，不再重复读取完整详情的作物、报价涨跌、库存与待料说明。开始、完工与完工后同秒续批仍按最新完整经营快照同步，未减少动态实例刷新。`TestWeatherPresentation` 经真实买入原料、领取启动及批次完成，对照 `GetProcessorDetails` 状态与 `GetPlot` 剩余时间验证磨坊等待不转、加工旋转、完成待料停止。

资源映射、q0～q3路径、pivot、外观键和节点缓存均为WorldMap内部实现，不把纹理路径或字典暴露给场景协调入口。七建筑、两土层、播种和七作物三档均提取四向，共124张原字节PNG，另保留一个地形图集。加载时使用固定四向数组，土层、播种层与生长档都按同一个快照朝向索引；不动态扫描目录，不旋转整图。来源见各`assets/gameplay/{terrain,soil,crops,buildings}/source_notes.md`与[素材总览](../../../project/asset-sources.md)。

## 占地外围几何

外围计算继续集中在现有内部 `PlacementPreviewGeometry`，不增加转发模块。`GetCellOuterEdges(anchorCell, offset, offsets)` 按同一四邻顺序检查完整占地偏移集合，只返回没有相邻占地格的边，角点由 `MapCoordinates.GridRectangleOutline` 转换为地图本地坐标；它不读节点、颜色、线宽或缓存，也不将越界候选移位或裁切。实际固定形状仍唯一来自 `BuildingFootprint`，几何模块没有新增建筑配置。

`SelectionOverlay` 通过 `FarmGame.GetBuildingSpace(selectedCell)` 解析任一子格的同一锚点／占地后，逐格调用此方法，以既有3像素金线绘制整座外围。空格选择继续绘制原有单格线框。`PlacementOverlay` 从当前候选同一占地定义逐格调用此方法，仍先画半透明设施图与逐格冲突覆盖，再以2像素绿／红线绘制对应格的外围边；内部逐格的1像素提示线保持。两个调用方各自建立一次偏移集合并保留自身重绘时机，相同候选的缓存判断不变。

共享边计算只在独立交互覆盖层绘制，不调用 `SyncFromGame` 或地面块重绘。`TestWorldMap` 以3×3、1×1和既有2×4矩形夹具检查唯一外围线段及越界原位置，`TestRoadMap` 逐子格核对真实整座金框和未改变的内部边像素，`TestPlacementPreview` 核对三类型及冲突／越界候选的逐段外围颜色；后两者同时保护 `ChunkRedrawCount` 不增加的约定。

## 统一层级

从后至前依次为：

1. 地表/道路分块（Z=-2）。
2. 农田干湿土（Z=-1）。土层永远不会盖住人物脚根。
3. 共同YSort层（Z=0）：建筑、通用播种及四种静态整田作物以工作中心为节点原点，q0小麦/甘蔗/萝卜各独立植株以根点为节点原点，人物以脚根为节点原点，Y较大者后画。人物容器也启用YSort，使各人物跨容器参与排序；同Y按场景节点顺序稳定排列。
4. 地图边缘与整设施金色选框（Z=10）。
5. 候选朝向的设施半透明图、逐格冲突覆盖/外围线与锚点环（Z=11）。候选属于交互提示，置于真实设施前方，不参与世界遮挡；先画候选图再画冲突覆盖，不能让屋顶遮掉红格。

建筑画布256×240/pivot(128,176)，农田224×192/pivot(112,128)，均保留原透明边并对齐`WorkCell`；逻辑3×3占地不由PNG大小推断。玉米、水稻、马铃薯、向日葵仍按静态整田工作中心排序，不裁切原图；q0小麦、甘蔗、萝卜采用原包独立植株，每株原点为根点，经两层嵌套YSort参与同一世界排序。q1～q3全部采用各方向完整静态原图，按设施工作中心排序；q0磨坊body→sails→hub在单个建筑内部保持局部顺序，不能将叶片抬为全场高Z。

## 跨块与视野边缘

设施静态层作为独立Sprite2D、实际动效作为同级FacilityMotion绘制，不隶属锚点地面块，不按8×8块裁剪。可见性使用保留的整幅画布矩形；工作中心已经离开视口但屋顶仍与视口相交时仍显示。镜头变化只检查块与实例可见性，不读取或推进生产。工人不受地图块开关影响。选框按真实占地外边单独绘制，任一子格仍操作同一实例。

## 静态水域与共享水纹

每块 mesh 的 UV 从本局 `TerrainReadView` 的权威四角编码及稳定三变体生成。地表使用块内 `MeshInstance2D`，独立挂共享水纹材质并在父块后方绘制；道路仍由父块绘制，避免道路 UV 被错误解释为地形 mask。所有块共享 `WaterAnimationSeconds`，每帧只更新一个 shader uniform，不因水纹变化重建 mesh 或请求块重绘。纹理选择和水纹相位使用世界局部坐标，跨块无时间相位重置。水 mask 仅裁剪波光，与逻辑通行完全独立。

水 mask 的透明度才是水面裁剪依据；PNG 导入的透明边颜色修复可能扩散 RGB，因此 shader 读取 alpha，不读取透明像素的红通道。`TestWaterRippleRendering` 在真实 SubViewport 中直接对比四倍率与暂停前后的像素，分别要求三种纹理变体水面变化、岸格干地和完整陆地不变，避免只验证 CPU 时间变量而漏掉 shader 或 UV 错误。

水纹补丁的空间周期为 80×40 地图本地像素，仍读取原图中的独立 24×24 纹理片，并共用原有六经营秒透明度周期。空间相位与地表三变体的格序分离，避免某类地表永远落在水纹补丁空隙。原 96×48 周期存在可证实的共振：地表变体 `(73x+17y)%3` 等于 `(x-y)%3`，第 0 变体的格中心横坐标是 96 的倍数；实际 mesh 横向半宽仅 32.75，无法触及该周期内横向 `[36,60)` 的水纹窗口。初次真实 GPU 的三变体变化点为 `0/40/30`，快复现精确重现该结果，且陆地和岸格干地均零变化、暂停整帧保持；失败不是整个水纹未推进，也不通过忽略第 0 变体来处理。128×64 试验虽解除了锁定，但密度不足、三类变化均为 8，失败证据独立保留；80×40 提高同一原素材补丁的可见密度，真实快探针得到 `76/31/124` 并通过原门槛。

像素验收仍要求每个变体至少 10 个水面探针实际变化，两类干地零变化，暂停整帧相同。每个倍率先保存真实 before／after／paused PNG、各变体和分类的代表探针及全部变更探针，再执行原门槛；JSON 同时记录实际材质绑定、shader 哈希、uniform 时间、atlas／mask UV、mask alpha 与 GPU RGBA。因此失败也保留可复查的实际颜色及帧，不只留下计数或堆栈。`TestWaterFps` 普通门槛失败也记录各失败倍率及原测量事实，仍继续完成全部矩阵；首个失败档的真实截图立即复制为 `failure.png` 并注明来源，不用最后一档或之后成功阶段的图替代。场景异常单独记录实际阶段；若已经保存普通失败图，异常帧存为 `exception.png`，保留两处真实事实。
