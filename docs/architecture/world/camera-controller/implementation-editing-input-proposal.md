# 镜头键盘编辑输入归属修复设计

关联 [#136](https://github.com/Fotally/Farm-Exchange/issues/136)。分支为 `fix/136-camera-input-focus`，基线为 `ed84e455d703e59cc0257b7295fe6c866e6987f6`。本分支已实施焦点判定与专项回归测试；现行契约见 [CameraController Interface](interface-camera-controller.md)。完整 dev 集成验收及 Windows 导出由集成步骤统一完成，专项结果不表示发布验收已完成。

修复保留 CameraController 的逐帧键盘移动，在读取方向前检查当前视口的真实可编辑焦点。文本和数字编辑期间只屏蔽键盘平移，鼠标状态校正、地图短按和缩放仍走原路径。Main 与各窗口无须发送“停用镜头”命令。

## 问题和可观察结果

基线在指定 Godot 4.7.2 Mono 的真实 Main、原生 GUI 焦点及公开 Input 事件下复现：年度表名称正常输入 `d`，全局 D 仍为按下，相机处理 0.1 秒同时移动 56 世界像素。名称和原料保留数字输入使用左方向键时，光标正常左移，镜头同时移动 −56 像素。未编辑对照保持原 56 像素移动。该证据为 headless 主场景及受控处理时间，不等于 Windows 导出或桌面人工验收。

GUI 消费事件不会清除全局 Input 状态。问题发生在 CameraController 从全局键态生成地图方向的 Seam；窗口输入本身已经正确，无须逐个窗口改写键态。

## Module 与 Interface

| Module | 状态和责任 |
| --- | --- |
| Godot Viewport 与编辑控件 | 真实键盘焦点、文本、光标、编辑和输入法状态 |
| CameraController | 玩家倍率、镜头位置、鼠标意图；决定本帧是否可生成键盘平移 |
| Main 与窗口 | 组装和经营意图；保持原控件及焦点，不另存镜头是否允许移动 |

保留所有现有公开成员、事件和场景配置。新增约定属于原 Interface 的使用语义：当前视口有可编辑文本控件焦点时，WASD 和方向键不产生镜头平移；编辑焦点释放后的下一帧恢复原全局键态轮询，速度仍为 `700 × delta / PlayerZoom`。按钮焦点本身不视为文本编辑，不关闭原地图键盘能力。

## Implementation 和焦点判定

在 CameraController 内使用一个私有判断读取 `GetViewport().GuiGetFocusOwner()`，不缓存焦点、不逐帧扫描整棵 UI 树。它读取实际控件类型和可编辑状态：

| 当前焦点 | 是否屏蔽键盘平移 |
| --- | --- |
| 可编辑 LineEdit | 是，涵盖年度表名称、库存保留数字、配置文本与另存名称 |
| 可编辑 TextEdit 及其子类 | 是，文本及多行编辑采用同一语义 |
| SpinBox 内实际聚焦的可编辑 LineEdit | 是；无需让数字窗口注册自己 |
| 只读 LineEdit 或 TextEdit | 否，按可编辑性而非单纯控件类型判断 |
| Button、普通面板、无焦点 | 否 |

`_Process` 先校正左键和中键释放，再检查可编辑焦点；正在编辑时在键盘方向采集前返回。该返回发生在鼠标释放校正之后，不跳过 `_Input`、`_UnhandledInput`、尺寸变化或原鼠标路径中的 ClampPosition 职责。

没有逐键追踪表，所以按键在编辑控件中释放不会残留地图移动状态。按住 D 时进入编辑立即停止；仍按住 D 时退出编辑恢复原连续移动。这保留“镜头使用当前全局键态”的现行模式，不新增必须重新按键的行为。控件拥有编辑焦点时，Ctrl+A、方向键和中文输入使用的 WASD 都落入同一屏蔽，不试图从文字内容识别输入法。

指定引擎专项通过 `SpinBox.GetLineEdit()`、GrabFocus 和公开 Input 事件验证了编辑焦点：实际焦点是可编辑的子 LineEdit，数字输入、方向键及全选沿用同一规则，无须让各数字窗口注册自己。

## 方案比较和 Depth

| 方案 | 评估 |
| --- | --- |
| 所有 GUI 焦点均阻止平移 | 判断简单，但按钮焦点会使地图键盘行为异常停用 |
| 在未处理事件中维护按键按下集合 | 能表达更多输入归属，却新增释放、焦点变化和窗口生命周期状态；目前缺陷不需要这套状态机 |
| 轮询前读取真实编辑焦点 | 推荐；维持现有连续键态与输入类型，最少新增 Interface 知识 |

Depth 体现为所有真实编辑调用方自动共享一项完整输入归属规则。Locality 留在 CameraController 的键盘方向生成处；删除它后各窗口都要保存及恢复相机许可，说明修复有实际 Leverage。已有引擎焦点查询就是依赖输入，无须新增全局事件总线、可配置焦点策略或单一实现的 Adapter。

## 专项用例与验收

扩展 `TestCameraInteraction`，复用真实 Main 和已接入 TestSuite 的异步入口。主路径保持镜头自动处理，输入经 `Input.ParseInputEvent`、`FlushBufferedEvents` 和实际 SceneTree 处理帧分发；名称和数字编辑的零位移、释放焦点与隐藏窗口后的持键恢复，以及按键释放后停止均观察真实处理帧，不直接调用 `_Process` 替代该主路径。其余类型和确定性速度使用受控 0.1 秒处理补充验证。两类检查都断言实际焦点、文本或光标和 Camera2D 位置，不用直接赋值文字替代输入。

- 年度表名称：WASD 能正常编辑，镜头零位移；左右方向键只移动光标；Ctrl+A 和后续输入正常，镜头不动。
- 原料保留数字控件：方向键可编辑光标且不平移；至少验证一项真实数字编辑入口。指定引擎内另外验证实际 SpinBox 子编辑控件的焦点行为。
- 可编辑 TextEdit 阻止平移；只读文本及按钮焦点保持地图方向输入；多窗口间切换焦点、隐藏当前编辑窗口后正确恢复。
- 按住方向键进入编辑、在编辑中释放、仍按住时退出编辑分别观察处理帧，证明没有镜头漂移或残留输入。
- 原 56 像素速度、对角归一化、窗口尺寸往返、鼠标拖动和 UI 截获释放、短按选择、滚轮及摆放回归。
- 中文 IME 组合窗口行为需在有窗口的指定引擎环境实际验收；headless 注入按键只能验证编辑焦点屏蔽，不能冒充操作系统 IME 验收。完整构建、测试、覆盖率及 Windows 导出启动仍按项目规则执行。

分支验证记录保存在 `build/issue136-validation/`。受控 0.1 秒红例在真实名称输入和库存数字光标中分别测得 `(56, 0)` 与 `(-56, 0)`；修复后两处均为 `(0, 0)`。真实 SceneTree 处理帧主路径另记录禁用本修复焦点判断后的红例与恢复判断后的绿例，帧间时长由引擎决定，恢复平移只断言实际方向及发生位移，不用固定秒数替代。对角归一化验收使用已知 `(39.59798, -39.59798)`，允许等距格换算在约 6128 世界像素坐标处产生小于 0.001 世界像素的浮点误差。
