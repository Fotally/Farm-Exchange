# 静态池塘、圆脚底与完整导航

本页履行[地形 Interface](interface-terrain-map.md)。玩法参数仍以[水域方案](../../project/water-terrain-proposal.md)为准。正式实现与本页须一同通过审查和完整验收，文件落盘不代表已经交付。

## 权威几何与素材校准

`shoreline_templates.json` 保存 16 种水角的有理连续折线；全草和全水无局部岸段。分母为 `2^24`，共享边交点精确等于中点，草土替换不改变水域。作者公式及来源记录见[素材来源说明](../../../assets/gameplay/terrain/source_notes.md)。这是正式权威岸线；作者连续 `sin` 曲线用于离线校准，而不是运行时再生成另一份碰撞面。

维护入口 `python tools/Generate-TerrainTemplates.py` 使用 NumPy 与 mpmath 1.3.0 的区间运算。工具在全部模板上认证作者场 `F`，不是对两个采样分辨率作差：

1. 对单位格作有界四叉分解，区间求值证明每盒 `F` 不与 `[.49,.51]` 相交，或 `|∇F|²>1/16`。最深 12 层仍未证明时立即失败；正式证书实际最深 8 层。全水、全陆模板由扰动幅度小于 .5 直接排除零等值线。
2. 双线性场二阶导的非零项绝对值最多 2。三角扰动按乘积求导，使用 `π<22/7` 和 `|sin|,|cos|≤1`，Hessian 最大行和小于 64，因此算子范数至多 64。
3. 固定 `h=1/1024` 的直角三角形网格，场值由周期归约后的 27 阶正弦 Taylor 多项式确定，余项 `3.142^29/29!<2^-54`。π 的固定二进制近似误差小于 `2^-51`，每个周期系数绝对值不超过 6；Horner 中间绝对项和小于 12，有限 IEEE 运算的累计舍入与系数舍入远小于 `10^-9`。顶点值量化到 `2^-40` 后仍使用 `10^-9` 作为明确上界。
4. 三角形上线性插值的值误差至多 `64h²+10^-9<1/16000`；梯度误差至多 `128h+2√2·10^-9/h<1/8+1/100000`，严格小于前项认证的梯度下界 `1/4`。连接真场与分片线性场的同伦在该带内没有临界点；共享边上的场完全相同，交点不移动。因此连通拓扑和端点配对保持，不能凭像素分类猜测对角连接。
5. 沿原场单位梯度流，跨越上述场误差所需距离小于 `1/4000`，给出双向 Hausdorff 界。交点用整数分数求解后量化到 `2^-24`，位移小于 `1/10000000`。折线简化逐点使用整数平方距离比较，阈值 `1/8192`；连续投影和固定两端同时界定反向距离。总校准误差小于 `1/2500` 格，投影至默认倍率后的位移小于一个像素。该界不增加脚底半径，不作为通道 epsilon，也不宽免最终尺寸／面积等硬约束。

运行时仅加载已认证的不可变模板，不运行 Python、不从 PNG 色值反算经营数据。模板更改、量化、候选顺序或预算变化会改变生成语义，须更新生成版本及重跑校准。精确区间和分片线性推导是证据；1080P 实际采样检查仍单独验收。

## 有界候选与硬约束

PCG 整数随机使用固定地形域标记、种子和布局编号，不消费作物、天气或行情序列。参考椭圆轴向由有理单位圆参数 `((1-t²)/(1+t²),2t/(1+t²))` 给出，标签归属通过有理二次式计算；运行时不依赖平台 `Sin`／`Cos` 的末位结果。

每次布局先放近景，接着大、中、其余小。近景参考轴长读取配置，默认中心相对地图中心为 `(+.5,+18)`；之后仍按最终岸线验证范围。普通候选从保护区外四个不重叠分区按实际可用面积加权抽取，再区内随机，不按规则网格排列。

一个完整创建最多 4 次布局，每座最多 256 次候选；每候选枚举的标签只在有限地图内，模板和岸段数也有固定上界。候选只有单一简单闭环、中心严格位于全部有向岸段内侧才接受（星形）。最终岸线的精确 Green 面积、记录主轴上的投影跨度、归一化径向扰动、中心保护完整格、外圈完整格和近景实际距离全部检查。保护距离和池塘间距可以用包含岸线的凸包距离下界认证；下界不足只是拒绝该候选，不能据此声称实际岸线必然违法。

普通候选的轴长分布读取 `WaterCoverage.Target`：将其在允许覆盖区间中的比例，与一次均匀随机数取平均，再映射到各轴允许范围。目标升高会使候选尺寸分布向大尺寸移动，最终面积仍独立按真实岸线硬区间验收；不额外生成多张图挑选接近目标的一张。

候选圆净空外包保持分离并位于内缩地图内，最后验证实际面积区间，再交由原生导航分区。耗尽预算给出最后不能认证的条件，不减少数量、放宽间隔或切换地图。合法参数不承诺每个种子一定能在有限预算内生成；失败不能伪装为无水成功。纯陆地配置由同一创建入口发布完整全陆地，无需加载没有使用的岸线资源。

完整入口在主线程预先加载不可变模板，再由 `Task.Run` 执行纯 CPU 候选及有理几何计算；布局、候选、岸段与精确距离循环检查同一个取消令牌。后台不读取 Godot 资源、不访问 SceneTree、不注册导航区域，不改变随机抽取顺序。生成完成后回到调用方主线程继续组装。正式测试在创建期间等待三次真实物理帧后取消，确认不会发布地图，再创建后续种子验证取消不污染后续创建。

## 原生圆角导航与有限精度

2026-10-13 用户确认采用成熟引擎方案，2026-10-14 进一步确认原生 RDP `1/32` 格保守简化与额外离岸 `1/8` 格。默认圆脚底仍为 0.125 格，数值安全余量仍为 `1/256` 格。全部坐标放大 1024 倍，导航 CellSize 换算为 `1/4096` 基础格。创建时将原岸首点追加到尾部，以 `NavigationServer2D.SimplifyPath` 简化闭环，检查闭环首尾及最少点数，再移除末尾的闭合点。最终外扩合并脚底、数值余量、额外离岸、RDP 容差与一个导航 CellSize 的补偿，总计 `0.285400390625` 格；只调用一次 `Geometry2D.OffsetPolygon(..., Round)`，不先补偿 Round 再做第二次 Round。随后 `NavigationPolygon.AgentRadius=0`，避免引擎再按 Miter 二次退让。地图外框只按脚底与原数值余量内缩，额外离岸不作用于地图边界。

原生 Round 输出仅删除严格相等的连续浮点顶点及与首点相同的闭合尾点；非零边不移动，非连续重复直接拒绝。实际删点时，以 Clipper 双向差集为空认证几何未变。每座池塘在创建期一次性验证最终障碍覆盖原水域，并完整包含未简化原岸按“脚底＋数值余量＋额外离岸”Round 外扩的区域；未通过时明确报告导航简化阶段失败，不减小参数或改用另一条路线算法。认证所需原岸外扩不进入静态分区，最终简化障碍只准备一次并由所有分块共用。权威岸线、建造检查与运行时原岸扫圆保持原实现。

该方案允许收窄可通行空间：同步就绪后的小型实验中，新参数的 0.55 格通道不通、0.58 格通道可通；旧参数的 0.251 不通、0.26 可通仅作为历史基准。真实旧近岸路线点即使脚底仍在陆地，也可被新的导航退让带排除，查询应明确不可达而非投影瞬移。依据、完整性能与通行差异见[原生导航调研](../../research/godot-water-navigation.md)，正式多种子及经营验收另行执行，不能用实验替代。

2026-10-14 道路偏好确认后，连续导航面按既有游戏地块分区：每格矩形边在 `i±0.5`，地图边缘按原脚底与数值余量内缩；通过 `Geometry2D.ClipPolygons` 减去同一最终保守障碍，先将完整裁剪轮廓按既有 `0.1×CellSize` 对齐，再仅移除严格相等的连续顶点及重复闭合尾点，以 `TriangulatePolygon` 生成静态三角面；生成后不再移动顶点。实际去重时认证原生双向差集为空。只有包围盒相交的池塘进入该地块裁剪。拒绝洞环、对齐后不足三个顶点、原生三角化失败和退化面，不自行修洞或按epsilon删面。并非沿旧三角面逐格切割；该被否决方案的小图曾产生12条内部T接缝，证据见[原生导航调研](../../research/godot-water-navigation.md)。

种子12345的地块(70,77)暴露了输入顺序问题：原岸裁剪轮廓两个相邻浮点点对齐后变为同一点；先三角化再对齐使其中一张原本叉积为0.077392578125的有效面塌缩为0。单格原生重放确认先对齐整个轮廓、精确去重再原生三角化后零面积面由1降为0，去重前后双向差集为空。此修复没有改变对齐步长、脚底、离岸余量或地图种子，也没有删除已生成的面。该种子纳入正式多种子回归。

每局拥有一个 NavigationServer2D 地图 RID，按16×16格保存静态面，每块分普通地面/道路两个 region；384地图最多576块、1152个 region。所有块共享相同的一格边界细分，顶点按既有 `0.1×CellSize=1/40960格` 对齐，三角形循环轮换最短边先出现，数值原因见后文。不是第二份可通行格地图：没有格搜索、格连通表、flood fill或另一套寻路。关闭额外边缘自动连接，以完整边的原生合并进入同一地图，由原生 A* 搜索、Funnel 收紧通道，禁用路径再简化并取消默认搜索多边形数量预算。没有自行实现搜索、圆角偏移、三角化或跨块路线拼接。Funnel 不要求工人沿全部岸段逐点行走，也不承诺所有绕湖方向上的全局最短。

创建分帧准备障碍，每8块静态分区让出真实物理帧，SceneTree 保持响应。登记前订阅本地图 `MapChanged`，记住地图与所有本次变更 region 的旧迭代；只在地图及这些 region 已切换新迭代且仍归属本地图后完成。固定引擎 [`NavMap2D::sync`](https://github.com/godotengine/godot/blob/ed1daf0bf/modules/navigation_2d/nav_map_2d.cpp) 先同步区域，再取当前区域迭代构建地图，切换活动快照后发出事件；本局地图与各region均明确设置 `UseAsyncIterations=false`。区域在同一正常服务器同步轮中构建，防止普通/道路区域独立异步完成而暂时混入新旧面；地图本身关闭异步并不能替代区域开关。事件内本次区域已就绪时，当前快照包含这些变更，不需要对每个区域各调用一次扫描全图的 owner 查询。注册完成标记避免提前事件，完成、失败和取消均在 `finally` 退订；任务后续处理异步调度，不在引擎事件回调中直接开始整图校验。没有固定帧数或 MapForceUpdate。

两个组都登记有效 NavigationPolygon，允许其中一个为0面。固定版本 [`NavRegion2D`](https://github.com/godotengine/godot/blob/ed1daf0bf/modules/navigation_2d/nav_region_2d.cpp#L90-L105) 对设置空多边形也请求新迭代；构建后 `_sync_iteration` 无条件递增 region iteration（同文件257–273行），不按面数跳过。因此初始空道路组与最后道路拆除仍须等待本轮区域迭代，不把空组的旧0状态当作已完成，也不忽略实际非空变更。

真实全图回归曾在“清空后复建跨块道路”时出现原生完整边冲突警告，虽最终路线完整也不能通过。阶段日志排除取消释放：警告发生在复建等待期间；固定源码显示异步region可分轮完成，地图会采集当轮各自的活动版本。只加入上述官方region同步开关，不改几何、CellSize或余量。`TestRoadNavigation` 通过官方 `OS.AddLogger` 局部、线程安全地捕获该原生警告并要求为0，不屏蔽原警告。真实当轮验证及完整性能记录见[#110完成记录](https://github.com/Fotally/Farm-Exchange/issues/110)。

初次纯陆地无道路仍由同一创建入口立即返回，不调用原生服务器、不需要 SceneTree；首条道路经 `UpdateRoadsAsync` 建立同一连续原生网格，正常同步及全部工作中心认证后才就绪。随后求路不能再按 IsAllLand 直接返回直线。最后道路拆除保留已创建网格、全部归为普通成本。

道路 `travel_cost=1`，普通地面为2，五材质相同，不改每秒3格速度。土地提交后传入完整稳定只读空间快照，导航只派生道路锚点集合；集合无变化立即完成。实际变化以道路锚点对称差定位受影响块，只把不变静态面重新归入两个 polygon，等待真实新迭代，不重新裁岸或烘焙。旧 polygon 保留至本次等待结束后释放。正在领取的 LandPath 不变，FarmGame 的道路版本及唯一准备Task负责合并分帧期间连续建拆；最新版本就绪前宿主停止完整经营tick，后续领取使用新道路。原生成本只是尽量偏好道路，固定引擎区域启发式及 Funnel 不保证所有加权距离的全局最优。

全图无可行走面、中心保护区不覆盖或完整边认证失败明确拒绝。外部令牌与地图内部生命周期令牌共同中断分帧及正常同步等待；Dispose先标记已释放并取消内部令牌，事件回调先检查已释放状态，不在释放RID后继续查询服务器。失败或取消时结束该地图，不回退旧图或直线。正式实现不再调用异步烘焙，因此没有仍持有资源的烘焙回调需要等待。

路径非空不代表到达。查询核对返回首尾与目标差异，仅容许一个导航 CellSize 内的数值舍入；结果始终拼回原始 double 起终点，并用现成 `Geometry2D.GetClosestPointsBetweenSegments` 对全部段和原始岸线核验圆净空。真实请求起终点先检查地图范围及圆净空，再通过下述 Clipper 操作判断水域内部。中间点保留地图范围检查和逐段完整扫圆：连续路径从已确认陆地起点进入水域必穿岸，扫圆会拒绝，不重复执行逐点内外分类。提前排除远处池塘使用已按脚底半径扩张的凸包外包，再按整格向外取整并加一格，不使用原始岸线包围盒，以免漏掉段本身在岸外但脚底触水的情况。不能把引擎部分路线交给工人，也不能通过投影瞬移；安全检查失败给出明确异常，没有替代寻路算法。

这些操作是有限精度运行校验，尚不构成全地图浮点误差上限证明。固定余量不保证任何微小宽度通道保留；真实岸线、多种子和连续取消的验证通过正式入口分别执行。

原岸段按一格空间桶建立一次性只读索引。查询先取线段 AABB 并向四边扩张圆半径，闭边界同时访问邻桶；稳定岸段编号去重后仍使用原 `Geometry2D` 几何核验。端点的水域内部判定保持，因此完全落水但没有穿岸的段也会被拒绝。该做法遵循[业界空间划分证据](../../research/water-navigation-game-practices.md)，只减少候选岸段，不修改原生路线、权威岸线、脚底半径或安全余量。

发布前对全部真实合法农田与加工场地工作中心逐个验证原生连通性。临时并查集按引擎的 `float cellSize×mergeRasterizerCellScale` 和向下取整端点键，匹配完整无向边；先配对每个区域内部边，再让未配对边参与跨区域连接，只有共点不连接，同边超过两面明确拒绝。所有最终未配对完整边都必须属于同一最终障碍或内缩地图边界：原生点到线段检查两端与同一边界段的距离不超过既有 NavigationCellSize，超出即报告内部未配对边，不修补T接缝。该门限属于有限精度审计，不放宽脚底或离岸规则。

一格临时空间桶仅加速边界段候选与调用引擎 `PointIsInsideTriangle` 判断工作中心是否位于保护区中心同一分量；按三角形正反朝向各调用一次覆盖相同闭边界，退化面不作为工作中心覆盖。不生成路线、不改网格，不把不含业务工作中心的小碎片误判为必须连通。边键、并查集、面与工作中心桶在检查后丢弃，取消令牌和分帧检查保持准备界面可响应。日志记录实际三角面、边界审计数量及时间；全图性能与内存必须通过正式默认地图测量，不能外推小图结果。

## 原生射线误分类的诊断与修复

固定引擎 `ed1daf0bf` 的 [`Geometry2D::is_point_in_polygon`](https://github.com/godotengine/godot/blob/ed1daf0bf/core/math/geometry_2d.h) 从查询点向包围盒外固定方向发射线，对每条边调用 `segment_intersects_segment` 并累计交点奇偶。真实种子 0 路线中，两点 `(94.65243,181.52794)` 与 `(94.64864,181.52873)` 相距约 0.00387 格、距原岸线分别约 2.28645 和 2.28834 格，却被分别判为外部和内部。

重放真实岸线后，单独平移、缩放或先平移再缩放都不能消除错误。按原生谓词最小化后，从 5,064 点减少至 6 点仍稳定复现；不是必须依赖密集轮廓或大坐标的缺陷。逐边原生交点记录确认：第二点的射线被相邻两条边各计数一次，两者返回同一个共享顶点 `(98325.203125,187865.203125)`（放大 1024 倍坐标）；加上另一侧交点共三次，错误翻成“内部”。第一点只有两次交点。交点与查询点不近似相等，因此不是查询点贴岸分支。相同输入的原生 Clipper 交集均确认两点位于水外。

修复统一采用已有 `Geometry2D.IntersectPolygons`，不加入备用谓词或自写射线算法。步骤先确认中心到所有可能相近的岸段距离不少于真实圆半径 `r`，再以中心构造半边长 `r/2` 的小方框。该框的角距中心为 `r/√2<r`，严格包含在圆脚底内部；已通过净空检查时，它不可能跨岸。因此该框与池塘有交集等价于中心位于池塘内，方框仅用于内外分类，不替换圆脚底或改动半径。Clipper 只作用于真实请求起终点及其附近池塘，路线各段仍完整扫圆；没有增加许可误差。

秒级诊断工件保存在 `build/issue110-recovery/`：`clearance-repro.json` 记录完整真实输入，`clearance-minimal.json` 保存六点案例，`clearance-rays.json` 保存实际引擎逐边交点；`clearance_clipper_regression.gd` 检查两个旧误报点、水内中心、贴岸、方框跨岸前置拒绝以及原生三角形闭边界。正式公开入口回归仍使用 `TestTerrainMap` 的真实种子 0 远端路径及连续取消，不能以独立几何探针代替完整导航验证。

## 长细三角形端点投影与等价索引

另一处真实失败发生于种子 0 连续位置 `(185,210.95731608072916)`：实际距岸约 2.05 格，原生 `MapGetClosestPoint` 返回原点，但 `QueryPath` 把首点移动了约 0.004367 格，超过原有 `1/4096` 格端点门限。相同地图切换 Funnel、EdgeCentered、None 都保持相同首点偏移，问题在进入搜索前的端点投影，而非后处理或通路断开。

固定引擎 [`Triangle2::get_closest_point_to`](https://github.com/godotengine/godot/blob/ed1daf0bf/modules/navigation_2d/triangle2.cpp) 以索引 0 为基点构造两边，并计算 `det=a*c-b*b` 及相关 Gram 表达式。最小化到包含该点的一个长细三角形后，点仍被原生叉积包含检查认定在内部，投影却偏移 3,170.396 个放大单位；平移和二进制等比缩放都未改变结果。这个三角形的两条长边约 19,000 单位，短边仅约 16 单位；原始起始索引使两个大而接近的乘积相减，单精度 Gram 值约 `3.436×10^10`，叉积平方约 `2.385×10^10`。仅循环轮换成 `[1,2,0]` 或 `[2,0,1]`，实际原生查询偏移均恢复为零。

正式处理在原生三角化和既有 snap 之后进行：按 `Vector2.DistanceSquaredTo` 的原生单精度结果依次比较三边，严格较短才更新、等长保留先遇到的边；仅将原索引循环轮换为最短边先出现。顶点坐标、面朝向、三条有向边及多边形顺序均不变，不重烘焙、不增加通路，不改脚底半径、安全余量、端点门限、A* 或 Funnel，也没有失败替代查询。全图实验仅轮换 147,501 个面的起始索引，前后坐标与保持朝向的面校验和、有向边校验和完全一致；捕获点、近景自身三格接续、100 次取消和八处远端均保持原端点精度门限通过。正式回归从 `FindLandPath` 重新验证捕获坐标和正常连续取样，而非仅测试排列函数。

这是一项针对固定引擎数值实现的等价输入修正，不能宣称消除了所有浮点误差。[David Eberly 的原始点到三角形实现说明](https://github.com/davideberly/GeometricTools/blob/master/GTE/Mathematics/DistPointTriangle.h)也明确区分可能受舍入影响的 Gram 实现与更稳健的浮点实现；这里没有自行移植或替换寻路。证据保存在 `continuation-repro.json`、`continuation-triangles-minimal.json`、`continuation-triangles-result.json` 与 `continuation-rotation-result.json`。

## 静态有理几何与运行位置

`TerrainPoint`／`TerrainNumber` 只服务一次性静态生成和硬约束验证。`LandPosition` 是有限 double 基础格坐标，`LandPath` 按 double 累计最大轴差长度；不再将插值点编码成分母不断增长的 BigInteger 有理数。连续取消保留原 double 点，Vector2 只在引擎和显示转换使用。

单秒与批量从同一路线的整数累计移动距离采样，整趟一次向上取整，终点截断返回原始真实目标。暂停、倍率和到达秒不作业由原经营推进维护。正式测试 `TestTerrainMap.RunChecks(SceneTree)` 串行创建种子0、1、110、12345与重复0，每次输出完整创建时间，检查全部边缘和保护格、八处远端合法工作中心、真实绕行、岸格干地及100次原生取消改派；重复0比较逐格地形、最终面积及真实路线。单独运行其场景时可传 `-- --terrain-seed=12345` 定向执行该种子的完整创建与路线检查，正常失败退出1，不影响TestSuite默认种子表。`TestLandPath` 检查无道路纯陆地100次接续及距离临界点。`TestRoadNavigation.RunChecksAsync` 通过真实土地建拆快照验证纯陆地首路、跨块U形道路偏好、断路拆路、同成本材质、既有不可变路线、连续取消、原生等待时直接Dispose/外部取消及首次分帧Dispose。单秒与批量、三工人领取、快速连续版本由经营及表现验收覆盖；真实当轮结果见[#110完成记录](https://github.com/Fotally/Farm-Exchange/issues/110)。
