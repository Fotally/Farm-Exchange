# 年度日期事件与预备安排

删除共享表先检查编号存在，再遍历绑定快照，仅移除 `PlanId` 为该表编号的绑定，并调用 `FarmingSystem.SetSowingEnabled(index, true)` 恢复当前品种的播种许可，最后移除表配置。移除绑定同时清除其计划执行凭据、完成缓存、预备目标及日期事件；不调用 `RestartCrop` 或 `TakeManualControl`，因此当前作物、待水或生长阶段、剩余时长和水分保持。原有工人凭据按播种许可变化失效并重验，后续仍通过正常工人及季节检查开始当前品种的新轮。手动预备绑定的 `PlanId` 为空，其他表引用也不受影响。未知编号在任何写入前返回正常拒绝，表编号高水位 `_nextId` 不下降。

本文履行[计划 Module Interface](interface-cultivation-plan-book.md)。`CultivationPlanBook` 唯一保存共享表的名称、执行方式、年度条、条编号高水位，以及各锚点的表引用、当前执行条、逐条年度执行凭据、完成时间缓存、预备目标与下一日期事件。农田的作物、水分、阶段和精确剩余单位仍由 `FarmingSystem` 唯一保存。

年度长度为 `336 × GameTimeUnits.PerDay`。定位时只检查相关上一年、本年和下一年的条，按绝对比例单位判断半开区间 `[起点, 起点 + 完整周期)`；上一年冬条可以覆盖本年春初。每田以 `(条编号, 所属年度)` 集合记录全部实际已播条，定位时排除该集合中的候选，不能只记录最近一条。共享编辑和再次应用同表保留集合，所以执行其他条后再把较早的已执行条拖到本年未来日期，也不会重复执行。下一年度的同编号条是新的一轮。跨年清理早于上一年度的凭据，保留冬春所需的两年范围；这不是作物历史或待补种队列。

凭据只在农田实际为 Seeded 或 Growing、且存在本田已启用计划条时写入。`RecordSownCrops` 在工人相位结束后、日历换季清除前遍历引用田，只登记凭据；因此春末实际 Sow 后同一步进入夏季被清除，也不会漏掉该条。它与 `Synchronize` 共用私有登记逻辑，后者保留单 Module 测试直接推进时的相同约定，并在处理到期中断事件前记录实际播种。同步发现已启用条有执行凭据而当前农田为空时，按已生效日期更新中断安排。初次应用保留的外来当前轮没有已启用条，不会被虚认为某计划条已播种。手动接管移除本田绑定，亦清除其执行凭据。过期条仍直接跳过。

`ValidateEntries` 唯一检查完整条目排程，不检查名称或模式，使首次未命名草稿仍可拖放编辑。条编号、作物与日期合法后，按 `GameCalendar.GetDate` 换算条起点及周期内日期的季节，与 `CropCatalog` 的适宜季节比较。第一天不适宜则返回包含作物名称的中文拒绝原因；适季开始后才进入禁生季节则只记录风险编号，不改变固定条长或自动移动草稿。随后按年度起点排序，相邻条包含年度首尾的一对，覆盖区间不能重叠，异种条须至少一个游戏日空白，同种可首尾相接。UI 悬停和落位通过 `CheckCultivationEntries` 复用该检查；完整 `Validate` 先检查名称、模式，再调用该检查，共享表创建及更新仍要求有效名称，不另行复制季节或冲突规则。

每表 `Plan.NextEntryId` 保存生命周期编号高水位，通过独立只读快照提供给草稿编辑器。成功更新构造替换配置时保留旧高水位，并纳入新条最大编号加一；空表的最大编号按 0 处理，因此首次空表从 1 开始，已有表删空仍保留旧值。更新前检查新请求中低于旧高水位的编号是否仍存在于当前表，存在才表示移动或编辑原条，否则拒绝历史编号复用。检查全部通过后才替换配置并重新定位引用田；失败不改变高水位、条集合、农田或凭据。窗口的草稿计数只在成功新增后前进，不因删条退回；保存空表并重新载入后仍从持久快照继续。农田 `Executed` 集合保持原行为，新编号代表独立轮次，移动旧编号仍不能在本年重复执行。

初次应用和共享编辑不改田中当前轮。生长中直接读取 `FarmingSystem.GetExpectedRoundEndTimeUnits` 定位预计结束位置，不复制生长或季节结局状态。正常结束按实际经营 tick 对齐；首个禁生季边界可能促熟或清理，均意味着本轮结束；适季边界不截短。待水等待实际开始生长。编辑、供水使结束日期首次确定、当前轮清除或完成时重算相关缓存，查询和每日换日不重算。

缓存的下一个条起点或终点到期时，按实际日期定位，并推进下一事件。空田启用仍有效条或休耕；进行中的当前轮遇到空白或下一同种条时，两种模式均保持旧轮及其 `Active` 凭据，只关闭新播种。旧轮不能归入新条编号，连续 n 条按各条完整周期分别执行 n 轮。只有下一不同作物条实际起点到达，立即模式才中断旧轮、保留水分并切换；预备模式继续供水和生长。不能用休耕或同种接续绕过禁生清理。

正常收获通知只关闭本田播种、按实际结束日期定位目标并标记完成；工人相位仍读取步进开始的日历，不能提前执行按下一时刻定位的计划条。待原有日历相位完成，再由 `Synchronize` 按已生效的实际结束位置重新定位并启用有效条或休耕。无收成禁生清理也按实际结束位置接续。不能仅检查旧预备条未过期：若实际结束早于原预测，仍可能存在比旧目标更早且有效的条。未来目标持续保存在缓存中。本条只允许一次播种，收获后的工人相位也不能复种；`SowingEnabled` 仅阻止空田播种，已有待水作物仍可以获得工人供水。空田错过条终点则跳过。

手动预备以同一绑定记录保存目标作物和无共享表的状态；收获或越季中断后接续目标并移除手动预备记录，恢复原有手动自动复种。手动立即改种则直接移除绑定并强制重启选种，即使同种也执行当前轮丢弃。拆田清理引用；满地图测试夹具清理全部引用，不删除共享配置。

`CheckDraftSchedule` 通过真实 `FarmGame.CheckCultivationEntries` 验证无名称草稿可编辑，全部既有条目约束及跨季风险保持，查询不推进经营，未命名创建及更新仍失败。`CheckEntryIdentityLifetime` 实际完成旧萝卜后移动同编号，验证本年不重播；保存空表后保留下一编号，拒绝复用旧编号且失败零修改，以新编号在本年第 10 天接续并实际收获。另检查独立表、首次空表、非连续编号、失败更新不消费编号及旧快照不变。

验证通过 `TestCultivationPlanBook` 覆盖年度首尾冲突、风险、共享编辑、应用保留、不同执行方式、待水完成日期、同条不复种、冬春重复、批量原子检查、手动接管、暂停及换季入库连接。`CheckStartSeasonValidation` 检查七种作物全部四季起点、冬季玉米预检及创建/编辑失败零修改、春末小麦及夏末玉米合法风险、冬春小麦适季连续。`CheckHarvestPlanDateActivation` 通过真实 FarmGame 路径验证春末成熟时目标不会借旧春季执行 Sow：预备模式中合法的春末风险小麦在本轮结束进入夏季后不耗播种动作；夏适宜玉米在两种模式下均在日期生效后的工人相位才播种，原收成仅入库一次。`CheckRescueWithinPlanBar` 验证禁生边界促熟发生在原条内部时仍将该条视为已执行，保持休耕并缓存下一年度目标。`CheckExecutedEntriesAfterEdit` 真实完成两条后移动较早条、重应用同表，验证本年不重播而下一年两条仍可执行；`CheckPreservedRoundDoesNotConsumeEntry` 验证初次应用保留的手动当前轮不虚记为计划条。`CheckOneRoundAndYearWrap` 同时验证收获通知和日历同步后都保持休耕及未来目标缓存；手动下一轮仍由 `CheckManualAndFacade` 验证原收获相位接续。完整相位顺序见[经营推进](../game-state/farm-game/implementation-tick-order.md)。

`CheckSowBeforeSeasonClearIsConsumed` 使用两种表级模式从累计 4319 秒开始，真实验证春末风险萝卜 Sow 后随换季清除，仍登记执行并更新休耕缓存；同 ID 移到本年秋季再重应用也不会二次播种，翌年秋季恢复正常执行。

回归通过真实 `FarmGame` 公共调用路径验证：`CheckSeasonEndCache` 从累计 11006 秒开始种甘蔗，第 250 天应用萝卜第 249 天、小麦第 260 天的预备表，验证第 252 天秋冬促熟前已缓存仍有效萝卜，实际收获 12 份后正确接续；另验证甘蔗夏秋适季继续生长及秋冬远离成熟时清理不入库。`CheckRestBufferAndConsecutiveRounds` 对两模式分别检查 1 条、3 条连续萝卜：条尾不丢弃未成熟旧轮，每条各收一次，末轮收获后空白不复种且保持下一年缓存。`CheckDifferentCropAfterBuffer` 晚于条起点播种萝卜，验证空白继续成熟，但第 6 天的小麦起点仍分别按立即中断或预备保留执行。
