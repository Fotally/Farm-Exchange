# 固定锚点、公告锁价与报价计算

本实现履行 [MarketQuotes 接口](interface-market-quotes.md)。排期、事件、因素和报价均收在这一模块；商品定义由 [CommodityCatalog](../commodity-catalog/interface-commodity-catalog.md) 提供，日期数学唯一委托 [GameCalendar](../../time/game-calendar/interface-game-calendar.md)。

## 单期状态

市场内部持有十四项初价、当前价、上次价、待生效价和本期供需指数，以及下个固定锚点、最后实际报价日、最近公告的实际报价日和当前持续事件。数组在一局内复用，UI 不接触内部数组。

没有待生效报价时，到达实际报价前一日生成事件和各商品供需，按实际报价日季节计算全部正式待生效价格。若上一期歉收仍持续，则直接保留事件对象，不重新筛选资格；其他情况下按确认概率抽取新事件。报价前的多次推进或读取只使用已经准备好的结果。

到达报价日时，复制当前价为上次价、待生效价为当前价，减少持续期，固定锚点增加十四日。跳过多日时顺序重放每次公告与报价；不会跳过必须作用于旧价的中间期，也不会每个无事件日循环一次。

公告文本由最近一批已锁定因素生成，报价前后使用同一批数据。旧快照包含独立只读集合，后续行情推进不会修改已返回快照。

日志只在已有提交位置观察：`PrepareQuote` 设置公告日期和准备完成标记后递交只读公告查询，由 `MarketLog` 在隔离的观察中构造文字和投影；`AdvanceTo` 完成价格复制及下一锚点更新后递交真实商品快照和本轮因素，再进入下一期。正式因素复用已有纯因子查询，不重复价格公式、取整限幅或随机抽取，不另存日志用行情数组。行情字段、事件描述和文本格式全部留在日志模块；构造器历史回放不传入记录入口。

改期公告追加对应夏庆日或丰收日的原日期、实际日期及方向说明；从已采用的实际报价日期生成，UI 直接读取中文消息，不另算节日锚点。

## 精确报价

先算并限幅原料，再用原料的本期正式新价计算成品成本。公式以 `long` 分子、分母保存精确有理数，避免浮点误差改变半分取整。正数有理候选加半个分母后整除，得到 0.5 分向上；再截入绝对界限和旧价单次限幅交集。当前初价与因素范围下计算不会超过 `long` 容量。

原料分母为 200；成品分母为 `200×B原料`，分子同时包含旧价平均、独立供需事件和对应原料新价的成本项。无额外利润保护、初价恢复或价格缓存。公开涨跌使用正式当前价与上次价计算，公告的成本百分比仅为显示取四位小数，正式计算保留精确有理式。

## 排期与日期

固定锚点始终从经过十四日开始每期增加十四日。每年经过日数模 336 等于 98 的锚点延后一日，等于 182 的锚点提前一日，其余保持原日。下一锚点不从实际报价日推导。所有显示日期和事件季节通过 `GameCalendar.GetDate` 换算。

这两个改期只改变公告和报价的执行日期；不增加倍率、不按间隔补乘，也不生成天气。
