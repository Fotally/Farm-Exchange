# 天气模块 Interface

`scripts/weather/` 使用 `FarmExchange.Weather`。`WeatherSystem` 唯一拥有预排表、当前执行位置及活动矩形，调用方不重建天气规则。现行数据与玩家行为见[地区天气](../../gameplay/world/weather.md)，预排实现见[循环排程](implementation-weather-schedule.md)。

## 类型与状态

- `WeatherKind`：`Sunny`、`Cloudy`、`Rain`，首版互斥。
- `WeatherMode`：`Natural`、`Explicit`，在构造局时确定，不在运行中切换。
- `WeatherRegionSnapshot`：只读值 `Cells: Rect2I`、`Kind: WeatherKind`。矩形使用基础格坐标，右／下边不包含；只返回当前云雨，不包含未来预报或永久分区 ID。
- `WeatherSystem.Mode` 与 `CycleSeconds`：本局模式及当前配置周期经营秒数。
- `ActiveRegions`：只读独立快照缓存；活动状态未变化时必须复用同一对象引用，实际变化时发布新的不可变快照，后续推进、设置、清除不改写已返回对象。拒绝命令及无变化推进保留引用。没有活动区域表示全图晴天；调用方可以据引用变化刷新表现缓存，不能把普通时间推进当作天气变化。

## 调用顺序

`new WeatherSystem(int seed, WeatherRules rules, WeatherMode mode = Natural, uint elapsedSeconds = 0)` 使用独立天气种子与建局时明确选定的已验证配置；执行器不读取全局默认配置。`FarmGame` 是每局组装点：省略 `weatherRules` 时选择正式 `WeatherRules.Default`，开发／测试可传入 `Parse` 返回的合法变体。自然局在构造时一次生成全部周期事件，显式局没有自然事件，但同样使用传入配置的区域数量上限。创建时同步已有经营时刻，零秒新自然局全图晴天；不能消费开局作物或市场已有随机流。空配置明确抛出参数异常。

不可变配置可被多个局共享，但预排、执行位置、活动快照与整田派生缓存由各个 `WeatherSystem` 独立拥有。创建后不能替换配置、重排或热加载；同种子与同配置可复现真实排程。

经营协调在时刻变化后调用 `AdvanceTo(uint elapsedSeconds)`，同步到不早于当前的累计经营秒。允许一次跨越多事件／周期，运行中不抽取随机数。天气同步本身不供水、不推进农田；经营入口按照原相位读取同一天气状态执行生产。倒退时刻及非法模式明确抛出参数异常。

`GetNextEventSeconds(uint now)` 返回严格晚于 `now` 的下一天气生效或结束距离；无事件返回 `uint.MaxValue`。协调入口将它与工人、农田、季节及行情事件一起参与批量推进边界。第一周期不报告尚未存在的前周期尾部结束事件。

## 查询与显式设置

| 成员 | 调用方约定 | 结果 |
| --- | --- | --- |
| `GetWeather(Vector2I cell)` | 基础格在地图内 | 当前互斥天气；越界明确抛出参数异常 |
| `GetFarmWeather(BuildingSpaceSnapshot farm)` | 土地模块真实农田空间快照 | 遍历全部占地，雨＞云＞晴；非农田参数拒绝 |
| `TrySetRegion(Rect2I cells, WeatherKind kind, out string reason)` | 显式局，正宽高且完整在地图内，多云或雨 | 完整检查上限与互斥后一次登记；失败快照与状态零修改 |
| `TryClearRegion(Rect2I cells, out string reason)` | 显式局，矩形与已有活动区完全一致 | 整片清除并恢复默认晴；不存在／部分清除拒绝且零修改 |

整田查询内部按固定几何锚点缓存只读派生结果，命中前仍确认实例类别为农田。同锚点拆除重建保持土地模块定义的固定农田几何，可以复用同一天气结果；缓存不持有实例对象、水分或生产状态。活动快照真正改变后失效：显式设置／清除成功及自然事件／循环状态变化同步清除派生结果；失败修改及无变化推进保留当前结果。

自然局拒绝显式修改，不允许修改预排表。显式区域没有自然到期，推进后保持直到清除；不增加覆盖恢复或区域叠加。成功 `reason` 为空，正常拒绝为中文原因。

## 正式配置与失败

`WeatherRules.Default` 从 `res://assets/gameplay/weather/weather_rules.json` 只加载一次，并经过与测试相同的 `Parse`；所有导出预设明确包含该 JSON。`WeatherRules.Parse(string json)` 是唯一配置验证入口，拒绝未知字段、缺失有效数值、非法权重、日历不一致、逆序区间、地图外尺寸或非法周期；容量检查包含周期末尾候选的最长完整存续，不能只保证周期本身可转换为经营秒。加载／解析失败直接抛出异常，不静默替换默认表或运行补排。

JSON 先反序列化为模块内部描述，完整校验后由私有构造生成 `WeatherRules`。公开属性只有读取入口，外部不能通过无参构造或 `init` 绕过验证，也不能修改已被局采用的规则。配置读取／合法性集中在天气模块，配置选择集中在经营局组装点，执行器只执行传入的合法规则。数据修改需同步现行天气文档与验收。

### 配置字段扩展与规模变更

新增字段时，在 `WeatherRules.cs` 同步内部 `JsonConfiguration` 描述、公开只读属性、私有复制构造与 `Parse` 校验，并让执行器实际使用已验证值。字段合法性与复制关系集中在这个文件，不增加通用映射框架或第二个验证入口。测试同时覆盖新字段的缺失／非法拒绝和合法变体的实际执行效果，不能只证明 JSON 能解析；正式配置文件及玩家规则随生效数值同步维护。

`CycleYears` 与 `MinimumIntervalDays`／`MaximumIntervalDays` 会改变候选数量；持续、尺寸和活动上限也会影响接纳规模。`Parse` 保证数值与规则安全，不保证任意合法配置的建局成本已经验收。实际调整这些参数时，应对照修改前后的自然天气构造耗时与分配，并记录配置、种子、环境与重复样本；方法见[预排规模验收](implementation-weather-schedule.md#预排规模变更的建局验收)。本约定不增加任意容量上限或固定性能阈值。

## 责任划分与验收

天气不拥有农田水分、作物进度、每轮随机产量、库存或动画。农田的天气积分沿用实际消耗的精确时间单位，末秒裁到剩余量；该状态由农田模块维护。世界只读取当前区域和暂停／倍率，农田详情读取同一整田查询。

经营已通过 `GetNextEventSeconds` 在真正天气变化处结束平静区间，而不是每日重建或扫描预排；区间内查询命中整田缓存。供水与生长入口仍明确读取当前权威天气，包括晴天，详见[执行设计](implementation-weather-schedule.md#事件边界与查询职责)。本轮不增加地区通知订阅和受影响建筑登记表。

`tests/unit/weather/TestWeatherSystem.cs` 通过公开 Interface 检查配置、显式失败零修改、快照只读、整田九格优先级、完整两周期事件、接缝持续、多个种子与不同批量同步等价；边界冷／热查询、同锚点农田改建道路与重建、显式变更及自然事件／循环失效均与九格位置查询逐项比对。全局覆盖率由统一测试入口检查 `scripts/weather` 至少 80%。

配置执行回归在同一进程用两份已验证配置运行真实天气系统，核对周期、间隔、持续、尺寸、显式上限、固定种子的类型权重效果、同配置种子复现及局间隔离；不只检查解析结果。`TestWeatherYield` 另从 `FarmGame` 建局传入变体，核对权威查询及跨事件／循环的单秒与批量生产、工人和库存等价。自然与显式天气测试同时保护稳定引用及旧快照不变约定。

天气 JSON 测试变体通过 `System.Text.Json.Nodes` 按字段设置、移除或重命名，每例从原配置独立解析，再用 `ToJsonString` 交给正式 `WeatherRules.Parse`。非法字段在紧凑／缩进输入与输出下均验证拒绝，`null`／空对象保留原始缺失输入；合法经营变体比较两种排版配置的真实事件与区域，再执行一次原有单秒／批量经营检查。测试不依赖字段旁的空格、换行或正式文件的排版。
