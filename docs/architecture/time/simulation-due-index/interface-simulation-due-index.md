# SimulationDueIndex 对外接口

对应 `FarmExchange.Time.SimulationDueIndex`，代码位于 `scripts/time/SimulationDueIndex.cs`。该 Module 只拥有绝对经营秒到业务整数锚点的预约索引；作物、加工、库存和业务结算仍由各自 Module 持有。索引不执行回调，不读取日历实例，不推进经营，不定义业务阶段。

| 成员 | 调用约定 |
| --- | --- |
| `SimulationDueIndex(int capacity, long currentSecond = 0)` | 容量必须为正整数，初始水位非负；新索引的当前秒开放登记。容量独立于物理秒桶数。 |
| `MaxDelaySeconds` | 从统一历法及时间比例导出的一年经营秒数，目前为 17,280；允许恰好一年。 |
| `Count`、`Capacity`、`CurrentSecond` | 只读挂起数量、固定容量和绝对经营秒水位。业务可在提交资源前检查容量。 |
| `Register(long dueSecond, int anchor)` | 目标必须在当前水位至未来一年内，当前秒还必须未封口；成功返回不透明 `Handle`，登记到该秒队尾。锚点只作业务标识，不用于排序。期限非法抛 `ArgumentOutOfRangeException`，满容量抛 `InvalidOperationException`；失败不修改已有预约。 |
| `Cancel(Handle handle)` | 有效凭据立即摘链并释放位置，返回 `true`。默认、重复、已清空、已复用或来自其他索引的凭据返回 `false`。取消后重登按新登记排尾。 |
| `TryGetNext(out long dueSecond)` | 返回最近挂起的绝对到期秒；无预约时返回 `false` 并输出零。查询不封口、不移动水位。 |
| `AdvanceTo(long currentSecond)` | 允许推进至最早挂起预约秒，但不能越过它；空索引可直接跨多年跳时。倒退抛 `ArgumentOutOfRangeException`，越过未消费项抛 `InvalidOperationException`，失败零修改。真正进入新秒才开放登记，同水位调用不重开。 |
| `TryPeekDue(out Handle handle, out int anchor)` | 封闭当前秒登记，再读取本秒队首。即使无到期项也封口；空时返回 `false`、默认句柄及零锚点。重复读取仍为同一预约，读取本身不释放容量。 |
| `Clear()` | 清除全部预约并复用数组，使旧凭据失效。保留当前水位及封口状态，不作为新局回到零秒的接口；新局创建新索引。 |

## 消费与业务提交

同一经营秒先提交允许的秒首输入，再推进索引水位至执行秒。首次读取到期项后，本队列该秒不再接受登记；不能以重复 `AdvanceTo` 或 `Clear` 重新开放该秒。

消费顺序固定为“读取队首 → 业务结算成功 → `Cancel` 移除预约”。业务抛出容量等异常时，当前项和后续项仍在索引中；已经成功提交并取消的前项不回滚。异常向上传播，索引不捕获业务异常、不自动重试、不创建失败队列。调用方不得在业务提交前取消该项，也不得越过尚未处理的到期秒。

首批生产共用一个产出索引，农田成熟和加工完工同秒按登记顺序结算。全部产出及原有换季促熟完成后，再按经营阶段领取原料；FIFO 不把领取插进单设施完工之后。若其他业务以后需要不同阶段，应独立组装同一种索引；本 Module 不提供阶段回调或事件总线。

## 精度、窗口与身份

预约时刻使用非负 `long` 绝对经营秒。当前日历的 `uint` 上限不限制预约整数表示，晚于日历末端的时刻仍可在合法一年窗口内登记；实际经营是否可继续由日历与经营入口判断。先检查合法期限，再计算物理桶，不把超窗口日期取模混入当前轮。

生产采用完成后的日历秒作为执行秒。目标精度由生产 Module 保存，例如精确 358 与 361 单位均在第 52 个经营 tick 到期，索引只保留同秒登记顺序，不按精确单位重排。秒首降雨、本秒工人动作和步间命令的计时偏移也由生产 Module 封装；索引不从到期秒反推精确剩余量。时间比例见 [GameTimeUnits](../game-time-units/interface-game-time-units.md)，日历范围见 [GameCalendar](../game-calendar/interface-game-calendar.md)。

句柄封装所属索引、记录位置和代次。位置取消后立即进入空闲链；复用时递增代次。清空保留每个位置的代次，下次分配仍递增，因此旧句柄不能命中新预约。代次使用 `ulong`，达到表示上限时登记显式溢出失败，不发生绕回。

## 固定存储与复杂度

Implementation 使用 32,768 个秒桶，每桶头尾各一个 `int`；512 个 `ulong` 叶位图和 8 个 `ulong` 摘要位图，无根位图。双向链使用事件数组位置；登记尾部追加、取消真实摘链，均为 O(1)，同秒 K 项读取及移除的容器工作为 O(K)。最近查询检查当前叶及至多两次各 8 个摘要字的有界范围，不逐秒拨轮、不扫描全部事件、不排序。`Clear` 为 O(容量＋固定桶数)，不在逐秒热路径调用。

固定索引数组有效载荷为 266,304 字节。每条事件的字段包含 `long` 秒、`ulong` 代次及三个 `int`（锚点、前后索引），64 位 .NET 的数组元素步长为 32 字节，容量 16,384 时事件池有效载荷为 524,288 字节，合计 790,592 字节；这些数值不包括对象头及业务自行保存的句柄。句柄包含一个索引引用、一个 `int` 位置及一个 `ulong` 代次，64 位布局为 24 字节。

2026-10-16 的独立 .NET 10 Release 验证中，容量 16,384 的索引构造实际分配 790,792 字节（包含索引对象及五个数组对象）；预热后 10,000 次推进、登记、最近查询、到期读取及取消合计分配零字节。该验证仅链接正式索引、日历及其契约测试，以最小 Godot 输出桩运行，证据程序位于本地 `build/issue65-index-validation/`。这不是完整生产集成或全游戏零 GC 结论。

## 契约测试

`tests/unit/time/TestSimulationDueIndex.cs` 的 `RunChecks` 已接入根测试套件；独立场景为 `tests/unit/time/test_simulation_due_index.tscn`。覆盖同秒 FIFO、头中尾取消、最早项取消、重登排尾、位置代次、跨索引句柄、清空失效、业务异常保留、当前秒封口、失败零修改、精确一年、51/52 秒、358/361 精确单位同秒、物理环绕、空轮长跳及 `uint` 日历末端。随机对照使用独立列表按绝对秒及登记序号排序，跨多次物理环周逐项比较最近秒、锚点及凭据。
