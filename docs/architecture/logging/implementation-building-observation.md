# 建造、拆除与原料底线观察

本文履行[日志 Interface](interface-logging.md)，字段和事件含义以 [schema v1](../../project/runtime-log-schema-v1.md) 为准，关联 #128。`GameplayLog` 拥有三个命令的原请求投影和前后观察；设施、钱包及底线仍由原经营模块拥有。

## 实际提交位置

`TryPlace`、`RemoveBuilding`、`SetRawReserve` 在验证和修改业务前开始观察，保留原输入及默认 `Player` 或显式 `Scenario` 来源。非法来源在日志和业务提交前抛出，关闭日志也相同。`BuildFarm`、`BuildProcessor` 透传同一来源并复用一次 `TryPlace`，不会额外产生包装命令。只读 `CheckPlacement` 不记录命令或建造结果。

建造沿原顺序完成实际扣费、设施登记和新建加工场地时的全场领取，再结束观察。`ChargedCents` 直接消费 `PlacementResult`，失败为零；成功从已创建实例取得锚点，失败的候选没有创建，锚点为 null。原类型和作物枚举值保留；道路的原作物参数仍在收到命令中，但领域结果没有作物字段。

拆除观察在提交前读取输入子格对应的真实设施锚点、类型和作物；正式删除后不再反查已经消失的实例。成功和拒绝均记录实际资金前后，扣费恒为零，不伪造退款。原返回值是中文原因或 null，记录入口不根据中文生成新的失败码。越界或空地没有可解析的设施，锚点、类型和作物为 null。

建拆只记录资金总额、可用额和冻结额的前后值，不重复记录库存流量。暂停中新建加工场地依然触发原有全场领取，实际原料投入由生产观察累计；拆除不返还已投入原料。日志不控制、重跑或补做放置判断。

## 底线与观察生命周期

原料底线请求保存作物和原始份数，负数保持原值。合法作物前后值来自 `GetRawReserve`，非法作物不调用该查询，两值均为 null。`RawReserveFailure` 直接决定成功或拒绝和稳定失败码；中文原因只解释该枚举，不参与业务判断。修改底线自身不触发领取，不改变公共库存或已投入原料。

`BuildingLogOperation` 与 `RawReserveLogOperation` 只保存本次原输入和前观察，复用 `CommandObservation` 的命令身份、收到/结束配对、异常关联和一次终结。业务执行权与异常传播仍属于经营入口；投影和输出故障沿既有日志隔离处理。完成后再次完成或报错不补写，局结束后不创建新观察。

## 验证

`TestBuildingLogging` 经公开经营入口验证：预览无提交日志、任意锚点建造/子格整座拆除、部分越界/负坐标/非法建筑/非法作物、道路原参数、冻结与耗尽资金拒绝、拆除不退款、暂停新建全场领取、底线成功/拒绝/非法作物、非法来源零修改，以及正常、关闭、未接入和输出故障时经营等价。独立公开观察验证异常关联、一次终结及结束后关闭；没有为制造业务异常新增注入开关。执行状态以主任务统一编译、测试与导出验收记录为准。
