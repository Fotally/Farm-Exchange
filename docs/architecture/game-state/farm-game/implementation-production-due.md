# 生产精确目标与到期索引

履行 [FarmGame Interface](interface-farm-game.md)、[FarmingSystem Interface](../../farming/farming-system/interface-farming-system.md) 与 [ProcessingSystem Interface](../../processing/processing-system/interface-processing-system.md)，对应 #65。底层桶、位图、记录容量与句柄契约见 [SimulationDueIndex](../../time/simulation-due-index/interface-simulation-due-index.md)。

## 状态与容量

FarmGame 组装一个容量 16,384 的生产到期索引，农田成熟和加工完工共用；384×384 地图上生产设施均占3×3，每设施最多一条预约，所以实际生产预约不超过该容量。道路不登记生产预约。容量与32,768秒桶数独立，不把本局生产容量当成通用工具的所有业务上限。

农田与加工 Module 分别唯一持有每轮／批的 long 精确目标与不透明句柄，以及 Module 的当前读取秒。索引只保存执行秒与锚点，FarmGame 按真实占地类别分派，不复制目标、批量、作物或天气状态。工人轮次凭据继续只用于原工作身份，不作为成熟预约句柄。

每次开始生长或实际开批，先登记目标秒；登记失败不改变播种、水分、随机抽取、批次或库存。加工在确认可领取后登记，再调用原库存原子领取，整个操作内没有外部命令插入。取消真实摘链；改种、同种重启、拆除、禁生清理、收获／促熟和清空都撤销旧预约，关闭未来播种许可保留当前生长。清局使所有旧句柄失效。

## 精度与经营相位

精确目标为 `起点秒×7＋完整周期单位`，预约执行秒为 `ceil(精确目标/7)`。剩余快照只读计算 `max(0, 精确目标−当前生产秒×7)`，不从取整执行秒反推剩余量。正常目标可大于 uint 日历终点，保持终点附近仍能开工的行为；实际推进仍由 FarmGame 在业务相位前检查 uint 容量，越界请求零推进。

若本秒开始日历为 t，完整时长 U，D＝ceil(U/7)：

| 开工来源 | Module 起点秒 | 完成后日历秒 |
| --- | --- | --- |
| 秒首降雨供水 | t | t＋D |
| 本秒工人浇水／湿田播种 | t＋1 | t＋1＋D |
| 本秒产出后领取原料 | t＋1 | t＋1＋D |
| 两个完整经营步之间的建造命令开批 | t | t＋D |

事件秒先按原流程降雨，再把两个 Module 及索引时钟同步到 E＝t＋1。开始 Peek 后封闭当前秒登记。每次 Peek 只读队首，农田或加工通过容量检查并完成本轮后取消自身句柄，FarmGame 紧邻提交库存、日志、表现和计划通知；然后再读取下一项。正常产出严格按目标桶的登记 FIFO 混合处理，取消后重登排到尾部，不按锚点或类型排序。正常产出全部完成，再按原换季相位促熟，之后全场空闲加工按原锚点顺序领取，最后工人、日历、计划和订单。

FarmGame 的最近事件查询直接读取索引；平静段只同步两个 Module 的当前秒和索引水位，不逐生产设施减时。空闲领取判断、降雨供水、工人寻找、计划和表现扫描仍保留，不承诺解决 #66 的全部长帧。

## 天气积分段

新田显式接收权威整田天气。每轮开始生长时锁定一次随机基础量，保存积分段的开始精确单位；此前积分为零。自然天气活动快照实际变化、显式设置或清除成功后，FarmGame 读取各田真实九格判定并调用 `SetWeather`。天气相同不改字段；变化时先结清旧段，再保存新段的天气与起点。

段末只计算至 `min(当前生产秒×7, 精确成熟目标)`；成熟和促熟在局部变量中加入最后一段、算实际产量，检查原料容量后才终结本轮。萝卜1440单位最后一秒只计5单位，促熟只平均已生长部分。平静推进及未到期普通秒不逐田写天气积分，快照查询不结清积分或重抽随机量。农田保存的是当前积分段，不拥有第二份天气区域或预排表。

## 容量异常与显式续读

某项原料／成品容量不足时，原异常传播；当前失败项和后续项仍在队列，之前真实入库项不回滚、不重复入库。失败项的精确目标、轮次、水分、锁定量、随机基础量及积分不修改。同一 E 调用完成方法的前后快照相同。

此时生产时钟和索引已到 E，但日历尚未提交，失败设施剩余显示0，表示已经到期而尚未成功入库；不冻结旧显示剩余量，不倒退水位。FarmGame 只保留该产出相位已开始的标记、已经提交的产出总数和真实结果。调用方明确调整资源并再次调用 AdvanceTick／AdvanceTicks 时，在同一 E 继续 Peek；不重跑降雨、不清除本次成功结果、不重复积分。换季促熟失败也保留当前轮并在同 E 重验，已成功田已清轮，不会再入库。产出阶段完成后即清除续读标记，后续相位的异常继续原传播行为，不引入通用阶段重试。

容器与经营均不自动重试、丢弃失败项、追加溢出队列或延后应结算的秒。完整检查点仍只在整个经营秒完成后发布。

## 验证范围

- `TestProductionState` 保留511/504/497严格促熟边界、剩余精确量、湿田开工、复种启停及只读预测；夹具改为真实共享绝对时钟，不再让同一 Module 的各田分别走不同时间。
- `TestWeatherYield` 保留七作物系数、末秒5单位、等待不抽取、重复供水、显式天气及自然／显式跨年度逐秒与批量等价。
- `TestProductionDueIntegration` 直接组合真实农田、加工、库存和共享索引，检查混合 FIFO、头成功／中失败／尾保留、释放容量同 E 续读、天气切段与失败不重抽、促熟失败、开工预约容量失败资源零修改、取消与 uint 附近目标；通过真实 FarmGame 逆锚点建坊验证同秒结果 FIFO。
- 同一测试的 `CheckGameHarvestOverflowContinuation` 让三名真实工人在降雨下同秒播种，通过正常经营推进到三田共同成熟。无溢出同种子对照局给出真实收成，受测局初始原料仅留首田容量；首田入库后中项溢出，尾田保留。再次请求仍溢出时核对失败轮次、水分、工人、库存、金币和未提交日历保持，首田不会因重跑降雨重新得水；正式出售释放容量后 `AdvanceTick` 在同秒完成，完整收成和表现顺序与对照相同，下一秒不重复入库。
- `CheckGameProductOverflowContinuation` 通过真实建造、买入和第1秒领取启动三批九份加工，第27秒中项成品溢出。`AdvanceTicks` 保留第1秒完整检查点和已完成至第26秒的时间，不发布失败秒检查点；首项已入库，当前／尾项锁量保留。正式出售18份后显式批量续推，完成秒汇总包含此前成功的九份但库存只补后两批，随后四秒平静尾段清除旧表现。异常前后跨单秒与批量入口调用，均检查失败项不丢失、结果不重复和旧只读快照保持。
- `TestBatchProcessing` 在到期生产时钟下比较容量失败前后快照，剩余为0且锁量保持；释放容量后只完成一次。原半日26秒、末批完整周期、底线冻结与实际批量守恒断言保留。
- 原 `TestBatchedSimulation`、工人、耕作与日志测试继续验证随机切段、检查点、经营相位、原工作身份及诊断。

上述 FarmGame 边界夹具复用已有内部建局构造的可选 `initialStock`：开局设施建立后、日志绑定前按库存合法性规则复制初始数量，不保留调用方字典，不提前让开局加工领取。正式同步／异步建局省略此参数；测试不反射访问私有字段，不提供运行中资源改写。该准备仅使 int 库存容量边界可在短小夹具中到达，异常触发、释放容量及续推均走真实经营入口。测试仍由 `TestFarmGame.RunChecks` 纳入独立经营场景和完整 `TestSuite`。

性能测试读取真实 Module 与索引，分别记录稀疏／集中到期访问量、耗时及分配；满图50 tick、1080P图形性能、逐模块覆盖率及导出启动由总工程师统一验收，结果不在实现文档预写为通过。
