# FarmGame 的经营步进顺序

对应[FarmGame 对外接口](interface-farm-game.md)的 AdvanceTick。`FarmGame` 只协调推进相位；农田及其目标有效性由 `FarmingSystem`、加工状态由 `ProcessingSystem`、三名工人的位置/任务/共享轮转与认领由 `WorkerScheduler`、分类库存由 `Inventory` 唯一维护。调用方只获得聚合快照与结果。

每次步进代表一模拟秒，依次：

1. 若本秒输入降雨，按格索引顺序对全部现有农田调用 `FarmingSystem.SupplyWater`；暂停时不应用降雨。
2. 按旧格索引顺序推进 `FarmingSystem` 的生长和 `ProcessingSystem` 的在加工批次；到期结果由 `FarmGame` 交给 `Inventory` 入库。收获清除本轮水分，本秒降雨不立即补水。
3. 按 `Y * 128 + X` 递增顺序让 `ProcessingSystem` 的空闲场地，通过 `Inventory.TryTakeRawForProcessing` 领取超过该种当前底线的一份原料；后一个场地读取前一个扣减后的数量。
4. 调用一次 `WorkerScheduler.AdvanceOneSecond`，按固定编号让三人各推进完整一秒；内部先统一释放失效认领，再选择有效且未认领的农田并推进移动或工作。实际工作经 `FarmingSystem.TryCompleteWork` 重验目标凭据、动作需求与播种条件；到田的移动秒不同时播种，干田播种与原地接续浇水分别占完整一秒。湿田播种后直接生长；`WorkerActed` 聚合本秒是否至少一人真正完成动作，移动不计入。
5. `GameCalendar` 累计一秒；跨季时让 `FarmingSystem.ClearDisallowedCrops` 按新季节一次清理禁生的待水或生长中作物及水分、进度，保留农田与选种；跨入新日时按新天数更新旧价格曲线。

生产时长统一用整数比例单位累计：一模拟秒推进 7 单位，一游戏日为 360 单位，半日为 180 单位。作物获得水或场地领取原料时设置目标；之后每秒扣除 7 单位，首次达到目标时收获或完工。步进开始的降雨让待水作物从本秒生长；工人在生长相位之后浇水或使用留水播种，则从下一步开始扣减。同一步到期与换日、跨季同时发生时，先结算成熟、加工、领取和工人动作，最后换日。暂停时全部经营相位不执行，恢复后不补现实时间；窗口失焦不会自动暂停。

换季清理只处理未收获的本轮作物，不操作历史库存和金币，不产生额外工人工作。适季作物继续原进度，空田留水保持；同一步成熟已先收获入库，不会随后失败。清理使本轮目标凭据失效；下一工人相位释放旧任务和认领，旧动作不能操作新轮。空田的工作需求继续复用统一播种检查，禁生季节不再播种，改种或条件恢复后可继续。

降雨已在工人相位前满足供水时，调度取消过期浇水，既不重复供水也不重置生长；移动中的播种任务可以继续使用湿田。任务实际完成时使用本步开始的日历快照重验，不能因选取时允许播种就略过执行检查。暂停时工人位置和任务保持，恢复只推进下一模拟秒；界面插值不修改这些状态。

底线设置只修改 `Inventory` 中该品种的规则值，不调用领取阶段；下一经营步按新值检查。新建加工场地立即调用同一全场领取阶段，让全部空闲场地按稳定格序检查当前底线；先前等待的场地同样参与，保持旧行为。提高底线不会退回批次投入物；暂停时仍可编辑底线，但不会因编辑推进经营。

地图镜头、可见块和帧率不影响上述遍历；满地图 50 步检查覆盖角落实体。作物成熟与加工时长以[作物表](../../../gameplay/production/crop-growth.md)为准，出售结算以[交易规则](../../../gameplay/trading/sales.md)为准。
