# 等价批量经营推进实现

履行 [FarmGame Interface](interface-farm-game.md) 的 `AdvanceTicks`。状态仍归各原模块唯一拥有，经营协调不复制生产时间、工人任务、计划凭据或订单资源。

一次请求先校验日历容量，再取各模块下一事件距离的最小值。事件之前的平静段只对农田和加工同步 O(1) 读取时钟、对工人一次累计位置，日历一次加秒；无公告和报价的日期直接保持行情并同步其已推进日期。请求在事件前结束时给出终点检查点；否则在事件秒调用 `AdvanceEventTick` 执行与单秒入口相同的完整相位，再提供稳定检查点。循环次数取决于事件数量，批量入口不循环调用 `AdvanceTick`。

事件包含天气开始与结束、雨天干田供水、农田成熟、加工完工或领取、工人任务失效/选择/到达/动作、年度表起止与年度凭据清理、季节边界、行情公告与报价，以及必要订单检查。普通日界没有其他业务变化时允许跨过，检查点和最终结果仍正确汇总 `DayAdvanced`；宿主自身日期与等待预算必须先限制请求秒数。

农田和加工各自唯一持有 long 精确目标及预约句柄，最近生产事件直接从共享索引取得；平静段不逐设施减时或写天气积分。到期秒按混合 FIFO 逐项完成并入库，正常产出及原换季促熟全部完成后才领取原料。萝卜每批 `ceil(180/7)=26` 秒，100 批仍是 2600 秒，不合并批次取整。当前局买入的首次领取额外占下一秒；加工品入库后本秒可领取下一批，新批从下一秒计时。场地领取仍按锚点稳定顺序竞争同一库存。完整契约见[生产到期接入](implementation-production-due.md)。

工人模块封装行程事件和位置公式。单秒与批量使用同一不可变完整路线，以整数累计已行秒乘 3 采样权威 double 连续位置；各段最大轴差累计后整趟一次向上取整，取消从实际点重新求路，不从 Vector2 显示投影回读。平静批量只发布最近完整秒的真实距离区间，秒戳和任务凭据与逐秒推进一致。最近事件距离由工人模块查询，经营入口不计算路线或距离。失效和空闲选择是下一秒事件，到达当秒只移动，下秒才动作，播种与浇水各占一秒。

计划模块给出缓存条起止和年度清理的下一个到达整秒；生长中的预计结束时间不因平静累计改变。到期、供水、实际播种、禁生清理仍在完整相位中通知和同步，平静区间不重复扫描安排或伪造播种凭据。行情模块给出公告准备或正式报价的绝对日，日历按 `ceil(day×360/7)` 定位事件；每次随机调用、旧价递推及节日排期仍依次执行。

订单模块每次新批量请求先安排一次必要检查，覆盖请求之间的正式经营命令。事件相位永远按创建顺序重验所有等待订单；任意一次单或持续单本秒成功且仍有等待单时，下一秒继续检查，纳入库存、现金及冻结释放对前序等待单的影响，保持密集成交和手续费逐笔取整。已检查的前单本秒不回头重试，每单每秒最多成交一次。全部等待单在依赖不变时未成交后，平静段可省略重复失败检查；全部订单已结束或停用时也不额外安排检查。任何生产、领取、季节或行情事件都会重新执行订单相位。以上重检条件封装在[订单模块](../../trading/trade-order-book/interface-trade-order-book.md)的 `NeedsNextTickCheck`，不合并交易轮次，不在经营入口识别成交组合或复制交易公式。

单秒和批量读取同一 WeatherSystem。天气开始／结束作为完整事件；事件前平静段使用原天气，完成该秒后天气同步到当前日历，下一秒才应用新天气。显式局在请求之间设置／清除矩形天气，雨仍先供水再生长。持续雨下已有水的农田不会强制每秒事件，待水／干田才要求下一秒供水，收获清水后下一秒重新供水。回调发生在全部相位完成的稳定点；宿主可提交正式命令并返回 false，下一请求重新定位全部业务事件。回调不能嵌套推进。

`TestBatchedSimulation` 通过公开快照和稳定回调逐段对照原单秒入口：每个批量检查点让参考局逐秒到达相同绝对时刻，比较本段产出、工人、日期、生产、计划、十四商品库存与冻结、行情/公告及订单状态/最后逐笔成交，再继续后续事件。覆盖七作物随机切段、显式雨、季年与冬春条、两种计划模式、禁生严格阈值、中途换目标/拆建、底线冻结与场地竞争、密集成交、四份一批首次达到两份目标的27秒和预算终点、暂停零请求与容量拒绝。另覆盖无设施的一次卖单唤醒补货、一次买单唤醒卖出、冻结现金释放唤醒前序买单：先检查第1秒只有后单成交，再比较第2秒的完整状态，并对10秒采用整段、1+9和2+3+5切段与逐秒对照；全部等待场景要求10秒仍为1个事件秒和9个平静秒。执行成本分别报告平静与事件秒数；满地图50秒额外对照检查真实累计。验收结果由总工程师集中记录。

## 长期维护约束

请求先完整校验uint32日历容量，超出不能截断；每经营秒7单位、每日360单位，季节4320 tick、年度17280 tick。处理事件时沿用[完整经营相位](implementation-tick-order.md)，暂停不推进，订单买入原料不提前到本秒领取。宿主以目标日期和等待预算限制请求，回调只在完整经营秒之后观察与中止。

密集持续成交仍逐笔结算，不能把多笔手续费合并取整；不承诺任意状态的常数时间推进。本次 #65 仅替换生产计时和到期定位；空闲领取、降雨、工人寻找及计划等扫描仍保持。全图索引优化 #66 和未来稳定成交轮次聚合不在本范围。


## 日志窗口安全边界

生产累计接入原实际收获入库、加工完工入库、全场闲置领取成功和工人成功回调；换季清理返回原遍历产生的真实轮数。quiet 段不产生这些事实，不为日志拆段或重扫实例。AdvanceTicks 外层完整请求通知日志进入/退出推进，checkpoint 内命令终结只请求窗口检查，实际封窗延后到外层请求返回；原有禁止嵌套推进约定保持。AdvanceTick 同样在完整请求结束处检查。异常退出保留原异常，当前窗标为缺少完整推进边界；详见[窗口实现](../../logging/implementation-event-output.md#生产累计与安全封窗)。

`TestWeatherYield` 另对自然及显式局逐秒、整批和二段拆批跨年度对照：真实区域、工人、生产进度、最近成功结果及两类库存必须相同，随机抽取与天气积分不能随拆批改变。末秒与促熟按实际生长单位结算，正常成熟末秒最多7单位。

禁生严格阈值回归保留临界值511/504/497精确单位；实际促熟时两坊各锁9份，共18份，按“原料库存＋当前投入＝本次收成”检查守恒，同时比较逐秒与批量。未达到严格促熟条件时仍要求零收成且零投入，不降低边界断言。
