# 等价批量经营推进实现

履行 [FarmGame Interface](interface-farm-game.md) 的 `AdvanceTicks`，关联 #100。状态仍归各原模块唯一拥有，经营协调不复制生产时间、工人任务、计划凭据或订单资源。

一次请求先校验日历容量，再取各模块下一事件距离的最小值。事件之前的平静段由农田、加工、工人分别一次累计，日历一次加秒；无公告和报价的日期直接保持行情并同步其已推进日期。请求在事件前结束时给出终点检查点；否则在事件秒调用 `AdvanceEventTick` 执行与单秒入口相同的完整相位，再提供稳定检查点。循环次数取决于事件数量，批量入口不循环调用 `AdvanceTick`。

事件包含农田成熟、加工完工或领取、工人任务失效/选择/到达/动作、年度表起止与年度凭据清理、季节边界、行情公告与报价，以及必要订单检查。普通日界没有其他业务变化时允许跨过，检查点和最终结果仍正确汇总 `DayAdvanced`；宿主自身日期与等待预算必须先限制请求秒数。

农田和加工各自按精确剩余时间给出向上取整的秒距离；平静段只扣 `7×N`，到期事件沿原操作结算并清空。萝卜每批 `ceil(180/7)=26` 秒，100 批仍是 2600 秒，不合并批次取整。当前局买入的首次领取额外占下一秒；加工品入库后本秒可领取下一批，但新批从下一秒开始推进。场地始终按锚点稳定顺序竞争同一库存。

工人模块封装行程事件和位置公式。单秒与批量均为本段起点加每秒位移乘累计移动秒数，到达时对齐工作中心。最近事件距离由工人模块查询，经营入口不计算路线或距离。失效和空闲选择是下一秒事件，到达当秒只移动，下秒才动作，播种与浇水各占一秒。

计划模块给出缓存条起止和年度清理的下一个到达整秒；生长中的预计结束时间不因平静累计改变。到期、供水、实际播种、禁生清理仍在完整相位中通知和同步，平静区间不重复扫描安排或伪造播种凭据。行情模块给出公告准备或正式报价的绝对日，日历按 `ceil(day×360/7)` 定位事件；每次随机调用、旧价递推及节日排期仍依次执行。

订单模块每次新批量请求先安排一次必要检查，覆盖请求之间的正式经营命令。事件相位永远按创建顺序重验所有等待订单；任意一次单或持续单本秒成功且仍有等待单时，下一秒继续检查，纳入库存、现金及冻结释放对前序等待单的影响，保持密集成交和手续费逐笔取整。已检查的前单本秒不回头重试，每单每秒最多成交一次。全部等待单在依赖不变时未成交后，平静段可省略重复失败检查；全部订单已结束或停用时也不额外安排检查。任何生产、领取、季节或行情事件都会重新执行订单相位。以上重检条件封装在[订单模块](../../trading/trade-order-book/interface-trade-order-book.md)的 `NeedsNextTickCheck`，不合并交易轮次，不在经营入口识别成交组合或复制交易公式。

显式雨输入由宿主分隔无雨请求并调用 `AdvanceTick(true)`，雨仍先供水再生长。回调发生在全部相位完成的稳定点；宿主可提交正式命令并返回 false，下一请求重新定位全部业务事件。回调不能嵌套推进。

`TestBatchedSimulation` 通过公开快照和稳定回调逐段对照原单秒入口：每个批量检查点让参考局逐秒到达相同绝对时刻，比较本段产出、工人、日期、生产、计划、十四商品库存与冻结、行情/公告及订单状态/最后逐笔成交，再继续后续事件。覆盖七作物随机切段、显式雨、季年与冬春条、两种计划模式、禁生严格阈值、中途换目标/拆建、底线冻结与场地竞争、密集成交、首次目标53秒和预算终点、暂停零请求与容量拒绝。#117 增加无设施的一次卖单唤醒补货、一次买单唤醒卖出、冻结现金释放唤醒前序买单：先检查第1秒只有后单成交，再比较第2秒的完整状态，并对10秒采用整段、1+9和2+3+5切段与逐秒对照；全部等待场景要求10秒仍为1个事件秒和9个平静秒。执行成本分别报告平静与事件秒数；满地图50秒额外对照检查真实累计。验收结果由总工程师集中记录。

## 长期维护约束

请求先完整校验uint32日历容量，超出不能截断；每经营秒7单位、每日360单位，季节4320 tick、年度17280 tick。处理事件时沿用[完整经营相位](implementation-tick-order.md)，暂停不推进，订单买入原料不提前到本秒领取。宿主以目标日期和等待预算限制请求，回调只在完整经营秒之后观察与中止。

密集持续成交仍逐笔结算，不能把多笔手续费合并取整；不承诺任意状态的常数时间推进。生产绝对到期时间优化#65、全图索引优化#66和未来稳定成交轮次聚合仍是独立范围，本次批量实现不代表这些后续任务已经完成。
