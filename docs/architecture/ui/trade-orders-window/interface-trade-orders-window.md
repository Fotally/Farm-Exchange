# TradeOrdersWindow 接口

窗口以1920×1080为视觉设计基准，另验收2560×1440及3840×2160。统一 `UiScaling` 接口调整窗口整体及额外字体倍率；新增条件组、条件行注册到树后继承当前倍率，仍保留原始控件尺度供后续绝对设置，重复设置不累计。编辑及资源快照的业务语义不变，动态输入继承与草稿保持由 `tests/e2e/TestUiScaling.cs` 验证。

汇总 `TestSuite` 与独立 `TestTradeOrdersWindow` 入口显式设置1920×1080，并等待真实视口尺寸生效。关闭画布拉伸后，headless 原生默认64×64不能作为正式布局基准；测试仍检查143/180上下避让、31像素侧边距、真实标题及固定操作可见，条件滚动与焦点断言保持。

实现为 `scripts/ui/TradeOrdersWindow.cs`，继承 [DraggableWindow](../draggable-window/interface-draggable-window.md)。玩家从[市场窗口](../market-window/interface-market-window.md)的“委托与策略”打开独立窗口；经营状态与冻结资源由 `FarmGame` 的委托入口唯一维护。

## 玩家编辑与命令

窗口左侧显示按建单顺序排列的委托，保留已成交和已撤销记录。选择列表项目才将完整配置加载到右侧编辑器；“新建委托”保留当前草稿作为新单的配置，并明确使用新的设单现金基准。普通刷新不重新加载所选单配置。活动单可保存修改或撤销，持续策略另可停用、恢复；已成交、已撤销的单据仅可查看，编辑和撤销按钮禁用。停用不是经营暂停，两者的执行规则由后端决定。

右侧选择十四商品之一、买卖方向、一次或持续、交易数量方式、现金保留，并按需增删条件组和条件行。同组显示“同时满足”，不同组显示“或”；价格采用金币输入并转为整数分，库存采用份数整数，季节只能等于春、夏、秋、冬之一。季节只读取现有日历，不额外增加收益或价格因素。

一次买单显示“最高单价＋数量”和“固定总预算”两种资金方式。固定预算含手续费，数量由真实成交价决定，因此界面隐藏数量、目标与最高单价输入。最高单价方式可指定固定数量或补货目标，单次目标由经营入口锁定差额。持续买单不显示冻结预算输入，持续目标由经营入口动态计算。卖单可选择固定数量或卖到剩余库存。方向切换禁用不适用的目标模式，当前选项若不适用则回到固定数量。

现金保留仅在买单编辑器出现，支持固定金额或整数百分比。界面只提交参数，不计算设单基准、保留金额、冻结预算、预算可买数量或手续费；选择已建单时可以查看后端锁定值，编辑仍通过原 ID 更新。未提交的条件、金额、数量都只是界面草稿。

| Interface | 调用约定 |
| --- | --- |
| `CreateRequested(TradeOrderRequest)` | 文本解析成功后发送完整建单意图，由 Main 调用 `CreateTradeOrder`。 |
| `UpdateRequested(int, TradeOrderRequest)` | 编辑同一活动单，携带原 ID；不通过撤销重建刷新现金基准。 |
| `CancelRequested(int)` | 撤销所选活动单，由经营入口释放冻结。 |
| `EnabledRequested(int, bool)` | 停用或恢复所选持续策略。 |
| `ShowCommandResult(TradeOrderCommandResult)` | 显示真实成功或拒绝原因；成功后关联真实 ID，失败保留原草稿。 |
| `Refresh(FarmGame)` | 读取余额、商品库存和独立委托快照，更新状态与成交结果，不求值、执行或重建编辑器。 |

金额只接受非负十进制且至多两位有效小数，转换后不超过 `int.MaxValue` 分；最高单价和总预算还须为正。数量接受非负整数，固定数量、补货目标是否为正等业务约束由经营入口统一拒绝。比例须为 0～100 的整数。空白、负值、小数份数、溢出与非法金额不发送意图，窗口显示中文输入原因；空条件组等完整配置拒绝由经营入口返回，界面不复制后端判断。

## 只读状态与刷新

顶部区分总金币、可用金币、冻结金币，以及当前编辑商品的总库存、可用库存、冻结库存。切换商品从最近的只读资源快照更新显示；真正提交仍由经营入口执行时重验，不使用显示值结算。

所选委托显示原设单现金、锁定保留线、冻结金币与商品、单次锁定数量、真实执行状态和等待原因。最近一次成交读取独立的 `LastFill` 成交快照，显示成交当时的商品、买卖方向、实际数量、商品货值、1% 手续费、含费用的实际支出或扣费后的实际收入，以及成交后总余额。编辑持续单的商品或方向不改写、清空这条已发生的成交，也不按修改后的配置猜测成交身份；后续成功成交才替换最近记录。不新增历史流水，不把未成交或拒绝显示为收费成交。

每秒刷新只更新标签和已有列表项目，新增委托才追加项目，终态记录不移除。条件控件仅在玩家添加、删除或明确选择另一单时改变；草稿、焦点、光标、滚动、控件身份、关闭重开后的窗口位置都保留。主场景暂停期间仍可编辑、创建、停用和撤销，刷新本身不推进经营。

## 布局与验收

标题沿用共享窗口的明确单行排版，避免初次零宽自动换行把窗口撑高后不回落。布局回归检查当前真实视口可用区域、末行可达与焦点，并同时检查原市场窗口；删除正在编辑的条件组前先释放焦点，不在移出树后操作失效的控件。

窗口基准尺寸 `960×520`，首次在可用视口居中，采用共享木框与纸面主题；统一定位和避让范围见[可拖动窗口](../draggable-window/interface-draggable-window.md)。左侧委托列表和状态使用独立有界区域，右侧编辑器纵向滚动；编辑标题、商品/方向/执行方式、买入资金、数量、现金保留及条件组按层级排列，字段基准高约36像素、纵向间距12像素。创建/保存为橄榄绿主操作，新建与添加条件为纸面次操作，撤销和删除降低强调。保存、停用、撤销位于编辑器下方，基准尺寸保持可见；较小可用高度由共享窗口外层滚动访问。

左侧委托列表最小高125、独立状态滚动区最小高105像素。状态详情保持原独立滚动，减少该区域的固定最小高度，让默认960×520窗口中的创建/保存、停用、撤销和新建完整处于 `WindowScroll` 的真实可见区域；QA同时检查窗口与滚动可视范围，不以“需要先滚动整个窗口”替代默认操作可见。

节点入口为 `TradeOrdersWindow`，主要节点为 `OrderList`、`OrderResources`、`OrderDetails`、`OrderEditorScroll`、`OrderConditionGroups`、`OrderFeedback`；输入以 `OrderCommodity`、`OrderSide`、`OrderFrequency`、`OrderQuantityMode`、`OrderQuantityInput`、`OrderBudgetMode`、`OrderBudgetInput`、`OrderLimitInput`、`OrderReserveMode`、`OrderReserveInput` 命名。条件行和组使用单调递增的显示编号，编号不作为经营单据 ID。

`tests/e2e/TestTradeOrdersWindow.cs` 通过真实主场景、可见控件和公开经营入口验证建单、OR/AND 编辑、季节条件、两种买单资金方式、单次锁定目标、现金基准不重算、冻结及撤销、持续停用恢复、真实买卖费用与反馈、终态按钮、市场可售量以及非法文本；持续买入成交后修改商品及方向仍显示原商品买入、原含费支出和成交后余额，后续卖出成功才替换为新商品和净收入。`RunLayoutChecks` 挂树等待排版后检查窗口和固定按钮可见、末个条件可滚动到达、条件行横向不溢出、暂停刷新保留焦点和滚动；图形后端将真实一次冻结单与持续策略窗口保存至 `build/issue36-validation/orders-window.png`。独立场景为 `tests/e2e/test_trade_orders_window.tscn`，根套件使用同一行为与布局入口。
