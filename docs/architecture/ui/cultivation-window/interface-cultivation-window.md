# CultivationWindow 接口

对应 `scripts/ui/CultivationWindow.cs`，继承[可拖动窗口](../draggable-window/interface-draggable-window.md)，从开局底部“年度耕作表”与农田详情入口打开。

窗口基准尺寸 `1000×520`，首次在可用视口居中，采用木框、纸面与深棕正文；统一定位与顶部143、底部180像素避让范围见[可拖动窗口](../draggable-window/interface-draggable-window.md)。窗口扩大时保持设定倍率下的像素尺寸。左侧保留共享表与勾选农田，右侧按名称/模式、作物来源、四季时间图、选中整轮说明、保存操作排列。作物卡是浅色方形卡片，时间带与作物条沿用同一纸面配色；月份、每七日周刻度、今日线、整条拖放和跨季环绕保持。保存和批量应用为橄榄绿主操作，移除降低强调。农田列表独立滚动，较小可用高度另由共享窗口外层滚动容纳全部操作；常规基准尺寸仍检查时间图、保存与应用可见。

- `Refresh(FarmGame)` 读取共享表、农田引用与当前日期；不提交命令、不推进经营，不覆盖名称、模式、作物条草稿、输入焦点或农田勾选。
- `SaveRequested(int?, CultivationPlanRequest)` 请求创建或编辑共享表；空 ID 创建，已有 ID 更新原表。每条稳定 ID 在移动、跨季折行与保存时保持。
- `ApplyRequested(int, IReadOnlyList<Vector2I>)` 报告已保存表与勾选农田锚点；表尚未保存或未勾选农田时在窗口内说明原因。
- `ShowCommandResult(CultivationCommandResult)` 与 `ShowApplyResult(string?)` 展示经营入口的真实结果。保存成功关联返回的表 ID，草稿留在原控件中。
- `DeleteRequested(int)` 只报告当前已保存表编号；“共享年度表”标题旁的“删除表”入口在未保存草稿状态禁用。提示显示真实引用田数量，并明确删除会解除引用、保留当前作物和水分，后续按各田当前作物自动复种。
- `ShowDeleteResult(string?)` 展示经营入口的真实删除结果；失败保留原表选择、名称、作物草稿与焦点。成功清除原表编号、草稿和选中作物条，切换到新表草稿，后续统一刷新同步列表与农田引用；不在窗口内修改生产状态。

窗口只持有编辑草稿与选择状态。新增及移动时，由窗口构造完整候选作物条，在时间图 `CanDrop` 阶段调用 `FarmGame.CheckCultivationEntries`；移动替换原 ID 对应的一条，不同时保留旧位置。落位回调再次验证同一候选，成功后才一次更新草稿。排程检查不依赖名称：首次开窗空名以及清空已有表名时仍可编辑，空名期间仍展示真实风险轮廓；保存时才以原名称、模式及完整草稿调用 `CheckCultivationPlan`，空名拒绝且正式表零修改，不用默认名称绕过验证。拒绝落位保持原条、草稿与正式表，显示经营入口的具体原因；UI 不重新计算季节、重叠或间隔约束。适季开始但跨禁生边界的条仍允许落位及保存，红色方形轮廓标识风险；禁生季起点拒绝，不自动移动或换作物。表级模式选项作用于整张表。列表展示真实引用田数量；保存按钮旁提示影响几块引用田，农田勾选行展示当前引用名称。

窗口从快照 `NextEntryId` 载入下一可用条编号；成功新增后推进草稿编号，删除不回退，刷新只向持久高水位提升。保存空表后重新选择也沿用持久高水位，移动已有条仍保留其 ID。窗口不删除或重置领域的年度执行凭据。农田 `CheckBox` 保持普通、悬停、按下、悬停按下与焦点五种状态的深色字，并继承共享纸面主题。

整表删除与“移除选中整条”是不同操作。后者只改当前草稿，保存后才生效；前者提交经营命令删除已保存表，包括其尚未提交编辑所对应的原保存表。允许删除已有引用的表，由经营模块解除该表全部引用和后续安排，保留各田当前品种、播种/生长阶段、剩余时间与水分；其它表和独立手动预备不受影响。表编号不复用。普通刷新保持其它未提交草稿；若当前选中的已保存表已被其它调用实际删除，刷新清除失效选择并切换新表草稿，避免引用不存在的编号。

执行日期与实际进度分开：时间图显示计划日期及今日标记，农田详情显示实际生长剩余游戏天数（向上取一位小数）、待水时完成日期未确定、预备作物与日期或休耕。具体折行与动效见[年度时间图实现](implementation-annual-timeline.md)，玩家操作见[耕作表操作](../../../gameplay/production/seasonal-cultivation-ui.md)。

## 验收入口

视觉基准为1920×1080，另验收2560×1440及3840×2160；原1280截图是历史取证。窗口使用统一 `UiScaling.SetOverallScale` / `SetFontScale` 调整整体及额外字体，设置不提交排程或改变草稿。动态农田勾选保留12号原始字号，注册到树后继承窗口当前倍率；四季自绘与原生预览使用同一实际字号，选中说明始终保留两行，防止字体/选中变化造成拖动期间轨道宽度漂移。独立入口 `test_ui_scaling.tscn` 检查倍率组合、输入保持、原生精确日期与滚动可达。

汇总 `TestSuite` 与独立 `TestCultivationWindow` 先显式设置1920×1080并等待视口生效，再运行界面流程。关闭画布拉伸后，headless 原生默认64×64会裁切原生拖放目标，不能用作UI验收；夹具只确定真实显示基准，首次空名编辑、精确落位日期、冲突拒绝和暂停规则继续完整验证。

`test_cultivation_management.tscn` 针对共享表列表管理。真实主场景保存表后，通过原生鼠标悬停、点击选中及聚焦 `CultivationPlanList`；检查普通、悬停、选中、选中焦点与选中悬停文字，特别覆盖当前引擎实测的 `font_hovered_color`、`font_hovered_selected_color`，文字与实际纸面背景的对比至少4.5。1080P、2K、4K及整体/字体极值取证写入 `build/issue94-cultivation-fix-validation/`；列表交互不得推进暂停的经营日期。删除回归使用真实按钮命中，验证无引用空表、多田生长中引用表、草稿清理、失败保留焦点、外部删除后刷新及编号不复用；删除前后截图同目录保存。

`TestCultivationDeletion` 通过真实经营入口检查两种表级模式下多田生长、待水、休耕干空田及湿空田的整表删除，并验证无引用空表与非空表均可删除、连续删除后表编号仍递增。不存在和已删除表的拒绝保持配置、农田、库存、金币与日期；成功保留当前轮与水分、其它共享表及独立手动预备，解除全部目标引用，后续由真实工人完成当前品种的收获和自动复种，不执行旧表异种安排。目标场景与汇总套件均包含这些检查，结果由项目测试记录统一登记。

`tests/e2e/test_cultivation_window.tscn` 使用真实 `Main` 与经营入口验证拖入、移动、移除、冲突拒绝、风险保存、表级模式、批量引用、手动接管和刷新草稿；两种手动窗口打开后从详情移除本田，验证窗口随生命周期关闭。布局检查验证当前真实视口可用区域、固定按钮与输入焦点；主要图形取证使用1920×1080和2560×1440。暂停时保存表改变当期空田作物，验证可见地图块同步，有渲染时还比较工作中心实际像素。

第一轮原生拖动到冬春落点、释放之前检查预览中心与实际鼠标位置误差不超过1.5逻辑像素、仍在拖动且经营日期未推进；有渲染时等该帧实际绘制完成，保存整根直条预览 `build/issue86-ui-validation/cultivation-drag-preview.png`。落位分段图保存在同目录 `cultivation-window.png`。真实原生拖放断言非法悬停不会触发落位事件，保存后原条保持；另检查自身替换、冬春重叠与一天间隔合法对照。

有窗口时，真实鼠标悬停短萝卜和窄冬春片段，按 Godot 标准提示延迟等待提示出现，验证整轮日期、完整周期及窗口内可读范围，保存 `short-radish-tooltip.png` 和 `winter-spring-tooltip.png`；移开后检查提示消失。能容纳完整信息的条直接条内显示，无需悬浮。headless 保留拖动及日期断言，不等待渲染、不保存截图，也不伪造原生提示已出现。

有窗口的原生鼠标事件同时定位系统鼠标，确保拖动预览与释放使用同一落点；每轮拖动结束或异常退出时恢复原屏幕鼠标位置。坐标换算与 headless 差异见上述年度时间图实现。

追加回归以首次空名窗口原生拖入马铃薯、空名保存拒绝及重命名保存验证编辑/提交分离；清空已有名称后新增及移动仍可行，重叠、禁生起点和异种间隔仍拒绝。条编号回归先实际收获日0萝卜，再删除、保存空表、重选并新增日10，核对新 ID 不复用且预备仍在本年日10。字色检查五种状态在窗口浅底的对比至少4.5；真实鼠标悬停勾选并聚焦的农田，分别在1280×720及1600×900窗口取证，测试后恢复原窗口尺寸与鼠标位置。追加证据写入 `build/issue86-followup-validation/`，保留上一轮日志和截图。
