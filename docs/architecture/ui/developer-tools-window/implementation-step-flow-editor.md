# C分步流程编辑器实现

履行[DeveloperToolsWindow接口](interface-developer-tools-window.md)，关联 [#104](https://github.com/Fotally/Farm-Exchange/issues/104)，维护已确认的C分步设计与实现。HTML仍为历史设计原型，实际运行、文件保存和删除均由Godot窗口接入配置库完成。

## 状态与维护位置

`DeveloperToolsWindow`唯一拥有当前步骤、流程标识、配置列表、草稿引用及运行上下文。`ScenarioCatalogStep`封装分类、搜索和两列卡片；`ScenarioEditorStep`封装配置选择、保存操作及通用表单；`ScenarioResultStep`封装启动、中止、进度和报告。三个步骤分别维护，不引入向导继承树。步骤切换仅改变可见性，不重新加载草稿。

配置定义、文件发现、修订、目录移除及受限文件操作属于`ScenarioConfigurationLibrary`。三个视图不拼接参数文件、不计算费用或日历；固定执行仍由`BuyProcessSellScenario`及`SimulationDriver`维护。

主窗口1360×740，以1920×1080为基准，沿用`DraggableWindow`上143、下180像素避让。本次按已选C原型重新兑现视觉，此前仅验证边界与功能的记录不能作为视觉通过。通用拖动和自动居中逻辑保持，1080P窗口顶部150px比原型155px高5px；对照按窗口内相对坐标进行。

页眉68px，标题「开发测试 · 流程与配置」21px，右侧13px「开发工具」标识保持单行、按文字自然宽度约72px展开；标识约28px高度与34px关闭按钮垂直居中，不随页眉行拉伸。避免默认自动换行将标识压成19px窄条、撑高页眉并使导航下移；不通过强制裁切页眉高度掩盖内容。正文水平22px、垂直20px内边距。步骤导航使用16px左对齐文字、43px高度，三项平均铺满行宽、间距13px；当前步为绿色奶油字，普通项为纸色，不再追加圆点。正文与导航相隔18px；反馈为空时隐藏整个反馈区域，错误或实际结果文字出现时才占位并滚动。

第一步侧栏285px，只显示39px搜索输入和可换行分类按钮；分类14px、间距7px，只有「全部」及真实非空分类。列间距28px，右侧列表额外左2px、右6px、上2px、下5px内边距；两列卡片间距10px，基准高度112px。卡片整体为一个选择按钮，仅绘制一层边框：普通纸色2px边框，选中为橄榄绿边框与左4px。名称15px、简介12px，文字区域水平13px、上11px、下38px，右下角29px垃圾桶覆盖在卡片中，不新增一行或触发主卡片选择。字号扩大时根据真实文字最小高度调整卡片，保持两列、焦点和可滚动内容。

底部1px分隔线、上下14px留白和120×43px「继续配置 →」按钮固定显示，保持原继续意图。外层正文禁用滚动，各步骤正文独立滚动。

配置页显示20px流程名与14px简介，下一行依次为「配置」标签、335×39px下拉、35px垃圾桶和草稿状态；较长名称在控件内裁剪、悬停显示完整名称，选项不占满整行。表单按扫描得到的Group聚合为并排列，含数组的组稳定置末，非数组组保留元数据原顺序，当前显示基本设置、生产参数、时间安排。三列宽度为1/1/1.15、间距25px，每组字段纵向排列、嵌套锚点等对象内部继续并排；字段路径和JSON序列化顺序不改变。不同Group数量继续使用同一布局，实际可用宽度或字号不足时减少列数；右侧预留滚动条宽度，添加数组行不挤动字段。底部保留原返回、另存为、覆盖与继续意图，说明放在保存行下方。

结果页显示24px所选流程名及14px配置摘要，真实进度与报告位于`#e4dfbc`纸色单框中、四周15px内容间距；原开发倍率与说明保留，下方分隔线及返回、启动、中止固定显示。配置和结果页仅恢复原C的视觉结构，持久化、修订、执行与终止快照规则保持。

分类按钮按CSS水平11px、垂直6px内边距加2px边框计算实际尺寸；Godot样式内容边距相应为13/8px，避免漏计边框使285px侧栏的第二行误挤进三个按钮。步骤与分类按钮的2px外框内绘制1px奶油细线，装饰控件忽略鼠标事件，分类、继续及步骤意图保持。

配置选择行的「配置」标签也禁止自动换行，按字号自然宽度显示，避免压成1px、撑高整行。下拉垂直居中保持39px、垃圾桶保持35px。配置选择及生成器的文本、数值、选项和日期控件共用本窗口局部输入样式：16px深色字、`#fff7e3`白纸、1px边框，正常、悬停和焦点保留纸面，禁用可淡色；选项箭头使用深色，不修改全局`UiElements`。日期输入每项62×39px、靠左，不在窄组中平均拉伸，年/月/日单位保持14px单行居中。

日期输入另外将Godot `minimum_character_width` 从默认4个M字符调整为2，并关闭按文本长度自动扩宽；固定62px宽度不被默认85px文字空间顶开。该主题常量是字符数而非像素，字体1.2倍仍能显示两位日期；实际文字行高可以自然增加，不裁切。约定依据见[Godot LineEdit主题说明](https://docs.godotengine.org/en/stable/classes/class_lineedit.html#class-lineedit-theme-constant-minimum-character-width)，只作用于三个日期输入。

## 字段描述与表单的Seam

`ScenarioConfigurationForm.BindDraft`接收配置草稿，从`Schema.Fields`递归构造控件。表单只使用字段形状、中文元数据、选项和字段路径，不判断`rawCommodity`等具体JSON键名。分组标题与对象标题、父对象标题与子字段标题相同时合并展示一次；包含不同单位的标题仍显示单位，不改变草稿字段路径。文本与数值输入保留原文，由草稿按字段类型校验；布尔使用勾选，选项使用中文下拉；游戏日期拆为年/月/日，有序对象数组提供增删与上下移动。

标量变化更新草稿、错误及条件可见性，不重建输入控件。数组结构改变重建表单并恢复滚动及仍存在的同路径焦点；不存在的已删字段不继续保留输入引用。错误使用草稿的字段路径，在对应行及窗口反馈显示。动态控件通过现有`UiScaling`继承整体与字体倍率，字体变化使容器真实重排。

运行中的状态刷新只更新锁定状态和结果文字，不重新构造草稿控件。运行上下文使用启动时实际加载的参数文件。成功保存新修订、切换配置身份或删除失效选择时，清空窗口旧进度及报告路径，避免将旧结果归到新输入；磁盘历史报告保留。单纯来回切换步骤保持同一配置结果。

## 两种确认与文件结果

`ScenarioConfirmationPanel`是主窗口内的木框遮罩，显示对象名称和明确的操作范围。另存为使用同一弹层输入新名称，删除使用取消、确认删除和关闭入口。弹层打开期间锁定背后导航与编辑，Esc只取消弹层；确认后才调用配置库。取消不修改草稿或文件。

流程删除成功清空该流程的选择、草稿与旧运行引用，回到目录；配置删除成功刷新列表并选取仍存在的配置。只读示例禁用覆盖、配置删除和启动，只允许修改草稿后另存为。删除失败仍重新扫描实际目录：同一文件仍存在时保留原草稿、非法输入、控件及焦点；已实际删除的选择清理后显示仍存在的配置。保留原删除错误，不把部分文件删除伪装成完整成功或回滚；若重扫也失败，另行显示实际目录刷新错误。

## 验证入口

`tests/e2e/test_developer_flow_editor.tscn`使用隔离配置目录，通过实际控件及原生点击验证卡片与垃圾桶分离、只读限制、条件种子、另存与覆盖、数组排序、两种删除确认和目录持久移除。真实运行生成报告后验证步骤切换保留结果、新修订清空旧界面结果且磁盘历史不变；外部改文件导致删除拒绝时保留非法输入草稿，目录记录位置被占据时验证部分删除失败后同步实际条目。另一个未登记为可运行流程的类型使用同一表单验证布尔、文本及完整uint32数组字段。

当前布局的代表性画面见[正式单流程目录](godot-flow-catalog-1920.png)、[同原型16条目容量](godot-flow-capacity-1920.png)、[配置编辑](godot-config-editor-1920.png)与[运行结果](godot-flow-result-1920.png)。容量条目仅用于测试，正式目录仍只有真实登记的流程。历次图形、覆盖率、导出与原生操作的验收证据通过[归档索引](../../../archive/index.md)查阅。

## 外部配置冲突恢复（#118）

配置下拉允许再次选择当前项，表示显式重新加载。窗口将原条目交给配置库 `ReloadSelection`，使用返回的最新目录、草稿和错误更新界面。覆盖或启动遇到外部变更时仍拒绝并保留原输入；脏草稿重选时复用确认弹层，明确显示「放弃未保存修改」和「确认重新加载」，取消或Esc恢复原下拉选择及草稿，确认后才读取最新文件。

合法修改保持文件身份，刷新名称、修订和字段值；文件删除或非法时清空当前选择、隐藏旧表单并禁用继续/运行，显示真实错误，不自动改选另一文件。清空选择后仍可从最新下拉选择合法配置。重新加载更新输入版本时清空旧界面结果，历史报告保留；只切换步骤不重载。运行期间禁止重选，已启动流程继续使用原参数和原字节SHA-256。

`TestDeveloperToolsWindow`通过真实窗口回归quantity从1到4、冲突、显式重选、运行及报告摘要，并检查旧脏草稿覆盖拒绝、重载确认取消与确认、外部非法/删除后的目录和禁用状态。库级测试通过同一恢复入口验证身份、原草稿隔离与失效结果。验证通过状态由本批次统一验收记录维护。
