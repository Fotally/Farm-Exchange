# UI 整体与字体倍率接口

对应 `scripts/ui/UiScaling.cs`，履行 [正式 UI/UX 设计](../../../project/ui-visual-prototype.md)。倍率只属于界面，不修改经营、镜头倍率或存档。

## 两个公开操作

| 操作 | 约定 |
| --- | --- |
| `SetOverallScale(Control ui, float multiplier)` | 绝对设置该控件子树的整体倍率，默认 1；改变明确的尺寸、边距、木框、图标及文字。 |
| `SetFontScale(Control ui, float multiplier)` | 绝对设置该控件子树的字体倍率，默认 1；相对于整体倍率改变字号，容器按真实文本重新排版。 |

倍率必须为有限正数，非法值抛出 `ArgumentOutOfRangeException`，不改变原配置。重复设置同一值不继续放大；设置回 1 恢复原始基准。两个值独立：整体 1.25、字体 1.2 时，几何按 1.25，文字按 1.5。

父级与子级设置相乘。例如主界面整体 1.25，市场窗口局部整体 0.8，则市场窗口有效整体为 1；市场局部字体 1.2 时有效文字为原字号的 1.2 倍。未设置的动态新控件沿用祖先设置，不需要窗口每次刷新后重新调用。

## 使用示例

```csharp
Control root = GetNode<Control>("CanvasLayer/UiRoot");
Control market = (Control)root.FindChild("MarketWindow", true, false);
UiScaling.SetOverallScale(root, 1.25f);
UiScaling.SetOverallScale(market, 0.8f);
UiScaling.SetFontScale(market, 1.2f);

// 恢复该窗口的局部配置；父级整体 1.25 仍然有效。
UiScaling.SetOverallScale(market, 1f);
UiScaling.SetFontScale(market, 1f);
```

主场景在 UI 构造后登记整棵控件树；独立 `DraggableWindow` 在挂树时登记自己。对其他控件可直接调用这两个操作完成首次登记。节点退出时恢复原始最小尺寸及自由布局偏移；仅移除倍率模块注入的主题覆盖，原有局部字号、常数、样式、图标覆盖和自身主题恢复原值，然后释放登记与事件订阅。`DraggableWindow` 的拖动位置不由此模块改写。

同一个节点或子树移除后再挂入，重新以恢复后的原始排版登记，不把上一次放大的结果当作新基准。局部倍率重置为 1，未设置自身主题的节点再次继承新父节点的实际主题与倍率，跨父移动不带入旧父的字号或尺寸；可重新调用两个公开操作设置新的局部倍率。原倍率不保存在存档，退出的控件不继续留在模块登记表。

## 真实排版与支持范围

实现集中保存每个控件原始 `CustomMinimumSize`、自由布局偏移、主题字号、几何常数与方框样式；只在倍率修改和新增控件事件时更新，随后调用 Godot 的最小尺寸更新及重绘。容器内控件由 Container 正常布局，不直接改 `Control.Scale`，不会在容器重新排版时被重置，也不会以放大的贴图伪造字号。字数和字体增大可能让容器扩大、目录减少列数或正文滚动。

登记时先复制并接入控件自身或最近祖先的有效主题；没有显式主题时使用项目共享主题，再捕获样式与字号。新控件尚未进入场景树也能取得正确基准，不将引擎默认灰色进度样式固定为覆盖项。独立主题与控件既有局部样式、字号覆盖仍保留，不改共享资源。

提示与弹出菜单各自保存有效主题中的原字号，分别按同一有效倍率换算；自定义主题可以为 `TooltipLabel` 和 `PopupMenu` 指定不同字号，不被共享默认字号覆盖。`OptionButton.GetPopup()` 若有独立主题，单独复制该主题并读取它的原菜单字号，保留其字色与样式；没有独立主题时从控件未缩放主题复制。菜单与控件的提示主题互相独立，退出时恢复原菜单主题。

下拉菜单整体倍率同时作用于原始 `StyleBoxFlat` 木框、内容边距与阴影、菜单几何常数，以及原生勾选和子菜单箭头等主题图标；字号（包含带文字分隔项）再乘独立字体倍率。只改变字体倍率时，菜单框边距、分隔间距与图标尺寸保持整体倍率的结果。布尔常数 `gutter_compact` 保留原值，原主题资源不被修改。

动态新增或重新挂入控件从已登记祖先的未缩放主题取得原始基准，再乘有效倍率；不把祖先已经放大的提示字号再次当作原始字号，避免动态控件累积放大。

自由布局的锚点继续决定靠边或居中；整体倍率只改变相应像素偏移。覆盖当前 UI 使用的标签、按钮、输入、勾选、列表、进度、滚动条、边距和图标宽度。原生 TooltipLabel 与 OptionButton 弹出菜单使用所属控件的有效字号。自绘年度图通过内部 `FontSize`、`OverallScale` 查询同一倍率，拖放预览从来源控件的实际几何与字号构造。

原生主题位图图标按原始尺寸重采样；滚动条用于表达“没有增减按钮”的零尺寸 `ImageTexture` 保持空纹理，不读取不存在的位图或将它放大为 1 像素。项目 SVG 按图标控件尺寸或按钮 `icon_max_width` 布局。

整体与字体设置不改变“填满父容器”或“跟随视窗边缘”的锚点语义；这类控件仍占用可用空间。窗口首选尺寸、可用区域和首次定位由 `DraggableWindow` 结合整体倍率更新；玩家已经拖动的窗口继续保留位置并限制在可用区域。大字号通过容器与滚动保持内容可达，不强制保证所有原本同屏的控件仍同时可见。

## 分辨率与验收

正式默认窗口为 1920×1080，项目关闭画布随窗口自动拉伸。1920×1080、2560×1440 与 3840×2160 下，倍率均为 1 时面板与字号保留同样物理像素尺寸，锚点仅重新定位，地图显示更多范围。未来视觉设计与验收至少从 1080P 开始；旧 1280×720 截图保留为历史。

`TestUiScaling` 验证两种倍率分别改变原始几何及文字、重复设置、恢复、父子组合、单窗口隔离、动态控件继承、自绘年度图、原生输入和不同分辨率固定像素尺寸。生命周期回归使用真实节点移除与重新挂入，检查离树后的基准恢复、同父重新登记、跨父继承新倍率、局部倍率设置后恢复，以及自身自定义主题、局部字号、样式和常数覆盖保留；提示与弹出菜单分别按各自原字号换算，不累积旧父或祖先主题的倍率。下拉菜单检查独立主题的字体、颜色、样式与退出恢复，实际菜单木框边宽、内容边距、分隔间距和主题图标随整体倍率变化、独立字体倍率不改变几何。运行方式见[自动化测试与性能测量](../../../project/testing.md)。
