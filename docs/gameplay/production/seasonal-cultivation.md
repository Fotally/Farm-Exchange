# 季节耕作表

耕作表开局即可使用，多块农田可以引用同一份具名年度安排，各田仍独立播种、供水和收获。年度共 336 天，春夏秋冬每季 84 天；表每年重复，冬春跨年连续处理。

每个条表示一次种植，长度为[作物表](crop-growth.md)的完整获水生长周期。条的位置是计划日期，工人仍需实际到田播种、浇水；不会按条的位置直接发放收成。空白为休耕，不同作物之间至少留一天空白，用于吸收工人播种、浇水产生的时间差。同种相邻条可以连续，n 轮就是 n 个完整周期、n 个独立条，不合并成一条。跨季片段仍属于同一个条、同一轮。

| 表级执行方式 | 行为 |
| --- | --- |
| 立即改种 | 下一不同作物条起点到达时切换，可丢弃当前未收获的一轮；空白及同种相邻起点保留当前轮，停止新播种。 |
| 预备下一轮 | 保留当前轮，按其预计结束日期对应的表位置预备目标；实际结束后接续有效条或按表休耕。 |

初次应用和修改共享表的操作本身保留农田当前轮；随后由表的执行方式处理日期事件。改表影响全部引用田，批量应用不会要求各田同时完成工作。当前轮待水时尚不能确定完成日期，必须等待实际供水，不猜测工人或未来降雨。

共享年度表可以整表删除，包括没有作物条或已有多田引用的表。删除解除该表全部引用、预备目标及后续日期安排，保留各田当前作物、待水或生长阶段、精确剩余时长与水分，恢复按各田当前作物自动复种。空田等待工人开始当前品种；已有作物继续本轮，收获后按当前品种开始下一轮，仍遵守原有季节限制。其它表及独立手动预备不受影响，删除不收费、不修改金币库存、不推进经营日期。表编号不复用；未知或已删除表正常拒绝且零修改。删除入口和草稿处理见[操作说明](seasonal-cultivation-ui.md)。

每条每年只执行一轮，不在条内自动复种；已经完全过去的条跳过，不补种旧条。移动已有条仍是原条，本年已经执行过就不会再次播种；删除后重新新增是独立新条，按本年尚有效日期安排，不会继承被删除条的已执行状态。保存空表再重新打开新增也遵守此规则。条尾进入空白时不会清除已播种或生长中的一轮，仍允许供水、成熟；空白不启动新一轮。同种连续条也要等旧轮实际结束后才独立启用下一条，不能在同种起点重置未完成进度。一天空白是排程间隔，实际收获后不额外等待一天。预计结束落在空白时按表等待后续条起点；实际结束时重新核对表位置，旧缓存仍有效也不能遗漏更早的有效条。打开窗口、查询和编辑草稿不推进经营；暂停保持实际生产和计划执行。

新表草稿可以先拖入、移动和移除作物条，再填写名称。编辑仍检查季节、重叠和间距；保存共享表时必须填写有效名称，未命名保存失败会保留草稿，不创建或修改正式表。

手动指令优先，并只接管本田：

- **立即改种**：解除共享表关联并清空其预备目标，立即丢弃当前未收获一轮、保留水分、设置手动作物；同种立即改种也执行丢弃。
- **预备下一轮**：解除共享表关联，保留当前轮并设置手动下一轮作物。当前轮结束后接续目标，没有额外一天等待；目标执行后沿用手动自动复种。

两种手动指令仍需工人实际播种和供水，不删除共享表、不改变其他田。操作前由界面说明解除安排及可能的当前轮损失。

手动和计划均按当前季节适宜性决定能否播种。预计来不及成熟仅提示风险，不阻止适季播种；禁生季节仍禁止播种。编辑年度表时，只禁止作物条从不适宜季节开始，例如玉米不能从冬季起点落位；适季开始但完整周期跨入禁生季节仍允许并提示风险，例如夏末玉米。新增和移动都在落位前检查完整候选排程，失败说明具体原因并保留原条及草稿；保存时再次核对，不自动换作物或重排。相邻适季跨季保留生长，例如甘蔗夏秋继续本轮；进入禁生季节时按[作物与选种](crop-growth.md)处理本轮结局。当前轮的预计结束日期纳入具体边界是否进入禁生季，空白缓冲仍遵守该规则；失败清理不会发放收成。拖动编辑与批量控件说明见[操作说明](seasonal-cultivation-ui.md)。
