## 空间规格与项目适配

| 类型 | 画布 / 图集 | 锚点与含义 |
| --- | --- | --- |
| 基础地形单元 | 64×32 | 与现项目基础格一致，固定 2:1 等距 |
| 加工建筑 | 256×240 | 地面 pivot=(128,176)，逻辑 3×3，占地投影 192×96 |
| 农田各层 | 224×192 | pivot=(112,128)，逻辑 3×3，占地投影 192×96 |
| 装饰 | 逐项读取 canvas | 逐项读取 pivot，不能根据不透明包围盒猜位置 |
| NPC 单帧 | 64×64 | 脚根=(32,60)，不能直接使用画布中心作为地面位置 |
| NPC 合成图集 | 六帧动作 384×256；八帧动作 512×256 | 四行依次 down、left、up、right；每行一个朝向 |

图像左上位置等于实际世界对齐点减去图像 pivot。建筑的 256×240 包含高度和透明余量，不能把它缩放成 192×96 来“适配占地”。工作中心与占地锚点也不是同一个概念，应使用现项目已有几何定义。

世界静态 `q0/q1/q2/q3` 分别是地面坐标 `(x,y)`、`(-y,x)`、`(-x,-y)`、`(y,-x)`，不是人物的 down/left/up/right。切静态方向应选择已提供图片，不能把整张 PNG 在屏幕上转 90°。多数作物是保持直立的 billboard，旋转的是根点布局与深度顺序；部分方向像素相同是合法对称。

作物 PNG 没有土壤。默认干湿土先绘制，播种或作物外观层随后显示；动效参考的单株根点资源是另一种拆分方式，不能把两种方式重叠画出双份作物。

## 地形图集怎样切

默认 `terrain_81.png` 与 `terrain_81_mesh.png` 均为 **612×972**。子清单规定每格 64×32、切片步长 68×36、padding=2、九列。

四角顺序为 top、right、bottom、left；编码 0=水、1=土、2=草。组合号：

```text
code = top + right*3 + bottom*9 + left*27
index = code + variant*81               # variant = 0..2
region = ((index%9)*68+2, (index//9)*36+2, 64, 32)
```

该切片公式与静态预览 `preview.gd` 的实际图集绘制代码一致。padding 不属于显示面积，也不是基础格宽度。

二元兼容 `terrain_atlas.png` 为 1088×144，使用四角 bit mask 和四变体；不能套用上述三元公式。示例布局只说明地形展示方式，不是当前 384×384 游戏地图数据。画出水不自动使该格禁建或不可通行。

## NPC 怎样使用

每名角色有九张合成动作图、一个 `.tres` SpriteFrames、`animations.json` 和可选分层资料。稳定角色 ID 与项目现有来源编号一致，缺号不是资源缺失。

| 动作 | 每方向帧数 | 当前用途边界 |
| --- | --- | --- |
| idle | 8 | 停驻表现候选 |
| walk、run | 各 6 | 实际位移的表现候选；不提供根运动 |
| sow、water | 各 8 | 已有经营动作的表现候选，但需区分待执行与实际成功 |
| carry_idle、carry_walk | 8、6 | 预留；现项目没有因本包新增搬运任务 |
| harvest、process | 各 8 | 预留；现项目自动收获入库/加工不能据此改成人工作业 |

包内 SpriteFrames 有 36 个动画，如 `sow_down`、`process_right`。旧示例 `work` 名称已统一成 `process`，没有额外旧名别名。

`animations.json` 的 `durations` 是逐帧秒数，优先于提示性 `fps`。已检查的随包 SpriteFrames 用 animation speed=1、帧 duration 为对应秒数；正式迁移应保持该关系，不能再次乘以平均 fps。NPC 的右向已烘焙为左向镜像，不应再 `flip_h`。

合成 PNG 与身体/道具分层是两种呈现方式。直接用合成图时，不再叠共享工具或同一 FX；选择分层时按该角色自己的可见遮罩和顺序处理，不能无条件把完整水壶、箱子放在躯干前。

播种释放种粒、浇水启停、收割/加工接触帧仅是美术时点，不是成功结算凭据。随包所有动作的预览循环设置也不表示正式工人应持续撒种或浇水。

## 与当前项目的具体关系

已读取的正式角色场景 `scenes/npc_character.tscn` 与 `WorkerPresentation.cs` 引用 `assets/gameplay/npc/`，UI 读取 `assets/ui/` SVG；本包没有要求替换 UI。

基础格、建筑占地和 NPC 帧画布能与项目对齐。新增静态素材可以作为世界表现候选，当前数值、占用、坐标与调度仍属于现有模块。新增动作内容超过当前主场景的行走呈现能力，资源就绪不表示真实执行事件、任务取消、倍速和暂停的表现绑定已经完成。

**新动作图集不能直接替换当前角色图集。** 当前 `NpcCharacter.cs` 固定每方向六帧，在 `_Ready` 中从旧大图的第 8、9、10 行（零基行号 7、8、9）生成三个移动动画，统一设为 8 FPS，并自行覆盖节点的 SpriteFrames。新包则按动作拆成四行图集，同时有六帧、八帧动作及逐帧时长。只替换 `CharacterSheet` 仍会按旧行号切片，也不会自动读取新包 `.tres`；可能切到图集范围外、遗漏动作或使用错误时长。未来接入须明确处理资源加载、切片、脚根与动作选择，此处只记录差别，不修改代码。

当前正式导出使用 `all_resources`，不能把“没有被主场景引用”当成安全存放示例工程的依据；后续正式归档应明确隔离来源资料，并检查实际导出内容。

## 来源和重建边界

NPC 的原图、衍生动作以包内记录为准：FrameRonin 来源、具体公开及商用许可未核实、总包为私人评估。现有角色获准加入项目的历史记录不能推导为本次派生动作和整个 ZIP 也获准公开再分发。

场景素材记录包括本项目 imagegen 画稿、程序化绘制、调色与规范化输入。字体为 Noto Sans CJK SC 子集，各字体目录有自己的许可证；这些预览子集不一定覆盖正式游戏全部中文，不应直接替换项目字体。

`tools/validate_bundle.py` 是完整性检查入口；`verify_godot.py` 在临时副本中做各独立工程干净导入；`verify_terrain_rebuild.py` 与 `verify_asset_rebuilds.py` 做可复现素材重建。以后运行前读取随包重建说明：部分旧脚本只覆盖早期农田子集，会改写清单，不能当成全量重建入口。

Pillow、NumPy、SciPy、fontTools 等是制作/验证依赖，不是直接播放 PNG、SpriteFrames 的游戏运行依赖。高分辨率生成过程候选没有完整提供，prompt 不能保证重新生成同一 AI 画稿；提供最终输入后的确定性后处理才有逐字节重建证据。

72 秒视频另行交付、不在 ZIP；部分静态截图与 NPC 联系图按省略清单移除。不要为了补齐它们，误认运行素材缺失或从参考工程覆盖默认资源。

本包内容已足以确定目录归属、读取入口、几何与动画约定。默认配色与清亮参考如何选择、哪些资源先采用、动作绑定与遮挡如何处理，仍属于后续确认范围，本次未作决定。
