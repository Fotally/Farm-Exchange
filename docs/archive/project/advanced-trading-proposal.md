# 多因素委托与自动交易：已确认实施方案

关联 [#36](https://github.com/Fotally/Farm-Exchange/issues/36)，主计划为[后续功能计划](../../project/deferred-features-plan.md)。确认日期：2026-10-02。

本次实现委托功能，不调整报价公式、公告可预测性、商品保质期或纯交易盈利平衡。深入季节供给与价格设计另见 [#80](https://github.com/Fotally/Farm-Exchange/issues/80)，本项只读取现有日历作为条件，不追加增益。

## 玩家配置

- 每单固定选择一种商品与买卖方向；不跨商品自动挑选。
- 条件组内全部满足，组间满足任意一组；支持价格、公共库存数值比较及可选当前季节。库存积压但价格不满意时，玩家可以继续等待。
- 多组同时成立仍只代表该单满足，不重复成交。
- 固定数量、买入补到目标库存、卖出减到目标库存分别配置；触发阈值不替玩家决定成交数量。

## 一次挂单与持续策略

| 类型 | 数量与资源 | 生命周期 |
| --- | --- | --- |
| 一次限价数量买单 | 最高买价乘数量，加该总额的 1% 向上取分费用，冻结所得金币；真实报价不得超过限价 | 完整成交后结束，释放未使用差额；撤销释放冻结额 |
| 一次固定预算买单 | 冻结玩家指定总预算（含费用），实际执行时按当前价算可完整买入的最大整数数量 | 完整成交后结束并释放未使用余额；预算定义的完整数量不等于固定数量单部分成交 |
| 一次卖单 | 冻结确定的商品数量，手续费从实际收入扣除 | 完整成交后结束；撤销释放冻结库存 |
| 持续策略 | 不冻结资源，每经营秒检查；固定数量或按当时总库存动态计算目标差额 | 保留到玩家停用或撤销 |

一次目标库存单在建单时将目标差额锁定为固定数量；之后库存变化，或只编辑价格、条件和现金保留设置，都不重算锁量。玩家主动改变商品、买卖方向或数量设置等交易数量意图时，才按新设置完整重验。持续目标每次检查动态计算。一次固定预算买单按预算决定数量，不同时指定固定数量或库存目标。

所有订单均完整检查后结算，资金、库存、容量或保留线不足时等待，不部分成交；数量为零时不成交、不收费。一次单提交时必须能冻结相应资源，提交失败不创建订单、不改变资源。

## 现金保留

每张买单提供两种选择：固定保留金额，或保留原设单现金的百分比。百分比在设单时计算一次并锁定为金额，整数分向上取整；不把库存市值计入，不动态重算。

例如设单时现金 5,000 金币，保留 20%，锁定保留线就是 1,000 金币。编辑价格、数量或条件不刷新原现金基准；修改保留参数仍按原基准计算，重新建单才取得新基准。建单冻结及实际买入均检查保留线，支出包含手续费；不能使用其他订单冻结资金。

## 费用与完整结算

委托买入、卖出各按实际成交总额收 1%，向上取整到分。仅成功成交扣费，未成交和撤销不收费。买入支出为成交额加费用，卖出入账为成交额减费用。现行即时交易仍同价零费。

实际成交使用当时正式报价，不按委托限价替换实际价。金额、数量聚合使用宽整数预检，库存与钱包维持现有整数容量；失败金币、库存与冻结额度零修改。

## 相位与暂停

每个未暂停经营秒先沿用生产入库、加工领取、工人、日历和行情更新顺序，再按建单顺序各检查一次委托。后单读取前单成交后的资源，不反复循环到所有策略不满足。创建或编辑本身不立即执行交易。

暂停时可创建、编辑、停用和撤销，自动检查停止；恢复从下一经营秒继续。关闭后不补算现实时间，本次不新增存档或离线收益。

## 冻结与其他操作

钱包、库存继续唯一持有实际总量和冻结额度；订单模块只维护各单配置、资源归属、原现金基准和执行结果，不新增第二份余额或持仓。

- 总余额与公共库存查询包含冻结部分；可用查询扣除一次挂单冻结。
- 主动交易、建造与加工不能消耗冻结资源，全部出售仅处理可用部分。
- 加工仍遵守原料保留底线与原领取相位，自动出售保留量不代替加工底线。
- 同一单编辑时完整重验并替换，失败保留旧单和旧冻结；不得用取消重建刷新现金基准。

## 模块与交付分工

按 codebase-design 的 Module、Interface 与 Implementation 词汇，订单 Module 唯一持有配置、身份、生命周期与执行状态，条件求值和预算数量算法留在 Implementation。`TradingService` 封装全部资源预检和一次结算，`Wallet` 与 `Inventory` 封装冻结与释放；`FarmGame` 组织经营相位并提供统一命令和只读快照。UI 发出玩家意图，不计算费用或拼装资源修改。

- `orders_core`：交易、冻结、订单执行、经营接入、核心单元测试及对应中文文档。
- `orders_ui`：条件编辑与订单管理、市场和主场景接入、端到端测试及界面文档。
- 主 Agent：计划、公共索引与根系统结构、FarmGame 人工文档、独立审查与全局验收、提交与 PR。

## 验收标准

- 实际表达多条件与季节选择，积压但价格不满意时不卖；同单不重复成交。
- 两种一次买单预算、卖单冻结、目标数量锁定与持续动态差额正确；撤销释放、失败编辑零修改。
- 原现金基准跨编辑不变，费用和保留线完整预检；其他订单的冻结资源不可借用。
- 即时交易、全部出售、建造和加工使用可用资源；原生产与行情规则保持。
- 界面显示真实状态、冻结、现金保留线与最近成交费用，每秒刷新保留草稿、焦点与光标。
- 完成代码与中文文档后独立审查；指定引擎编译、完整场景测试、逐模块至少 80% 行覆盖率、Windows Release 导出和实际导出程序启动。功能与验证均在 dev；只提交本 issue，创建 dev → main PR 等待人工合并。
