## 目标与范围

- 功能完成后开局即可使用，无规模或教学解锁门槛。
- 玩家创建具名年度耕作表，多块农田引用同一份表，各田保留独立的实际生产进度。
- 耕作表按日期安排种植，每年重复；本次不加入多年不同计划。
- 玩家手动操作拥有最高优先级，分别保留“立即改种”和“预备下一轮”。
- 本次包含可视化拖动编辑、共享与应用、预备安排、统一播种规则调整及换季成熟补救。
- 自动交易、人力扩充、天气生成、存档与离线收益不纳入本项。

## 时间图与作物条

现有日历每季 84 天、每年 336 天。春、夏、秋、冬四行是同一条年度时间轴的折行展示，换季不重置正在生长的适季作物。

| 图中内容 | 含义 |
| --- | --- |
| 一个作物条 | 一轮作物，长度固定为该作物获水后的完整生长周期 |
| 时间条的位置 | 玩家安排的日期位置，不代表工人一定能在该时刻完成播种 |
| 空白 | 休耕；无需新增休耕条或独立休耕配置 |
| 不同作物条之间的空白 | 至少一个游戏日，用于吸收播种、浇水等产生的时间差 |
| 同种作物的相邻条 | 可连续安排，无额外一天间隔要求 |
| 跨季拆分的多段 | 同一个作物条的显示片段，不增加轮次，不重置生长 |

时间预算使用完整生长周期，不把工人等待计入作物条长度；界面需区分计划日期与实际生产进度。一天间隔是耕作表的排程约束，不在实际收获后再追加固定一天等待，也不作用于手动指令。

年度首尾连续处理。冬春跨季条仍是一轮作物，每年重现的时间条不能导致同一农田重叠执行两轮。

### 拖动编辑

- 从作物选择区拖入时间轴，已有条也可拖动调整位置或移除。
- 拖动预览保持一根完整直条；只有放下后才按季节边界拆成多个显示片段。
- 后续拖动任何片段都操作原来的整条，不独立移动片段。
- 展示预计起止日期、跨季关系及越过禁生边界的警告。
- 重叠、不同作物间距不足等排程冲突需清楚显示；不自动选择其他作物或替玩家重新排表。
- 配合拿起、拖动和落位动画，帮助玩家看清操作反馈。动画不推进经营；具体动效时长属于实现细节。

## 一张表统一选择执行方式

执行方式设在整张表上，引用该表的农田共用；不增加逐条模式配置。

| 执行方式 | 对当前作物的处理 | 后续安排 |
| --- | --- | --- |
| 立即改种 | 到表内切换时点，可以丢弃当前未收获作物 | 按表内日期执行新安排，空白期间休耕 |
| 预备下一轮 | 保留正在种植的一轮，继续遵守适季与越季规则 | 按当前作物预计完成时间所在的表位置预备后续安排 |

两种方式都按日期定位，已经完全过去的条直接跳过，不积压为待补种轮次。每个条代表一次种植，不能在同一条内反复复种。

“立即改种”模式中，计划内不同作物切换前的休耕段承担时间缓冲，停止新播种并允许当前轮继续成熟；到下一条不同作物的开始日期才按模式切换。同种下一条也须等上一轮结束后独立播种。手动立即改种不受这段等待限制。

## 共享、应用与修改

- 共享表唯一保存名称、执行方式与年度时间条；每块田只保存引用和自身执行状态，不复制一份可独立编辑的同名表。
- 多块田能够统一应用同一份表；共享配置不要求各田同时完成播种、浇水或收获。
- 初次应用或修改表时，操作本身保留田中正在种植的一轮，并按其预计完成时间重算预备安排。之后由该表的执行方式决定后续切换。
- 修改共享表影响其所有引用农田；界面应能看清引用关系与影响范围。
- 不通过查询、打开窗口或编辑草稿推进经营。

批量应用是必需能力；具体选择控件在实施时围绕现有界面设计，本文不把地图框选作为已批准范围。

## 预备安排与查询时点

预备安排是当前轮结束后的目标，包含作物或休耕等待，不建立历史作物积压队列。

1. 当前作物完成时间确定后，查询该时刻对应的耕作表位置，并缓存预备安排。
2. 对应位置是尚未过去的作物条时，记录目标条及作物；对应空白时，按表休耕并记录后续启动时点。
3. 日期正常推进不每日重新查询。修改表、玩家覆盖目标、当前作物被中断或完成时间发生变化时，更新相关安排。
4. 到执行时点仍需重验目标有效性、当前适季条件及工人任务凭据。查询缓存不替代执行重验。
5. 已经过期的条跳过，不补执行旧安排，不为错过条增加复杂追回逻辑。

生长中的作物按实际推进步长预测正常完成时刻，并取正常完成与首次禁生边界中较早的本轮结束时刻；禁生边界可能促成成熟，也可能清除本轮。进入相邻适宜季节不缩短周期。已播种但尚未获水的作物，要等实际开始生长后才能确定结束时间。不得虚构工人到达或未来降雨时刻作为确定日期。

“立即改种”模式还需记录表内下一次切换或休耕事件；休耕关闭新播种，不同作物起点可以按计划中断当前轮。不通过每日重新扫描全表来判断。

## 手动指令

| 指令 | 当前作物 | 本田耕作表与预备安排 | 生效 |
| --- | --- | --- | --- |
| 立即改种 | 丢弃当前未收获作物，保留田块水分 | 解除本田共享表关联，清除计划预备安排，设置手动作物 | 指令即时处理，无额外休耕等待 |
| 预备下一轮 | 保留当前作物 | 解除本田共享表关联，使用手动指定的下一轮目标 | 目标即时更新，本轮结束后接续，无额外一天等待 |

手动接管只影响本田，不删除共享表、不改变其他引用田。操作前告知玩家会清空本田的耕作安排；立即改种还需明确当前作物损失。

手动预备目标开始执行后，沿用现有手动选种的自动复种方式。手动指令的即时生效不替代工人的实际播种、浇水，也不改变它们的现有耗时。

## 统一播种与越季规则

### 对现有规则的变更

手动和耕作表共用同一套播种判断：当前季节适宜即可播种；预计来不及成熟用于提示，不再拒绝播种。仍然禁止在当前禁生季节播种。

预计成熟继续按相邻适宜季节连成的区间判断，包括冬季到下一年春季。耕作表放置时，不适宜季节的起点拒绝；适季开始而越界的部分提示进入禁生季节后存在枯萎清除风险并允许保留。完整生长周期与既有供水规则继续复用。

### 图示边界

- A 的相邻同种条可连续安排；A 到 B 的计划切换需留至少一天空白。
- B 适宜春、夏，春末放置时可以使用春末加夏初的连续时间。放下后跨行显示，实际生长不中断。
- C 仅适宜夏，条延伸到秋时显示警告，允许保留；实际进入秋季尚未成熟时，按下述成熟补救或枯萎规则处理。
- 清除 C 不会追回已经错过的条；后续按有效的日期安排继续。C 到 D 的计划空白是排程缓冲，不额外添加实际等待一天。

### 内部换季成熟补救

本机制记录在内部文档和测试中，游戏界面不展示阈值、专门提示或收益说明。

- 只处理即将进入禁生季节的生长中作物；进入仍适宜的季节不触发。
- 换季时，剩余生长时间严格小于完整生长周期的 10%，立即促成成熟；等于 10% 不触发。
- 比较使用实际剩余生长时间和同一作物的完整生长周期，不以界面取整后的天数或秒数判断。
- 本规则只负责促成成熟，收获与入库沿用各自原有流程，不另行绕过流程发放库存。
- 正常到期的作物仍先完成成熟结算；其余进入禁生季节且未成熟的作物沿用清除本轮作物、水分与进度的规则。
- 待水作物没有即将完成的生长进度，不获得该补救。
- 不把该机制计入编辑器的作物条长度或可用时间预算。

当前没有独立人工采集流程，本项不新增采集劳动。成熟、收获和入库的既有归属见[经营推进顺序](../../architecture/game-state/farm-game/implementation-tick-order.md)；实施时同步相关接口与目标顺序。

## 模块职责

按 codebase-design 的 Module、Interface 与 Implementation 约定，计划 Module 集中拥有共享表、农田引用、预备安排和日期事件；日期定位、跳过旧条与模式执行顺序留在 Implementation。调用方通过简洁 Interface 提交计划操作或读取快照，不在 UI 和工人模块重复拼装这些规则。

- `CropCatalog`：继续唯一持有作物周期与适宜季节。
- `PlantingRules`：统一当前季节合法性与预计成熟风险，风险提示不再等同于禁止播种。
- `FarmingSystem`：继续唯一持有当前作物、水分、剩余生长时间；负责改种、成熟及越季清除。
- 计划 Module：唯一持有计划与各田执行安排，不复制农田生长状态或库存。
- `FarmGame`：协调玩家命令、计划事件、工人、生产结算与日历相位；收获入库沿用经营流程。
- `WorkerScheduler`：继续执行实际播种浇水与任务重验，不拥有共享计划。
- UI：拖动编辑、批量应用、显示计划和实际状态、发出两种手动意图；动画不修改经营状态。

以上职责已按唯一文件所有权实施；未增加通用计划语言、策略引擎或额外抽象层。全局验证由主 Agent 串行组织，结果见[测试记录](testing.md#2026-10-03-42-年度耕作表验收)。

## 验收标准

1. 创建年度表，多田共用并各自推进；每年重复，冬春连续，过去的条不补种，同一条不重复播种。
2. 作物条长度为完整周期；空白休耕、不同作物至少一天间距与同种连续排列符合规则。
3. 拖动预览为直条，落位后跨季拆分，重新拖动整条；动画与暂停不推进经营。
4. 两种表级执行方式分别验证中断与保留；应用、编辑保留当前轮，更新相应预备安排。
5. 预备安排按完成时间定位；休耕正确等待，无每日重查或旧条积压，变化后更新且执行重验。
6. 手动立即改种和预备下一轮语义独立，均接管本田；不影响其他田，不增加人工指令休耕等待。
7. 当前适季且预计时间不足时，手动和计划均可播种并提示风险；当前禁生季节仍不能播种。
8. 禁生边界的剩余时间小于、等于、大于 10% 分别验证；适季跨季不补救，待水不补救，成熟走原收获入库流程且不重复入库。
9. 供水、工人任务失效、暂停、成熟恰在季节边界与公共库存行为无回归。
10. 代码实施后同步中文玩法与架构文档、导航和根系统结构；完成独立审查及指定引擎编译、场景测试、总体与逐模块至少 80% 行覆盖率、满地图测试、适用图形验证、Windows Release 导出与实际 EXE 启动。验证在 `dev` 进行，最终提交 `dev → main` PR，等待人工合并。
