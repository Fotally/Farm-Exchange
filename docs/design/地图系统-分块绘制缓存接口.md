# 地图系统：分块绘制缓存接口

## 目的与范围

本接口让 `WorldMap` 在镜头移动时复用已有地块绘制命令，并在经营状态改变后只更新受影响的地图块。它只决定**怎样呈现**土地、建筑和作物；128×128 格的生产、加工、库存、市场与换日继续由 `FarmGame.AdvanceTick()` 每 tick 对完整世界计算，与镜头位置及地图块可见性无关。

设计覆盖当前平面等距地图、六种作物、农田和加工场地。每块采用固定的 8×8 格，共 16×16 块；块大小是 `WorldMap` 的实现细节，可在保持本接口不变的前提下依据性能报告调整。

## 模块和依赖

| 模块 | 输入 | 输出 | 依赖 |
| --- | --- | --- | --- |
| `FarmGame` | 经营命令、`AdvanceTick()`、格坐标 | `PlotSnapshot`、`TickResult`、库存和价格 | 不依赖地图、镜头或缓存 |
| `Main` | 玩家操作、计时器 | 调用经营命令并通知地图同步；刷新界面 | `FarmGame`、`WorldMap` |
| `WorldMap` | `FarmGame`、相机变换、视窗大小、屏幕点击位置 | 绘制地图；发出所选格坐标；返回坐标和镜头范围结果 | 只通过 `FarmGame.GetPlot()` 读取经营状态 |
| 地图块（`WorldMap` 内部） | 本块的地块视觉状态、可见性 | 缓存的绘制命令 | Godot `CanvasItem` 绘制缓存；不对 `Main` 或 `FarmGame` 提供接口 |

依赖方向固定为 `Main → FarmGame` 和 `Main → WorldMap → FarmGame.GetPlot()`。`FarmGame` 不读取屏幕、地图块、节点或渲染缓存。

## `WorldMap` 对外接口

| 接口 | 输入 | 输出或效果 | 调用时机 |
| --- | --- | --- | --- |
| `SetGame(FarmGame game)` | 已建立的游戏状态 | 建立地图块视觉缓存，安排初次可见块绘制 | 主场景初始化 |
| `SyncFromGame()` | 无；内部读取 16,384 格的当前快照 | 更新视觉状态记录，标记实际外观发生变化的块；已显示的脏块重绘 | 每次经营命令或 tick 完成后 |
| `SelectAtScreenPosition(Vector2 position)` | 屏幕坐标 | 选择有效格，发出 `SelectionChanged(cell)`，更新选中框 | 玩家短按地图 |
| `CellAtWorld(Vector2 position)` | 地图本地坐标 | 格坐标 | 坐标测试和选择 |
| `ClampCameraCenter(Vector2 center)`、`WorldBounds()` | 世界坐标或无 | 限制后的镜头中心、地图边界 | 镜头控制 |

`SyncFromGame()` 不返回经济结果，也不驱动 `AdvanceTick()`。调用者在修改 `FarmGame` 后调用它；函数只读取快照，不能改变土地、库存或计时。无变化时不要求块重绘。`SelectionChanged` 的含义和现有坐标规则保持不变。

## 内部更新流程

1. 初始化时按格坐标建立 256 个地图块的视觉记录。每块持有本块格子的绘制状态，不持有经营状态的副本或计时器。
2. 相机移动和视窗变化只重新判断哪些块与视窗相交。`WorldMap` 在镜头控制之后处理可见性，避免镜头移动当帧露出尚未启用的块。已经绘制过且内容未变的块复用 Godot 缓存的绘制命令；新进入视野的脏块在显示前重绘。
3. `SyncFromGame()` 顺序读取完整 128×128 地图，将 `PlotSnapshot` 映射为视觉状态。只有解锁状态、建筑类型、农田作物种类或作物阶段改变，才标记相应块为脏。`RemainingTicks` 的数值不影响地图图形；它仍由 `Main.Refresh()` 在选中土地信息中按 tick 显示。
4. 可见脏块在下一次绘制时重建本块命令；屏幕外脏块等进入视野时再重建。每块将地块菱形和作物、场地标记合成一份带顶点颜色的 `ArrayMesh`，由一次 `DrawMesh()` 提交。选中框与地图块分开绘制，改选只更新选中框。
5. 地图菱形边缘独立绘制。块内仍按当前等距坐标公式定位地块，不改变点击命中、镜头边界或现有颜色含义。

视觉缓存只是一份可以重新从 `FarmGame.GetPlot()` 构造的呈现数据。即使没有渲染帧，`FarmGame.AdvanceTick()` 也会在每个计时器 tick 完整推进所有地块；屏幕外农田照常成熟，屏幕外场地照常加工。

## 正确性约束

- 同一 `FarmGame` 状态与所选格，在任意镜头位置应得到相同地图内容；进入视野不得出现旧建筑或旧作物阶段。
- `SyncFromGame()` 的执行次数、地图块尺寸、可见块数量和帧率不得改变 `FarmGame` 的 tick、收获、产出、库存、价格或日期。
- 世界状态在 tick 计算完成后同步到表现层；性能优化只能延迟屏幕外的**绘制命令重建**，不能延迟经营计算。
- 选中框可以单独更新；选格不要求重建地块。

## 验收与测量

使用项目指定的 Godot 4.7.2 Mono，在 1280×720 窗口、镜头缩放 1.25、16,384 格实体、六种作物、水平往返移动镜头、每秒一个经营 tick 的场景中测试。关闭 VSync，取消 FPS 上限；预热 2 秒后至少采样 8 秒。验收为平均 FPS ≥60，P95 帧间隔 ≤16.67 ms。记录硬件、构建、帧率、P95/P99、地图块重绘次数与 tick 数；静止和移动镜头都要检查画面。

自动化回归需覆盖满地图连续 50 tick、屏幕外地块的生产结果、选格和镜头操作，并验证经营命令及作物阶段变化后地图同步。代码与本设计若出现偏差，应在同一任务中修正文档及对应地图、测试说明。
