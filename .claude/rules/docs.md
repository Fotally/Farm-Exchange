# 文档维护规则

- 正文使用中文；自定义目录与文件主体使用小写英文和连字符，扩展名的点保留。
- 玩家可观察的玩法规则放在 docs/gameplay/；模块对外约定与内部设计放在 docs/architecture/；项目流程放在 docs/project/；研究证据放在 docs/research/；机械检查说明放在 docs/static-checks/。
- 架构文档以 interface-模块名.md 或 implementation-具体设计点.md 命名。接口文档写调用方需要知道的成员、约束、调用顺序和结果；实现文档明确链接其履行的接口。
- 玩法专题按独立变化的规则拆分；生效数值表在一个专题文档中维护，背景摘要和其他文档链接到它。调研记录依据与历史，不能覆盖生效规则。
- 修改代码时同步受影响的专题文档及 docs/README.md 导航；迁移路径时修复仓库内链接。根 README 保持入口性质。

## 持续整理与归档

- 修改同一主题时优先更新已有文档；现行玩法、接口和操作约定各在对应专题维护，方案与验收记录引用它们。
- 功能合并后检查实施计划、讨论稿和阶段验收：先将仍生效的规则、长期用例及必要约束写入现行专题，把未确认或未完成事项留在现行计划，再归档已完成或被替代材料。
- 归档路径镜像原分类：`docs/<分类>/<路径>`迁至`docs/archive/<分类>/<路径>`；只建用到的目录，archive不再递归归档。拆分历史章节时，历史部分使用对应的镜像文档，现行文件保留操作与规则。
- 归档页首注明归档日期、关联issue、已核实状态与现行替代入口，历史正文按当时语境保留。同步修复仓库内链接、锚点及路径示例；主导航只保留一个归档入口，完整清单维护于`docs/archive/index.md`。
- 历史专用图片及原型按各自原路径一起归档；仍被现行基准使用的附件保留原位。文档只纳入代表性长期证据，重复截图、临时日志与运行报告保存在构建产物目录，不随每轮验收堆入文档库。
