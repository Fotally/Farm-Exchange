# 素材目录与使用规则

- 新增、迁移、替换素材或修改素材导入设置前，读取 `docs/project/asset-organization.md`；接入当前美术包时另读 `docs/research/bright-complete-v2.md`，v1 分析仅作历史。目录按实际用途归类，原始交付与正式运行资源分开。
- 正式资源沿用 `assets/gameplay/`、`assets/ui/`、`assets/development/`；共用字体放 `assets/fonts/`，原始压缩包放 `assets/source/`。只创建实际需要的子目录，禁止把独立示例工程直接放进运行资源目录。
- 项目维护的目录和文件主体使用小写 snake_case；世界静态方向用 `q0`～`q3`，NPC 方向用 `down/left/up/right`，两者不得混用。保留来源角色编号，生长档、方向和变体含义写在素材说明中。
- 原始包只读保存并记录 SHA-256；外层归档名可规范化，包内文件保持原样。解压预览与重建在项目外进行，参考配色和动效不得按同名文件自动覆盖默认资源。
- 新资源在对应目录的 `source_notes.md` 记录来源包及内部版本、原路径到项目路径的映射、授权与适用文件、实际改动和使用状态；授权总览维护于 `docs/project/asset-sources.md`。未接入、已接入与参考资源须明确区分。
- 保留画布、透明边、pivot/脚根、逐帧时长和分层约定。像素 PNG 使用 nearest、关闭 mipmaps；UI SVG 和字体按各自用途设置，不套用世界像素图规则。
- 可复用场景、脚本、着色器和工具按 `scenes/`、`scripts/`、`tools/` 的现有规范归属；`assets/` 保存纹理、字体、Godot 数据资源及确有运行需要的元数据。素材不得拥有经营状态。
- 已引用素材的迁移须同步修复 `.tscn`、`.tres`、脚本及元数据依赖并验证导入与导出；目录规则不授权自动迁移旧文件、变更风格或扩展玩法。完成时，引用、来源说明与实际文件一致。
